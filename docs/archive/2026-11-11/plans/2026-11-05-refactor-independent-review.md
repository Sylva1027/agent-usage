### 5.3 必须保留的实验口径

- 常见密度镜像：六来源、1,968 个用量文件、1,729 个会话、90 天；事实 146,412／1,464,120，原始字节约 4.27／41.83 GB。不同早期报告的捕获版本和字节数略不同，以各报告为准。
- 原生来源在有活动 journal 的 C 盘，SHA 回退来源通常在 E 盘；数据库在 E 盘。只在同卷、同证明方式内作版本因果比较。
- 既有完整索引含原始文件已消失的留存事实。曾有已有库 160,862 条、空库重建仅 146,412 条；**不能清空重导来“简化迁移”。**
- 没有清 OS 文件缓存；大部分结果不是物理冷盘，不是正式 p95。函数嵌套计时不可直接相加。

### 11.1 最需要改变的三项决定

1. **下一张先闭环 SHA 重复同步，不立即实施清单写入批量化。** 现有慢样本已经记录了第二次无新增数据的同步，不必再从广泛归因开始。先确认它为何发生、哪些检查是必要的，再修复可避免的重复工作；不把整次退化直接归罪于 SHA 或硬件。
2. **把“新会话、新目录、其他 harness 更新”提升为日常主场景。** 现在的快路径主要证明了已知 Codex/DSH 文件继续追加。新建文件及其他 harness 变化可导致整份清单重新登记，初始化成本会重复出现。仅让首次登记快 50%，仍未消除日常工作随总文件数增长的问题。
3. **把多冷分片的有界读取放到下一轮完整重建提速之前，并以工作量验证为先。** 两个冷分片、today/week 或修订覆盖就可能退出 SQL 路径，完整事件重新进入 JS 数组。再把空库导入缩短几十秒，不能消除这个容量风险。先证明查询工作集有界，再做更大的年度导入与最终压力验收。

### 11.4 唯一推荐的下一张卡：SHA 重复同步闭环

**目标：**说明并修复“同一次变化已经同步，页面显示新值前又发生全局同步”的可避免部分。保留必要的再次来源检查、真实第二次写入及外部提交处理。本卡不负责将完整 SHA 路径降到一秒。

**读证据与改动边界：**先用上述两个 trace/结果定位先后顺序；只在小夹具中补调用原因、来源输入身份、事实/发布身份的边界记录。优先修改 `src/server.js` 的共享调度/复用决定及相关服务测试；确有必要才改 `usage-summary-cache.js` 或执行器状态传递。不改解析、SHA 算法、原生协议、事实布局、业务计算或堆限制；诊断代码留在实验工具。

**实现原则：**已完成的采集与某个页面响应是否已缓存是不同状态。复用应绑定已经核验的来源、配置/证据和数据库状态，不能靠“上次刚同步过”、固定宽限时间或抑制文件通知推断无变化。核验失败继续原处理；真正第二次写入必须产生正确的后续版本。

| --- | --- | --- |
| 已有证据核对 | 上表 3 个 Codex 样本 | 对齐两次 sync、SSE、请求及绘制；不新跑大历史归因矩阵 |
| 确定时序反例 | 6 组小夹具：重复提示与并发请求、提交后才到的重复提示、核验中第二次写入、提交后第二次写入、外部数据库/辅助输入变化、发布未完成时重开 | 重复提示场景允许必要检查，但无真实变化不重复执行完整同步；真实变化不能被吞掉。外部输入组分别覆盖数据库与配置，报告子断言数 |
| 定位限额 | 最多 2 次隔离小数据页面诊断，必要时才跑 | 若仍不能解释第二次同步，停止并交付精确缺口，不改哈希/放宽守门条件碰运气 |

### 11.5 后续顺序、保留与删除

| 顺序 | 工作包 | 为什么这样排 |
| --- | --- | --- |
| 1 | 上述重复同步小卡 | 使用已知慢样本，先收住可定位的回退；限额明确 |
| 2 | 来源清单按真实变化维护，先覆盖 Codex/DSH 新文件与新目录 | 新会话是正常使用事件；以固定总事件量、不同文件/会话数验证不全局重登记，再逐来源缩小其他 harness 的回退范围 |
| 3 | 多冷分片、热冷混合和范围查询的有界读取 | 先消除可能重新物化全历史的路径；在默认堆内验证容量，再验收切换时间。冷包核验成本仍计入 |
| 4 | 首次清单登记和完整构建成本 | 两类任务分开计时、分卡实施；继续 Q4 已有批量机制，先确认重复核验/提交份额，再决定批量化与完整重建矩阵 |
| 5 | 其他来源覆盖收口、一年/两年容量与持续资源验收 | 优先覆盖新增会话、跨日目录、来源混用、漏通知/回退和冷历史，不用纯密度放大代替使用时长。通过定向场景再做长期样本 |
| 6 | Linux/macOS 与经授权的实际启用 | 当前先不扩平台实施，但通用事实/发布语义保持与 Windows 能力分离 |

**保留：**Node＋SQLite、浏览器、持久业务视图、已有四原型证据、真实输入检查、精确金额与恢复测试。现有证据支持改变工作量和调用组织；尚未支持再次全栈重写。只有在这些通路有界后，仍测得解析 CPU、索引查询、写入/维护是主要且不可通过既有机制消除的成本，才对那个组件做定向替换原型。

**修改：**阶段验收使用“结构性工作量＋同轮时间＋总资源＋正确性”，每卡只验其实际改动。将原定 8 次完整重建矩阵延后到有明确构建收益假设之后；年度大矩阵先改为能覆盖真实使用路径的场景表，再确定样本量。不能让正常新增文件继续按异常路径计入一个不受考核的回退桶。

**删除/暂停：**以无归因的“初始化总耗时减半”直接批准仅批量 `put` 的方案；把当前约 0.8 秒外推到所有 harness/新会话/卷；从小样本中位数证明稳定性；为了过线反复补跑已经没有新假设的矩阵。

**SHA 决策需要单列：**Q7 的额外同步问题和无可靠变更依据时全前缀校验的成本是两件事。前者应先闭环；后者不能因卡片通过而消失。保留当前可靠性要求时，通用一秒目标在现有无 journal 的大文件场景下未获支持，应作为产品目标与环境能力的不匹配提交用户判断，不静默改口径。SHA 未通过不阻止独立的冷历史容量工作，但阻止无条件宣布“全环境一秒刷新已完成”。

本次只追加审阅意见。做了两个调用现有方法的内存级分支核查，确认“受管目录新增文件会回退”和“两授权冷分片拒绝 SQL 快路径”；没有打开真实数据库。首版分支核查的模拟归档 ID 不符合格式，被校验拒绝，修正模拟 ID 后两项通过，该失误不作为产品故障。没有重跑完整测试、真实页面或性能矩阵，也没有更改源码、提交或部署。**第二次 SHA 同步的确切触发原因、全局重登记的实际日常耗时、多冷分片的大规模峰值仍待各自实施卡验证。**
