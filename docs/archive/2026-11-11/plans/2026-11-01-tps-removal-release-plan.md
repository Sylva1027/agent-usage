## 先交付独立研究盒子

建议保存到项目外的 `E:\12 AI\ccusage\tps-research-box\2026-11-01\`，同时提供可读目录、完整 ZIP、文件清单和 SHA-256。它独立于新的运行代码与发行包，不是回收站，也不只是一个指向旧 Git 提交的链接。

交付分成两个互不依赖的产物：研究盒子保存 TPS 的实现与经验，无 TPS 运行包服务现有用户。以后复用 TPS 从盒子取出所需部分，不要求把旧功能重新装回主项目。盒子入口记录封存日期、基准 commit、相关 tracked/untracked 工作树差异和原路径对应关系；源码快照保留封存时的实际内容，不以 HEAD 代替未提交实现。

保存内容：

- **当前实现与上下文。** 收齐专用 TPS 模块、前端、采集器、插件、工具、producer 补丁，以及本轮未提交的修复。共享的 core/store/server/executor/history 等文件保留当时完整源码快照和依赖定位，供后续理解原有接线；不声称这些耦合代码已经变成可直接安装的独立插件。
- **测试与实例。** 保存参考分词、首批扣除、SSE/WS/HTTP 批次、重试/并发、推理与工具分段、reader、持久化及历史兼容的相关测试和合成 fixture。优先保存无需真实模型请求的复现入口及预期结果。
- **研究文献与证据。** 保存方案、来源核验、计数/时钟语义、版本演进、验收摘要及可公开的标量证据。已知错误或被撤回的算法和高估反例一并保留并标清原因，避免后续再次采用；最终有效 v8 与获准的日志估计分别说明。
- **依赖与复用说明。** 保存 package/lock 文件、上游精确版本和 commit、必要上游源码、补丁与文件 hash、运行要求、关键命令、各 harness 支持范围及未解决问题。核心离线实例需要的依赖包连同许可证保存，不能只留下将来需要重新下载的锁文件。已有大体积二进制/构建产物建立位置与 hash 索引；源码、补丁与必要合成 fixture 不以易失的开发目录路径代替。完整定制引擎重编译所需的外部工具链与未封存依赖单独列出，不与核心离线实例的可复现性混为一谈。

不把账号凭据、auth/config 私密状态、代理环境、生产数据库、原始用户会话、TRACE 请求正文、无关实验目录或庞大构建缓存装入研究盒子。需要原流量才能理解的结论保存脱敏标量及合成反例；复现限制写清楚，不宣称原始实测可在缺少输入时原样重放。

盒子应附一份简短入口说明：从哪些文件理解 TPS、哪些结论可信、哪些实现已废弃、怎样跑核心离线实例、将来接入新技术栈时需要提供哪些输入。每个 harness 分开记录历史日志能提供什么、是否需要额外采集、是否经过实际验收；DSH 热启停等未解决问题明确保留，不能把所有来源写成“完整支持”。

先在临时目录解包核对文件清单和 hash，再从解包目录运行选定的核心离线实例，覆盖计数/窗口、reader 和历史持久化；不得借用原工作区的源码、fixture、node_modules 或私人日志。通过后才允许删除活动项目中的实现。研究盒子本身不上传或作为新 release 附件发布，除非另行授权。

## 目标与影响

发行包、前端、后台和公开数据接口均移除当前 TPS 功能：不再显示模型速度，不再扫描速度日志、生成测量、计算均值/分位数、维护速度索引或配置客户端采集。没有隐藏入口、恢复开关、空白占位区或“已停用 TPS”说明框。

用量、费用、模型/仓库对比、时间线、限额、5h/7d RANGE、来源发现/导入、刷新、冻结、备份和历史读取继续保留。它们的业务数据不需要 TPS；当前实现中的共享调用需要先拆开。因此可以独立摘除 TPS，但不能直接删除所有 `perf` 文件或回退到旧提交。

已确认的交叉点：

- [usage-core.js](../../../../src/usage-core.js) 在用量事件读取结束后追加性能扫描；`sourceGroupForQuota()` 又借用 TPS 的来源分类。移除追加扫描，同时让限额继续复用现有来源分组规则，保留 Codex 的 main/extra/jetbrains 别名。
- [usage-store.js](../../../../src/usage-store.js) 把性能抽取、Codex 性能投影、速度发布和普通事件索引放在同一同步流程。保留原生用量读取、事件事务、usage rollup、用量投影缓存与限额观察，摘除 TPS 的线程规划/采样/发布分支。
- [usage-executor.js](../../../../src/usage-executor.js) 和 [server.js](../../../../src/server.js) 交换性能发布状态，正常状态指纹也包含 TPS 修订。改用现有用量、来源和定价状态；保留 200 ms 空闲退出、共享读取和正常刷新。
- [usage-summary-cache.js](../../../../src/usage-summary-cache.js) 的有效性检查读取性能修订表、WorkBuddy trace，缓存到期边界 SQL 也引用 `perf_samples`。移除这些输入并更新缓存格式；保留用量事件、额度观察与 reset 的到期边界，防止旧缓存把 TPS 数据带回接口。
- [history-archive.js](../../../../src/history-archive.js) 与 [history-backup.js](../../../../src/history-backup.js) 包含 TPS 组件和删除权限证明。必须保留用量/报价/额度自身的完整性及来源删除约束，旧容器兼容不能依赖重新运行 TPS 算法。

## 删除范围

前端删除 [index.html](../../../../public/index.html) 的模型速度区域、[app.js](../../../../public/app.js) 的速度导入/渲染/事件监听、[app-state.js](../../../../public/app-state.js) 中的速度选择状态、`perf-ui.js` 及专属样式和翻译。保留模型用量表、时间线图、跨周期对比、来源编辑和皮肤；正常内容自然衔接，不保留空白行。

后台删除专用 `perf-*`、`perf-sources/*` 中的 TPS 计算/读取/计时/采集模块、`codex-official-*` 日志 DLC，以及相应 CLI 子命令、executor 消息、`summary.perf`、`report.perfSamples`、`perfMeta` 和公开性能状态。Codex 原始记录、来源身份和用量解析中确有共享用途的少量职责先移回正常读取路径，再移除旧目录的依赖；不保留一个能重新启用 TPS 的后端。

将 DSH/OpenCode 插件的打包入口、采集启动器、计时导入导出/探针、定制 Codex 引擎补丁和并排包工具收入研究盒子，再从活动项目与新发行包移除。TPS 独有测试随实现封存，混合测试保留非 TPS 的行为验证；有价值的完整历史上下文也保存在盒子中，Git 历史仅作为额外定位线索。

移除 `tiktoken` 及锁文件依赖。它是当前唯一生产 npm 依赖；摘除后以离线解压运行验证确认无需生产 `node_modules`。Node 版本要求仍由 SQLite、zstd 等正常用量能力决定，不在本次顺带降低。

## 旧数据与已安装采集器

首发不清空用户索引、不重写历史归档，也不执行全库 VACUUM。新索引采用 schema 24，只建立正常用量所需结构；schema 23 升级仅抬版本，不为 TPS 执行建表、删表、重建或数据回填。更早且当前已支持的索引保留必要的用量迁移，跳过废弃的 TPS 迁移。旧库遗留的 TPS 表/列不再被速度逻辑查询或维护；普通来源删除触发已有外键级联时，关联旧 TPS 行可能随之删除，不为阻止该间接效果重建旧表。

旧备份和归档只保留一份按 schema 19–24 区分的核心表清单，复用现有容器校验器。保留整文件 SHA-256、quick_check、核心表指纹、核心外键、定价与 service-tier 证据校验；允许旧 manifest 和 store_meta 含额外 TPS 项，不解码其速度语义，也不动态加载旧 TPS 模块。通用文件/元数据哈希可以覆盖旧内容，不等于继续维护 TPS 功能。旧文件的支持范围不因这次摘除缩小。

`perf_missing_sources` 虽然名称含 perf，仍承担原始来源缺失与历史保留账本的职责：保留旧键的兼容读取，去掉对 TPS ready/方法版本的依赖，并以普通来源状态对外提供。报价输入、历史事件修订、冷热事件 union、用量投影和 rollup 继续保留；它们不进入退役范围。fresh 库的投影跟踪只引用实际存在的核心表，避免仍为已删除的 TPS 表建 TEMP trigger。

`perf_file_warnings` 中的 project-log 截断与坏行诊断同样属于普通历史保留功能：只提取这两类诊断并维持原子提交、跨轮读取与回滚保护，旧速度告警不再参与。Codex `logs_2.sqlite` 及其 WAL 仍是 service-tier 计价与额度来源判定的输入，不能因 TPS 摘除而从普通缓存失效条件中删掉。

持久汇总缓存和当前服务的短期冻结快照更新格式并失效重建，避免旧 `summary.perf` 重新出现。旧离线包和历史归档不因此失效，也不改写原件；导入后只暴露非 TPS 数据。保留原始日志、events、来源信息、报价输入、额度证据、用量 rollup 与历史事件修订。无原始来源时，已归档的用量/费用仍应可读，不能以“删索引重建”作为升级方案。

主程序停止采集后，已安装在其他客户端里的插件和官方 TRACE 设置不会自动消失。切换前单独完成一次清理：

- Codex：利用现有恢复状态，只撤销本项目仍持有的 RUST_LOG/debug 与 analytics/OTLP 修改，保留用户之后的编辑。旧版 `codex-logging disable` 已要求 Desktop 退出；需要退出/重启时先与用户协调。清理完成后新运行包不保留启用日志的功能。
- DSH、OpenCode：通过各自标准插件管理/配置移除本项目条目，保留其它插件。WorkBuddy 恢复正常启动入口。不得整份覆盖客户端配置。
- 旧 companion、ledger 和原始日志作为本机历史文件保留，新版本不再消费。清理器只处理可确认由本项目安装的条目；没有安装记录的用户直接使用新包，不增加安装步骤。

这一步属于一次升级清理，不进入新看板的常驻后台或前端流程。本机清理使用保存的旧版恢复点，避免删除实现后失去恢复原配置的工具；新运行包不依赖该恢复点。当前不执行清理或重启。

研究盒子不包含私人恢复状态。本机恢复状态留在原受保护位置，清理工具从旧源码快照运行；新用户无需它。schema 24 库不交给旧 schema 23 程序直接打开，回退使用升级前的数据备份与对应旧包，避免“保留旧 release”被误解为可以直接降级读新库。

## 实施顺序

1. 制作并验收上述独立研究盒子，包含当前源码、测试、研究成果和未提交改动，排除用户数据、认证与无关实验产物。以当前包含 RANGE 的工作树为移除基线，不用 `reset` 或旧 HEAD 覆盖并行改动；盒子未验收前不删除实现。
2. 主代理先固定无 TPS 的报告/API/缓存契约，解开来源分类、缺失来源状态、普通索引和历史容器的共享调用。共享文件保持单人写入。
3. 按已确认边界，并行移除前端区域与独立 TPS 模块/工具/依赖；保留正常索引、报价、限额和历史功能。移除完成后检查整个运行导入链，确保没有启动采集、速度 SQL 或客户端配置写入。
4. 集中验证升级与正常功能，生成独立无 TPS 运行包，完成离线安装和界面验收。此前 TPS 的通过记录不作为本版本的完整验收。
5. 最后协调本机采集清理与服务切换。当前只生成本地候选运行包；不提交、推送、创建 release 或上传产物，客户端与现有看板保持原运行状态。

## 发布验收

- **统计不变：** 对固定数据比较各来源用量、费用、限额、日期/RANGE、模型/仓库对比和时间线。除 TPS 与动态时间/缓存标识外，核心业务值保持一致。
- **升级可用：** 从现有 schema 23 库升级到 24，读取支持范围内的旧备份和含冷数据的归档；覆盖原始来源已移除、历史导入、冻结、恢复与正常增量同步。保留用量、报价与额度本身的完整性和删除条件；旧 TPS 元数据不能单独授权删除原始用量数据。升级不得主动重写旧 TPS 数据，另测正常 source_files 删除的既有级联行为。
- **功能确实移除：** 全部 API/JSON/冻结导出不再输出 TPS；运行包没有 TPS 模块、插件、定制引擎或 `tiktoken`；普通启动和刷新没有速度扫描/计时写入/TRACE 配置。旧数据库残留 TPS 表不影响启动，新库无 TPS 表。
- **界面与安装：** 真实浏览器验证速度区域完全消失、没有残留空隙或脚本报错，RANGE/筛选/详情/刷新/皮肤正常；解压新包后直接启动，检查所需 Node 环境和无生产 npm 依赖。

先运行受影响的局部验证，稳定后执行一次剩余完整套件、typecheck、lint/format 和发行包冒烟。仅对失败或后续修改涉及的范围复测，不反复跑已通过的 TPS 专项。

建议新增 release 和普通命名产物 `agent-usage-v0.8.5.zip` / `.tar.gz`，保留旧版本作为回退点。发布说明只说明移除模型速度及正常功能保留，并提示 JSON 消费方的 TPS 字段已移除。最终包大小与耗时收益在实际打包后测量，不提前承诺比例。
