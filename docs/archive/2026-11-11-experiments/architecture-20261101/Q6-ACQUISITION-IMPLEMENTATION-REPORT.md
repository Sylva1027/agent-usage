- 新增一个可重建的 `usage_source_catalog` 表，保存文件/目录身份、来源绑定、逐文件指纹和小型检查状态。没有建立第二套用量事实或解析进度；没有修改计价、额度、汇总或冷历史算法。
- 快速通路按 journal 对象身份选择已存在的 Codex JSONL / DSH 文件，复用 `appendFile`、`replaceFile` 和持久化依赖队列。来源绑定从权威 `source_files` 读取。普通追加不再加载全部来源行、枚举全部历史目录或重算所有文件内容指纹。
- 首次初始化建立目录身份并给文件封口，读取固定结束截点后，只补处理该区间内的已知变化及依赖。补处理期间的新写入保留给下一轮；不把处理结束时刻当作已处理截点。原生逐文件证明仍绑定真实解析字节，SHA 回退保留完整前缀核验。
- 提示保留来源根、具体路径和事件类型，重复路径合并，最多保留 128 项，未知/溢出单独标记。提示只影响调度顺序，不授权跳过来源证明；没有收到提示也能检查 journal。
- 服务器、响应缓存和通知复用同一份完成凭据。已认证通路的同步前后、查询发布后不再重复全量发现；仍检查小型辅助输入和数据库发布版本。范围切换沿用既有 `skipCheck` 请求及完整已提交视图。

## 提交和恢复边界

每个来源的事实与解析进度仍在原事务中共同提交。全局检查游标在必要事实、依赖修复和输入核对之后发布；它与所有文件事实不是一个跨全轮的大事务。

来源/进度/额度事实变化会在同一事务中撤销旧清单的可用标记，事件修订另由现有持久业务修订检查。事实已经提交、清单尚未发布时，中断恢复会使用现有解析进度重新检查；不会把旧游标当作已经处理，也不会重复累计。发布前另检查本连接的 `data_version`，拒绝同步期间意外的外部数据库提交。原读快照、冷包核验及响应缓存外部写入保护保留。

一次变化区间最多接受 2,048 项记录，原助手扫描仍有 64 页、4 MiB、2 秒边界，单次桥接请求仍限 3 秒；JS 身份解析另有 2 秒检查预算。超过预算走原流程，不截断列表后宣称成功。依赖过多也回退。以上约束限制快速路径的选择，不丢弃合法的大记录或历史。

小游标和状态与目录行一起放在这一个派生表中，没有另写高频 `store_meta` 游标。这是对计划落点的局部调整；价格、时区及时间到期仍使用原有效期规则。目录游标写入仍可能使响应缓存因保守的外部提交保护而失效，没有为命中率放宽该保护。

## 已确认的限制与下一步

**本轮证实了接入、对拍和恢复，尚未证实目标速度或快速路径的持续命中率。** 实测遇到同卷已删除对象及父对象都无法解析的情况；即使很可能是无关临时文件，也无法证明它与来源无关，因而回到完整检查。没有把这类回退改成忽略。目录/新文件拓扑变化和其他 harness 改变也仍走完整路径。

已选中的变化文件仍会计算现有首尾指纹；`prefixBytesRead=0` 只表示解析证明没有重读旧前缀，不代表该轮所有来源读取字节为零。辅助文件检查、journal 读取、执行器启动、派生结果维护及缓存保守失效也仍有成本。

目录身份初始化和旧文件封口会增加首次认证的工作；本轮只有小夹具，没有测大型初始化开销、服务树内存峰值、全链路刷新中位数或完整重建。因此不能据此宣布刷新已达 1.5 秒、文件数增长达标、资源门达标或完整重建改善。

建议下一步仍严格执行原第三卡的固定 **100 次计时追加、80 次切换、8 次重开、0 次空库完整重建**。在原定样本内记录快速通路/回退次数及原因，单列首次认证成本；不增加新的路线或无限诊断。性能比较前冻结代码，原生和 SHA 分开，同口径对照 Q5。完成本卡后先停，不自动启动第三卡。

尚未检查：第三卡性能和资源矩阵、Linux/macOS、长期 p95 与一年/两年容量。未迁移活跃数据、配置系统 journal、重启用户服务、推送或部署。
