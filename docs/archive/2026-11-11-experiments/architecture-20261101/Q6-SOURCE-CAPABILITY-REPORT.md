## 本轮实际验证

使用当前 Windows 普通用户令牌、C 盘已活动的 journal 和隔离小文件；E 盘返回 journal 不可用，保留回退。没有启用或修改任何系统 journal。工具执行越过文件访问限制不等于提升为管理员令牌。

单文件 worker 的最终夹具为 **37,889 字节**；目录探针最终夹具按文件路径累计约 **1,026 字节**，包含硬链接的重复逻辑计量。没有读取真实使用日志、导入事实数据库或启动产品服务。实验助手复用现有 `usn.rs` 的打开、查询、分页、记录校验及扫描上限；新增观察逻辑仅在实验文件中，构建产物放在忽略目录。

| 第一卡情形 | 实际操作与结果 | 结论边界 |
| --- | --- | --- |
| 1. 持续打开的 writer | 句柄在初始边界前打开；只设一次文件边界后连续追加 20 次，19 次无新目标记录，等待 250 ms 和 1 s 后仍无记录；处理后逐次设文件边界的对照为 20/20 可见；现有 bridge 的 20 次 verify/advance 也全过 | 不能只读日志并推进游标；需要逐个已消费文件的新边界 |

| 6. 漏通知及未知路径 | 主探针完全不依赖 `fs.watch`；一次原始全区间读取在无预知文件 ID 过滤的情况下定位到处理中新建的文件；既有“漏 wake 后 checked sync 恢复”及合并通知测试通过 | 通知只唤醒；未知/重复通知不能改变检查的正确性 |

普通权限读取返回的 V3 记录中 `name` 实际为空，不能照着通用记录格式假定名称存在。本轮通过 `OpenFileById` 和 `GetFinalPathNameByHandleW` 定位新增文件；解析失败、对象已删除、重解析点或别名不明确时，必须保守重查。文件身份应同时支持实际返回的 V2/V3 表达，不以错误的 64/128 位字符串比较制造“没有变化”。

本轮的日志合并现象是对 [B2 活动 USN 记录](B2-ACTIVE-USN-PROBE.md)中已知机制的复核。新增证据集中在目录拓扑、无名称记录的路径定位、逐次边界对照及截点交接，不把已知问题包装成新发现。

## 第二卡必须实现的四项准入条件

1. **完整初始化。** 先盘点受管来源、目录、全部路径别名及相关配置/发现范围，建立卷与对象身份映射，对受支持文件建立有效边界。初始化起点取盘点之前的截点；盘点期间的变化仍留待处理。首次、状态不完整、外部写库、卷/目录身份变化或回退后，不能假装既有认证仍有效。缺失原始来源的已保存历史继续保留。
2. **处理过的文件重新设边界。** 日常把实际日志记录映射到既有路径，复用当前 verify/parse/advance 契约处理变化，再对这些文件建立新边界。不能因元数据相同跳过已经被日志标脏的文件。这样才有依据让下一次同种写入再次进入日志；不需要把所有历史文件永久留在活动集合，也不靠静默超时推断句柄关闭。强制 CLOSE 不是 writer 关闭事件；不能把自己生成的 CLOSE 当作噪声全部删除，它可能携带合并的并发写入原因。只有精确 seal USN 与已提交的解析内容/进度共同证明已处理的记录才可去重，无法证明则回退。
3. **保存本轮捕获的截点。** 本轮只确认开始处理前取得的有限区间。该区间的来源、跨文件依赖及必要业务结果处理完成后，才允许持久确认；期间的新变化从下一轮处理。不能用处理结束时的最新 journal 位置代替它。事实已提交而截点未确认时按旧区间重放，依赖既有进度保证不重复累计；这部分原子性须在第二卡用真实数据库中断用例验证。
4. **不明范围回退。** 初始快速范围只允许已有身份基线、受支持卷上的 Codex JSONL/DSH 普通追加。目录拓扑、硬链接/重解析点歧义、未知归属、辅助输入、其他 harness 变更、缺口、权限或助手失败均禁止假定“其余未变”；走既有完整检查并重建必要认证。确认不属于受管范围也需要依据，不能把无法解析的对象直接丢掉。

以上条件允许把正常追加的工作量压到实际变化及其依赖。它们并不保证现实中经常能进入快速通路：卷上的无关活动、未知对象、拓扑变化和 journal 限额仍可能造成回退。回退频率、首次目录认证成本以及最终绘制速度，必须在第二/三卡计量，不能从小文件结果推算 1.5 秒目标已经达到。

尚未完成的准入验证具体是：全体受管目录初始化与并发变化的闭合、并发 seal/write 的原因归属与去重，以及这些规则组成一个完整变化清单后的八组对照。日志重放可行也没有替代数据库提交/发布的崩溃原子性验收。按原计划的严格停止条件，不能把这张卡标成全面通过并自动启动第二卡；独立审查给出的“有条件允许实施”是技术建议，仍停下来交用户反馈。

- 单文件探针 **8/8** 通过，其中 7 组使用真实原生基线/拒绝结果，junction 一组明确标为受控 SHA 回退；原生被接受的追加边界共 21 个（20 次普通追加及 1 次硬链接追加），不把 `null` 算作安全拒绝通过。
- 独立 worker 运行既有来源、通知、协议及回滚定向检查，**5/5** 通过，并补查坏协议助手是否实际退出。
- 主探针已通过编译、真实区间正/负对照及脚本自检；不是整页性能测试。正式源码及原生源文件基线共 **108 个文件**，收尾检查逐文件一致。
- 首次目录探针的阳性对照失败，原因是 V2/V3 文件身份表达未匹配。保存为 `invalid-initial-positive-control.json` 并排除；修复后文件边界阳性对照、无名称路径定位及后续对照均通过。后续私有快照保存了补充对照前的版本，旧 `decision` 字段不代表本报告最终结论。
- 初次独立审查把“不设逐文件边界的反例”扩大成了活动集合不可收敛的判断。最终结论须基于逐文件重新设边界、路径定位及固定截点重放的对照；单一反例只否定其对应的简单方案，不能证明所有实现都不可行。
