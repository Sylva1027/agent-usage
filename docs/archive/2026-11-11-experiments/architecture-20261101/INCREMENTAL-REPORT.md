## 结果

在与[上轮初筛](WINDOWS-REPORT.md)相同的重复切换和小来源更新口径下，四个候选均已达到切换 200 ms、索引更新到显示 1 s 的目标。**首次未计算范围、冷启动和自然自动刷新仍有等待，不能把这些成绩推广为所有操作都即时响应。**

下列每个场景、每个候选均为 **100 次**，数字为 p95：

- **P1 / Node + SQLite**：切换 **672 → 67 ms**；更新到显示 **2,638 → 175 ms**，约 **15.1 倍**提速。常驻服务页面重载 **131 ms**。
- **P2 / Rust + SQLite**：切换 **134 → 57 ms**；更新到显示 **3,212 → 165 ms**，约 **19.4 倍**提速。页面重载 **115 ms**。
- **P3 / Rust + redb**：切换 **128 → 54 ms**；更新到显示 **3,097 → 106 ms**，约 **29.2 倍**提速。页面重载 **103 ms**。
- **P4 / Rust + DuckDB**：切换 **171 → 65 ms**；更新到显示 **5,134 → 138 ms**，约 **37.3 倍**提速。页面重载 **116 ms**。

四组各 100 次切换均低于 200 ms，400 次更新均低于 1 秒，且逐次校验修订和精确 token 数。更新最大值分别为 **203、188、122、175 ms**；Node 那一次超过 200 ms 的样本没有被删除。

这证明这一轮的主要收益来自增量发布和可复用的业务视图。Node + SQLite 也已达到本轮两项热路径目标，暂无必须更换语言或 SQLite 的证据。redb 在这次顺序运行中的更新数字最快，但它不构成生产迁移的最终选型依据。

## 改了什么

**持久提交只处理变化来源。** 三种 Rust 存储实现 `commit_delta`，不再在小提交内读取完整 State。发布态按来源持有 `Arc<PreparedSource>`，只准备变化来源、替换对应块并更新计数；提交时不再构造或排序全局事件向量。显式 report/query、启动及持久快照仍可全量读取。

**未变化元数据不再读取和重传。** changes 增加可选 `contextSince`，旧调用仍获得完整 context。Node 记录持久 context revision；Rust 重启后保守地重发完整 context。上下文省略只影响传输，不影响来源/游标/版本的原子提交。没有 context 的提交也不再读写原来的 23 MB blob。

**共享业务层保存来源贡献。** 常用范围首次使用时，按来源建立原业务公式的贡献及会话、仓库路径等身份集合。后续版本复用未变化来源，只重算被替换来源，再合成完整视图。会话、仓库路径、渠道/模型和 timeline 都按原口径合并，不能简单把各来源的去重数量相加。

新增默认 `incremental` 模式直接读取业务视图；`published` 和 `legacy` 保留为旧路径对照。热路径不再重复调用完整 `/api/query`：基础整数统计由同一来源事实的业务视图提供，并在独立对拍中验证。没有调用后丢弃结果，也没有冒充业务公式已全部 Rust 原生化。

## 增量工作的证据

四组诊断一致：初次准备 **159,610** 个事件，100 次单事件来源更新后累计为 **159,710**。来源业务贡献共构建 **164** 次：初始 16 个来源 × 4 个常用范围，加 100 次变化来源；未变化来源贡献命中 **1,600** 次。

初次载入加 100 次更新的 feed 总量由 **2.513 GB 降为 151.118 MB**，减少约 **94%**；后者主要是首轮完整历史。无变化的 307 次薄版本探测共约 10.5 KiB。真实数据联调另外检查：单来源新增、替换及清空时，各次 feed 小于 10 KB，且仅处理该次变化事件。

100 次更新的平均业务投影耗时从每组约 **1.25–1.37 秒**降为 **5–7 ms**。平均提交耗时：Node **11 ms**，Rust SQLite **49 ms**，redb **10 ms**，DuckDB **18 ms**。这是完整更新速度改善的分段证据。

合成仍需要合并已准备的分组和会话身份，不能由这些计数宣称总体成本与历史规模完全无关。1×/5×/10× 扩展矩阵尚未完成。

## 仍然慢的部分

**首次查看尚未计算的范围。** 本轮每组记录的一次首次“全部”查询为 **2.40–2.56 秒**；本周为 **0.75–0.90 秒**，本月为 **0.36–0.47 秒**。它们未计入预热后 100 次切换分布。常用视图首次按需建立，尚未持久化为重启后可直接读取的业务视图。

**冷服务首屏。** 每组三次观测：Node **2.91–3.23 秒**，Rust SQLite **3.06–3.62 秒**，redb **3.10–3.43 秒**，DuckDB **3.24–3.96 秒**；尚未达到原计划的 1 秒重启首屏目标。三次观测不作为稳定 p95。

**额度和滚动范围。** 为保留资格和时钟语义，额度窗口、滚动一天及其他尚未支持的 named recent 范围继续使用原业务算法。自定义普通日期范围和排除 homes 已有合成对拍，但没有各自独立的百样本速度矩阵。

**自然自动刷新。** 默认真实时钟下四组均通过冻结、恢复和无用户操作更新检查，显示新修订耗时 **60.03–60.09 秒**。这是小夹具单次功能观察，不是 p95；原页面的 60 秒检查周期未改变。手动触发后的百毫秒成绩不代表自然刷新也已变成百毫秒。
