# B2 整页成本归因：分段与资源账本

> 历史材料，2026-11-11 归档。本文命令与状态属于原记录日期；源码及恢复方法见[归档入口](../README.md)。

日期：2026-11-03。状态：**第一张归因卡完成，停止等待反馈。** 本轮没有实现主摘要复用切片，没有进入 B3/C，没有更改生产源码、真实历史、索引、保留策略或用户服务。

## 结论

当前追加慢的主要问题已经能解释：**原始新记录的解析只需毫秒，更新之后的全历史业务计算仍需要几十秒。** 活动 journal 能消除大前缀 SHA 验证，但不会消除主摘要、额度历史、元数据及周期对比的全局工作。

10× SHA 的一个普通 Codex 追加可展开为：通知前约 **6.959 秒**，页面请求至 JSON 完成约 **26.389 秒**，数值绘制约 **0.261 秒**，最终观察等待约 **0.103 秒**，合计 **33.712 秒**。其中主摘要约 **15.389 秒**，额度准备约 **6.740 秒**，周期对比约 **4.132 秒**。这些是有父子关系的时间，不能重复相加。

内存方面，已找到明确持有链：`UsageStore → summaryProjectionCache → HistoryQuoteInputs → chunks → TypedArray → ArrayBuffer`。10× 正常查询为报价复用分配 **126,812,160 字节，约 120.94 MiB** 的分块缓冲。它是完整逐事件载体，显示按周/月不会让它变小。除此之外还有临时对象分配、SQLite/运行时及网关占用，不能把整树 RSS 全归给这份缓冲。

建议下一张只做 **all 主摘要的持久增量复用**：覆盖时间线、费用、渠道/模型及基础总计，复用现有事实、精确成员和发布设施。其直接目标是消除每次追加后的约 15 秒主摘要重算及逐事件报价载体。**即使这部分耗时降为零，代表样本仍约剩 Codex 18.3 秒、DSH 8.6 秒；不能承诺一张卡就达到一秒整页目标。**

## 1. 范围与测量方法

沿用 [B2 原页面诊断](B2-PAGE-DIAGNOSTIC.md)、[来源增长诊断](B2-GROWTH-DIAGNOSTIC.md)及[历史年龄评估](../../2026-11-11/proposals/2026-11-03-age-tiered-history-query-assessment.md)。复用同一冻结生成规则：六来源、1,968 文件、1,729 会话、90 天；初始事件 1× 为 146,412、10× 为 1,464,120。本轮仍不能证明一年/三年或多冷分片容量。

- 核心矩阵为 **1×/10× × SHA/活动 journal，共四格**。每格一次未插桩对照，随后每种来源三次插桩追加，共 **32 次核心普通追加**，均通过正确总量、API 事件数及绘制核验。
- 使用原 Chromium 页面、原 SSE、默认 60 秒补查、相同业务规则。gateway old-space 512 MiB，executor old-space 224 MiB、semi-space 4 MiB，未加堆。
- E: 私有镜像走 SHA；C: 专用临时镜像使用已经活动的 journal，检查点和实测字节均确认原生路径。没有启用、重设 journal 或提升用户服务权限。
- 两个卷的物理位置、路径长度和数据库体积不同，因此不能把整页差额全当作 journal 收益。比较来源证明用直接分段与字节计数；整页数字分别报告。
- 每格只做一次必要的独立镜像准备及空库导入，不重复原完整重建矩阵。复制、导入、首次派生准备与普通追加分开；同一镜像顺序追加，trial 的实际起始计数保存在 `result.initial`，不冒充完全同状态的严格 A/B。
- 同时记录方法包含时间、直接子区间并集扣除后的 self wall、同进程 CPU、FS API 交付字节、实际缓存缓冲，以及浏览器 fetch/SSE/JSON/DOM/双帧时间。
- Windows 采样间隔 500 ms；服务树、浏览器、runner、observer 分开。明确传入真实 `StateDir`，修正旧 sampler 扫描错误目录的问题；记录 Working Set、Private Bytes、逻辑 I/O、SQLite/WAL/SHM 和可见临时文件长度。
- 重型 CPU/堆分析单独运行，一次 Codex 追加通过，但耗时和 RSS **不计入正常成绩**。另重放一次漏 SSE 轮询恢复，核对旧内存峰值的触发路径，不混入普通追加。

插桩经加载钩子注入，生产文件不变。首轮工具将 TypeScript 编译器留在服务进程，已单列为工程校准；之后改为在 runner 离线生成插桩源码，服务进程不加载编译器。晚增的成员预算、事实版本及临时页观测在原生组/重型/恢复组覆盖；早期 SHA 记录没有这些 note，不把缺失当作未触发。核心方法边界与业务规则一致，未据少量样本声明 p95 或精确优化百分比。

## 3. 分段成本账本

### 3.1 可以相加的整页时间

以下选择 10× SHA 第一条 Codex/DSH 普通追加。时间轴边界来自实际记录；日期毫秒与单调时钟的合计有不足 1 ms 的差别。

| 不重叠阶段 | Codex 秒 | DSH 秒 |
| --- | ---: | ---: |
| 来源写入开始 → 浏览器收到 SSE | 6.959 | 3.735 |
| SSE → 浏览器发出 usage 请求 | <0.001 | <0.001 |
| usage 请求 → JSON 读取完成 | 26.389 | 19.756 |
| JSON 完成 → 正确数值双帧绘制 | 0.261 | 0.265 |
| 该绘制 → 最终观察完成 | 0.103 | 0.107 |
| 合计 | **33.712** | **23.862** |

最终观察包含诊断等待，不把最后约 0.1 秒归为业务 CPU。通知前包括发现、证明、事实提交、元数据及通知准备，不能全部叫作解析。HTTP 请求阶段包含执行器、业务查询、结果传输和发布检查。

### 3.2 父调用内部的构成

以下行含有嵌套，**不能把父调用再与子调用求和**。单独列时间线，是为了区分它和主摘要总时间。

| 调用/工作 | Codex 秒 | DSH 秒 | 口径 |
| --- | ---: | ---: | --- |
| `syncRound` | 4.542 | 1.329 | 通知前的一部分 |
| └ 来源 `appendFile` | 3.149 | 0.309 | 包含证明、解析、提交 |
| └ 其中两次 SHA 前缀读取 | 3.103 | 0.279 | `verify` 与 `capture` |
| 原始新增内容流式解析并写事实 | 0.0054 | 0.0029 | 包含解析回调插入；不是纯解析 CPU |
| 本范围 COMMIT 调用合计 | 0.0045 | 0.0075 | 包含事实/派生提交；不再加入父调用 |
| 通知前主要元数据计算 | 2.118 | 2.115 | 与 `syncRound` 分开 |
| usage 中额度准备 | 6.740 | <0.001 | 主摘要 core 之前 |
| 主摘要 `summarizeInReadTransactionCore` | **15.389** | **15.303** | 后两行是它的组成部分 |
| └ 时间线事件流、计价与累加 | 9.554 | 9.462 | 约 146 万事件 |
| └ 渠道/模型 SQL 分组 | 5.128 | 5.144 | 两次查询合计 |
| 周期对比 | 4.132 | 4.125 | core 之后 |

主摘要余项约 0.71/0.70 秒，主要包含范围总计等；不是未分配的额外 15 秒。直接父子区间用并集扣除，异步等待保留在 self wall；**self wall 不等于独占 CPU**，跨进程等待不能再当作 IPC 自身耗时。

代表 Codex 的 HTTP 段 26.389 秒中，额度 6.740 + core 15.389 + 周期对比 4.132 = **26.261 秒**，剩余约 **0.128 秒**属于执行器/读边界/传输/其他网关工作，保留为综合余项。通知前 6.959 秒扣掉 `syncRound` 4.542 与元数据 2.118，余约 **0.299 秒**，包含通知唤醒、执行器启动、来源状态重验及发送；并未把这部分凭空分给解析。

### 3.3 重复工作及触发条件

1. **主摘要随全历史重做。** 一条新增事件后，时间线实际消耗约 1,464,123 条报价事件，产生约 4,392,369 次精确会话成员 `add`。计价回调自身约 1.28 秒，不能把整个 9.55 秒都称作价格算法；其余包括 SQL 取行/转换、桶与成员操作、累计及报价输入捕获。
2. **单遍分组会主动放弃。** `createFusedSummaryGroups` 对四种维度共享 1 MiB 的成员估算预算。原生组明确记录到 **1,048,680 字节**触发放弃；10× 原生诊断有 8 次。随后渠道和模型回退到两次全范围 SQL，约 5.2 秒。不是猜测 SQLite 无缘无故慢，也不是通过增大预算解决了它。
3. **额度有独立全局成本。** Codex 追加包含新额度观察，失效后的窗口选择约 6.7 秒，其中历史周期表构造占较大部分；DSH 没有使额度观察变化，准备可直接命中。旧观察仍参与窗口推断，不能简单按年龄删除。
4. **小范围页面还附带全局结果。** today/week 也返回元数据与多周期对比；约 2.1 秒元数据、4.1 秒周期计算不能由“今天只有几条事件”推断为零。已有纪录增量本轮可复用，`prepareRecordProjection` 不再是普通追加的主要秒级成本。
5. **来源证明已局部有效。** 10× 活动 journal 的代表来源追加约 Codex **48.7 ms**、DSH **28.9 ms**，零前缀读取；但整页仍约 31/24 秒。采集组件变快与整页达标是两件事。

### 3.4 缓存拒绝复用的实证

10× 两个插桩组分别记录到 13 次发布判定，其中各 **4 次**为：来源输入相同，但 publication 不同。原生组还同时记录事实业务修订号；一个明确例子是查询前后均 **149451**（1× 原生），durable 签名相同，publication 后缀从 `:0` 变成 `:1`。

对应代码是 `UsageSummaryCache.readPublication`：SQLite `data_version` 前进，即使 `store_meta` 的 durable 摘要不变，也会推进 publication 修订。查询维护派生缓存会写数据库，因此可能拒绝保存这次已计算的摘要，后续又出现 miss。

这确认了**事实未变化但复用机会丢失**的实际案例；没有证明所有 miss 都来自此处。保护本身仍负责外部写入与一致性，不能直接删掉。后续持久视图必须区分事实、价格/证据、派生完成状态及纯维护写入，同时保留对旧写入者、并发修订、未完成依赖修复的保护。

| 10× 环境/来源 | CPU 核秒（观测） | 逻辑读取 GB | 逻辑写入 GB |
| --- | ---: | ---: | ---: |

这是服务树采样范围内的 **OS 逻辑传输**，不是物理磁盘量；500 ms 采样、进程发现和短命执行器会漏掉首尾区间，尤其 1× 不能拿采样 CPU 当完整精确总数。插桩另有同进程 `cpuUsage` 和退出时 Node 进程 CPU；原生 helper/conhost 仍按 OS 观测单列。包含 CPU 不在父子调用间重复相加。

可以独立核对的实际输入读取：

- 10× SHA Codex 第一条：前缀证明 **4,044,844,405 字节**，`FileHandle.read` 实测求和相同；解析流实际交付 **569 字节**。
- 10× SHA DSH 第一条：前缀证明 **359,871,724 字节**，解析器边界读取有重叠，实际 FileHandle 交付与文件增长分别记录，不能把增长 144 字节冒充总读取。
- 10× 原生代表 Codex/DSH：证明前缀读取 **0**，journal 读取计数分别 **184,448 / 230,696 字节**；解析增长分别 **569 / 144 字节**。

纯新记录解析只有数毫秒、提交只有数毫秒，与三十秒不是同一量级。重型 CPU 剖析也指向 `createCycleTable`、`groupedRange`、`costEventsForRange`、`periodAggregateCore` 和 GC，未发现 IPC 序列化是主要秒级瓶颈。Profiler 的叶帧采样含 idle/采样间隔，不能替代 OS CPU 或正常分段数字。

## 5. 内存与磁盘高水位账本

### 5.1 服务树 RSS

包含 gateway、executor、存活 helper/conhost，浏览器、runner、observer 分开。

| 环境 | 未插桩活动峰值 MiB | 插桩活动峰值 MiB |
| --- | ---: | ---: |
| 1× SHA | 304.5 | 291.9 |
| 10× SHA | **520.0** | **518.1** |
| 1× 活动 journal | 292.6 | 332.6 |
| 10× 活动 journal | 503.9 | 490.5 |

数值覆盖启动后追加/切换的活动范围。SHA 未插桩也超过 512 MiB，不能把超限全解释为插桩。不同进程生命周期、GC、访问序列和卷路径会影响峰值；小样本不能据较低原生组宣布资源门全面通过。本轮没有执行连续 60 秒空闲与长期验收。

10× SHA 插桩最高点 **543,293,440 字节 = 518.125 MiB**，当时为：

- gateway：182,235,136 字节，约 **173.79 MiB**。
- executor：343,941,120 字节，约 **328.01 MiB**。
- 两个 conhost：17,117,184 字节，约 **16.32 MiB**；该点没有存活证明 helper。

这些是同一时刻的进程分解，可以相加。V8 heapUsed、external、arrayBuffers 和对象图则有包含/驻留差别，不能与 RSS 混加。

### 5.2 持有对象与临时分配

- 正常 10× `quote.finish` 记录约 146 万行、**90 块**缓冲，实测 backing storage **126,812,160 字节 = 120.9375 MiB**；1× 为 **12,681,216 字节 = 12.09375 MiB**。这不是按行公式推测，来自实际 `ArrayBuffer.byteLength`。
- 独立堆快照找到上述缓冲的强引用链，直达 `HistoryQuoteInputs` 和 `UsageStore`。执行器快照对象图 self size 合计 **139,956,802 字节**，其中所有 `JSArrayBufferData` 为 **127,012,522 字节**，与实测报价块相符。
- 网关独立快照对象图约 **23.36 MiB**，其中字符串约 **12.10 MiB**；它没有报价块。正常运行的 heapUsed/Working Set 峰值更大，CPU profile 有明显 GC；不能把峰值都解释为持续存活的业务缓存，也不能据此断言内存泄漏。
- 堆快照会触发 GC，并扰动占用和耗时，因此只用于持有关系。未对 SQLite 原生分配、V8 保留页、共享映像等逐字节追踪；这些不能用 `RSS - heapUsed - arrayBuffers` 简单算出。

### 5.3 原 573.5 MiB 与恢复路径

[B2 旧记录](B2-PAGE-DIAGNOSTIC.md)的 **573.50 MiB** 保持原结论：当时 gateway 209.92 MiB、executor 334.72 MiB，其余为 helper/conhost。旧运行没有对象快照，不能事后声称其每一字节的持有对象已知。

本轮额外重放一次闭 SSE 后的轮询恢复：**69.605 秒**后 API 与正确绘制完成，未观察到 SSE，事件数增加一条。该路径峰值 **464.75 MiB**；gateway 约 105.55 MiB、executor 约 330.41 MiB，其余为 helper/conhost。它复现了原恢复路径与量级，未复现旧总峰值；主要进程差额在网关，不能用较低新值覆盖旧超限，也不能把差额全部归给报价缓存。

### 5.4 SQLite、WAL 与临时空间

正常插桩 trial 的**可见 SQLite 文件族同时峰值**，不包含约 4/40 GB 来源镜像和剖析文件：

| 环境 | SQLite 文件族峰值 MiB | 单独 WAL 类峰值 MiB |
| --- | ---: | ---: |
| 1× SHA | 226.02 | 5.29 |
| 10× SHA | 1853.45 | 5.32 |
| 1× 活动 journal | 215.46 | 5.30 |
| 10× 活动 journal | 1752.82 | 5.33 |

WAL 类峰值与数据库类峰值不一定同时，不能再把各自峰值相加。未插桩对照还包含首次导入，10× SHA/原生的 WAL 类峰值约 **102.36 / 95.80 MiB**，与普通查询分开。C/E 逻辑路径长度不同，数据库体积差额不能当作新存储优化。

原始 `allocatedBytes` 字段调用 `GetCompressedFileSize`，普通未压缩、非稀疏文件下与文件长度相同，不能当成 NTFS 簇分配量或整个卷的实际占用。该字段名称保留兼容，工具说明已收紧；本报告表内只使用文件长度。[Microsoft API 说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getcompressedfilesizew)

专用 TempDir 未观察到命名文件，但匿名成员库在关闭前实测 **188 页 × 4096 = 770,048 字节**，`PRAGMA database_list` 文件名为空；额度 TEMP 库也观测到约 **1.34 MiB** 逻辑页。SQLite 匿名库/排序文件可能不可枚举或在采样间隔内消失，因此：**可见临时文件峰值为零，匿名物理临时空间总峰值未知**。本卡已经修正目录错误并揭示该观测边界，未声称临时磁盘为零。

2. 首个快路覆盖当前默认来源组合/日历口径；其他范围、排除来源和时区能力保持可用，回退及其成本明确记录。不能用关闭这些功能通过验收。
3. 请求级价格、未知字段、缓存写入、修订撤回、精确成员及数值/舍入契约保持不变。价格、证据、时区、算法变更按真实影响范围重建候选，完成后发布。
4. 为该视图区分事实和派生依赖，修正稳定复用所需的版本边界。保留并发写、外部旧写入者、pending 修复及一致发布保护，不能简单跳过 `data_version` 或返回旧数据。

不包含额度周期、元数据、多周期对比、其余四来源采集、多冷包、周/月年龄政策、语言或数据库更换。它们的现有成本继续计入整页。

**有依据的收益上限：**代表 SHA miss 的 core 为 Codex **15.389 秒**、DSH **15.303 秒**。即使整个 core 免费，33.711/23.861 秒仍约剩 **18.3/8.6 秒**；实际维护、合并、边界读取都有成本，所以这只是现有样本的消除上限，不是预测成绩。报价块可避免分配约 **120.94 MiB**，但不能承诺 RSS 同额下降；需重新计量视图、成员、WAL 和工作集。

验收出口应同时满足：

- 同一 1×/10× 的字段对拍、修订下降、价格/证据、边界时钟、成员重叠与中断恢复通过；新值发布后原页面准确绘制。
- 无变化重启能复用；普通追加的派生读行和计价量不随无关历史线性增长。组件 CPU/I/O ≤1.3 倍增长可作为新提议，先冻结工作集口径。
- 默认堆不提高，服务树仍接受 512 MiB 活动目标；新增磁盘、写放大、候选/临时高水位必须实测。
- 原页面刷新/切换仍全额测量。沿用 1 秒追加、200 ms 切换、2 秒无变化启动的最终目标，但组件通过不能冒充整页通过；SHA 下界及剩余 6.7 秒额度等照常报告。
