## 实现范围

一条候选，两项改造，沿用当前 Node、SQLite 和浏览器。

1. **事实批量写入。** 来源替换中的事件和额度观测以最多 128 行、256 KiB 的批次写入，另受实际 SQLite 参数数限制。超出字节预算的合法单行独立写入；顺序与逐来源事务保留，在累计查询、后续留档读取及提交前刷新待写批次。普通追加仍沿用既有增量入口。解析字节摘要与提交前重读验证保持 Q3 的 v2 契约。
2. **派生初始化减少重复工作。** 日汇总为空时复用既有精确增量 SQL，一次构建 UTC 和本地日、模型、仓库及会话关系，再认证进度；已有/部分视图使用原有修复入口。派生作用域集中核算自身写入，普通调用方继续逐行检测，事实修订另参与发布键。摘要仅记住每个现有成员作用域最后确认的一个成员，连续重复记录省去数据库查重；不增加全历史成员 Set。额度每个完整两分钟簇一次更新锚点，保留原有非传递聚类和后缀传播。

Windows 显式 `TZ` 切换下，SQLite 与 Node 可能使用不同本地时区。批量分组会核对每组真实最早/最晚时间是否都落在 Node 的日边界内，无法证明时使用原有路径。保留原有空日标记，旧时区修复及冷历史贡献回归通过。

没有新增持久表、迁移版本、运行进程、依赖或 UI 元素。gateway 512 MiB、executor 224 MiB / semi-space 4 MiB 保持不变。已有库保留既有事实，不需要清空重导，原始来源已缺失的事实继续按原契约保留。

## 验证方法

Q3 对照冻结自 `bd2a1fc7f46740bc5b15ed437571476563f0eb68`，逐文件核验 100 个源码/页面文件；Q4 候选冻结 101 个文件。运行中及跨轮源码摘要继续核验。全部 12 份镜像（含备用）在首次认证前准备完毕，Codex/DSH 追加文件为独立副本，其余来源只读；不复制活跃用户数据库。

两规模包含相同六类来源、1,968 个用量文件及辅助文件，原始输入约 4.27 / 41.83 GB，初始事实 146,412 / 1,464,120 条。完整重建从独立空库实际检查、同步、解析，直到原页面默认页和首次 all 正确绘制；包含浏览器启动，服务就绪和采样器准备单列。每组先两次，差值除以较小值超过 5% 才补第三次。不是物理冷盘或正式 p95 测试。

原页面四格每格 10 次 Codex、10 次 DSH，共 80 次，沿用对应最终冷构建的已发布事实。计时包含记录落地、来源检查、SSE、请求与正确新值绘制；另验服务重开复用。九类主业务字段、元数据和周期对比逐值比较，只规范镜像路径、来源 id 与评价时刻字段。额度另以相同 asOf、关闭响应 JSON 缓存、独立冻结 Q2 SQL 和完整周期流作对照。

八轮冷构建的页面价格结果精确一致。最初追加准备发现后台汇率更新（6.6505→6.6637），严格起点对拍拒绝续测，尚未注入任何追加。保留该失败准备记录，随后将四格隔离价目恢复为原种子快照，并仅在页面复测加载器中冻结远程价目更新；正式代码不变。普通追加比较固定价格输入，在线价格更新成本未纳入这 80 个样本。

服务树、浏览器、运行器与资源观察器分开记录。Windows 逻辑 I/O 不是物理磁盘流量；500 ms 采样峰值不是瞬时上界。持久页按 `dbstat` 计量，WAL 与目录可见 TEMP 另列；未观察到的匿名 SQLite 临时文件不能写成零。函数包围时间包含子调用，不能把嵌套标签相加。

## 结果

八次完整重建全部通过，四组差异均低于 5%，无需补样。每次原始耗时与中位数如下：

- 1× Q3 对照：55.590、54.878 秒，中位数 **55.234 秒**。
- 1× Q4：46.930、46.993 秒，中位数 **46.962 秒**，减少 **15.0%**。
- 10× Q3 对照：475.233、473.252 秒，中位数 **474.243 秒**。
- 10× Q4：371.291、372.850 秒，中位数 **372.071 秒**，减少 **21.5%**；两次均低于 400 秒目标。

首轮 10× 的包围计时显示：来源替换约 345.43→291.14 秒，UTC+本地日汇总约 42.96→17.49 秒，额度准备累计约 19.36→10.58 秒，all 摘要准备累计约 31.66→17.51 秒。这些是同轮标签的累计时间，包含子调用及正常回退，不与嵌套标签相加，不把单次分段写成全矩阵中位数。

初版分析器误将正常 `SOURCE_PROGRESS_UNSUPPORTED` 当作终局失败。八轮均有相同两次受控回退；修正后只有错误类型匹配、外层来源替换成功、完整重读子调用成功且时序闭合时才归类为恢复，原始错误记录保留，其余错误仍使验收失败。完整来源及页面校验照常生效，未重跑或删去计时。

## 普通追加与通知观测

最终四格共 80 次追加，原页面事件数、新值、精确业务字段、元数据及周期对比通过，四次服务重开复用通过。每源 10 个样本的中位数：

- 1× Codex：2.116→2.085 秒；DSH：1.743→1.735 秒。
- 10× Codex：5.140→5.167 秒（+0.53%）；DSH：2.108→2.078 秒。

刷新基本持平；本轮主要改善完整重建，整页一秒目标仍未实现。10× 主摘要读取中位数约 3.46 ms，额度准备约 4.99 ms，报价载体为零；普通追加额度保持增量，没有全历史周期重建。

第一次 10× 候选追加组在第 10 次 Codex 追加时，响应与新值绘制均已通过，但未观测到相应 SSE 计数增加，严格探针使该组停止。保存的前 9 个成功样本及该失败尝试单独归档，不混入最终统计。随后从同组未追加过的 rep1 冷库复测完整 20 次，起始业务结果与 rep2 精确相同，保留相同来源检查、严格 SSE、价格输入、资源参数，并增加通知/请求时序记录；20 次及重开全部通过，异常未复现。

因此实际注入为 **80 次最终样本，另有 10 次中断组诊断追加**；并非总共只注入了 80 次。原失败缺少触发时序，尚不能确定是轮询竞态还是通知异常，不将其解释成已修复的探针误报。重建与资源目标通过，通知可靠性保留这一项未解释观测。
