### 进程归属修正与原始失败记录

一年混合复测的原始统计给出 529.961 MiB 的服务树上界，未过 512 MiB 门。逐进程追溯发现，采样器只依据父 PID 遍历，把 11 月 4 日已启动的 OneDrive 归入 11 月 8 日刚启动的助手子树；Windows 复用了原父进程的 PID。这个不可能成立的父子关系带入约 150.57 MiB 的进程历史峰值。

保留 `analysis-year-before-identity-correction.json` 和全部原始 NDJSON。这套夹具的服务及浏览器均由本组 runner 新建；新增离线统计工具只排除**创建时间早于该 runner**的外部成员及其后代，证据不完整或可能是本任务孤儿的成员继续保留。这样也能处理误指的父 PID 已退出的采样。规则不按程序名字排除，也不降低 512 MiB 标准。原始记录和计时工具不改、不重跑页面，修正后的独立副本、逐文件原／新哈希及排除理由写入 `resource-identity/receipt.json`，由原验收分析器读取。最终资源表使用该规则统一重新分析全部组。

复现最终离线分析：

```powershell
node experiments/architecture-20261101/resource-identity-analysis.mjs all output/archive-verification-reuse-20261108/validation.json output/archive-verification-reuse-20261108/analysis-final.json
```

最终统一处理 30 份资源记录、421 个受影响采样，排除 13 个可证明属于实验外的进程身份（OneDrive、预先存在的 ASUS 进程及后代）。原始记录不变；Int64 创建时间保留精确值。生命周期清理核对 553 个身份，无存活或未知实验进程。

## 首轮失败与限定复核

固定矩阵为 10 组原页面运行。首轮一年出现 11 项延迟未过门，按事先允许的异常复核规则，仅对一年全热／混合各补一对新旧版，共多运行 4 组；没有重跑当前或追加第三次一年配对。另有 1 次旧版定向诊断，不能混入正式对照或称为 p95。

一年全热首轮的十项退化涉及相同读量、解析量下多个未改动阶段普遍慢约 14%～18%；新增授权检查不足 1 ms，未找到足以解释它的代码原因。同代码限定复核未再次出现，结论是“未稳定复现、原因未定”，不能称为已经证明机器噪声。

一年混合首轮切回 all 的 6.604→8.182 秒有具体轨迹：原执行器在既有 200 ms 空闲边界退出，新进程重算约 1.45 秒的周期统计。两版此操作均做 8 次 SHA、约 14.183 GB 读取，SHA 约 5.49 秒；并非证明写入导致失效或字节校验变慢。本卡没有延长空闲时间或重做周期缓存，保留这个间歇性成本。

## 比较口径

- 同一份来源、已有索引种子、原页面和原始归档；Windows、SHA 来源检查，价格检查统一为 1.1 秒后返回未改变价格的失败结果。
- 首开至 all 包含来源检查、同步、解析及首次建立派生完成记录；不是空库完整重建。刷新结束以正确新值实际绘制为准。
- gateway 512 MiB、executor 224 MiB＋4 MiB semi-space、200 ms 空闲退出均不变。服务树资源上界须≤512 MiB，浏览器另计。
- 延迟保护门：不能同时增加超过 10% 和 100 ms。不能用其他操作的收益抵消某一项退化。两年另有绝对门，一年混合保留 C1 的既有绝对门。
- 当前 49 天／146,412 条事实；一年 365 天／1,108,151 条；两年 730 天／2,175,492 条。一年、两年是冻结的合成扩展，不能声称已经覆盖真实累计多年使用的全部分布。
- 进程冷启动，不是清空操作系统文件缓存的物理冷启动。候选只回放业务时刻以便逐值对拍，性能计时使用真实时钟。

## 改动与成本边界

同一次同步和紧随其后的 dashboard 可以共用仍受保护的归档读者。每包仍执行锁前和固定 SQLite 读事务内的两次完整 SHA；每次独立操作重新验证字节。当前授权、来源绑定和修订继续按当前快照检查。

完整语义校验的完成记录存入既有冷热投影数据库，绑定归档 SHA、长度、完整 manifest、格式与算法版本。只有完整成功的校验才能发布；首次升级、内容变化、缺失或损坏证明仍完整检查。记录最多 256 条，淘汰只损失加速能力。

现有 Windows 助手增加短期归档只读租约，并固定从盘符根到直接父目录的完整非 reparse 路径。仅文件锁不足以阻止父目录联接替换；父目录允许读写共享、拒绝删除共享，实测兄弟文件操作及主库 WAL 写入正常。旧助手、无可用租约、WAL 归档继续走原有独立校验；旧进程内证明与新版持久证明分域，不能直接升级可信程度。

需要从本卡源码执行 `npm run native:build` 及 `npm run native:check` 才能获得新版租约能力；本次仅本地构建、测试，没有安装助手或重启在用服务。主事实库没有新增业务表；未更换语言、数据库、解析器或 UI。
