## 实际改变与六来源状态

Claude 保留严格较大用量胜出、相同用量取首条和末尾标题规则。WorkBuddy 立即挑选首个有效非 Auto 候选，不再保存所有原始重复消息。两者小集合用普通 Map，大集合落匿名 SQLite；仅对时间和消息 ID 排序，保留 JavaScript localeCompare 和稳定原序，相邻更新合并写。序列化保留负零等原数值，不改变事件 ID / 计价累计顺序。

ZCode、OpenCode 在同一只读快照中读取会话与用量。唯一 BINARY/TEXT 主键且实际键全为文本时直接使用上游索引；重复键、NULL/BLOB、非标准主键或缺表仍按原语义回退。回退集合和警告去重集合有预算，异常会关闭来源事务和临时库。没有以 MAX(id) 代替旧行修订、删除核查。

| 来源 | 当前采集能力 | 变化时仍需完整处理的范围 |
| --- | --- | --- |
| Codex | 有证据的逐文件续读、新会话／目录登记 | 历史改写、证据失效等受控回退 |
| DSH | 有边界证据的压缩帧续读、新会话／目录登记 | 不支持的合法大帧及受控回退 |
| Claude Code | **本卡新增：候选及排序有界** | 当前变化的整个转录文件 |
| WorkBuddy | **本卡新增：紧凑候选及排序有界** | 当前变化的整个转录文件 |
| ZCode | **本卡新增：索引会话读取、有界回退、一致快照** | 当前变化的数据库用量快照 |
| OpenCode | **本卡新增：索引会话读取、有界回退、一致快照** | 当前变化的数据库用量快照 |

六者共同使用同一事实库、持久业务视图与历史保留机制。**公共后端覆盖六来源，不等于六适配器都已完成相同的增量能力。** 本卡不改事实替换事务，旧行删除仍保存被替换的历史贡献；既有索引不必重建或升级 schema。
