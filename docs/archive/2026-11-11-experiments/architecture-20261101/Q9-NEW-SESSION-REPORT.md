## 4. 实施与正确性

仅修改生产模块`src/usage-source-acquisition.js`。完整变更区间中，按创建记录、对象身份和父目录链识别Codex普通JSONL、DSH v4新文件；父子记录可乱序。最终捕获再次核对文件身份，新目录与ready状态在最终短事务一起登记，不跨原生异步等待持有该事务。复用现有解析、事实、进度、依赖修复和业务发布。

新增与依赖路径总数仍限2,048。目录覆盖不完整、改名/删除、压缩表示切换、返回的缺失来源、硬链接/重解析点、未知路径、另一harness范围、无可靠证明及超预算保留完整回退。价格、历史保留、字节证明、恢复协议及“新数据已提交才算刷新完成”均未改变。没有可靠Windows变更区间时，本卡不提供这条新增快路径。

## 5. 验收结论、次数与证据

选定矩阵**8组服务、16次新增、8次追加、4次重开、0次真实历史空库重建**全部完成。另有正确性补丁前的2千候选组4次新增，保留但不并入最终对照：**实际共9组服务、20次新增**。重跑是为修复审查发现的嵌套来源范围和不完整目录覆盖漏洞，不是重采慢点。

准备阶段缺少可选配置/状态目录的失败记录保留，未产生计时观察。首次分析误将Q8“快路径拒绝、随后全同步”的无解析探针当作完成同步，已加严格自检并对原证据重分析；未重跑服务或改门槛，原工具摘要和旧分析另存。首次退出核对碰到一个恰好退出的PID，单独确认消失，最终核对通过。

最终为**86项契约检查85通过、1项原生重开复用失败；26项数值门19通过、7未通过**：3项规模比例、3项普通刷新防退化、1项原生重开。另核对原生普通刷新绝对1.5秒门通过、旧SHA4.718秒门未过，二者不混入26项。分析器保留`failed-or-incomplete`，表示验收失败，不是计划样本缺失。

私有证据：`output/architecture-20261105/q9/`下的`analysis.json`、`verification.json`、`process-cleanup.json`、冻结快照、各组结果/恢复记录、trace、绘制和资源样本；旧候选在`formal/new-2000-candidate-before-scope-fix/`。可复用工具为`q9-benchmark.mjs`、`q9-sessions.mjs`、`q9-hook.mjs`、`q9-analyze.mjs`，提供无服务启动的自检。
