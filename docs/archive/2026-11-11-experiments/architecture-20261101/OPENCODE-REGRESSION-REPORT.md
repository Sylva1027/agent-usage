### Claude：复现通知等待期间的执行器退出竞争

定位对照后续追加为 **2.045 → 2.264 秒**，增加 219 ms／10.7%，再次触线。文件数、字节、5 个文件的事实变更次数和 all 摘要读取／计价 2,030 条均相同；`syncRound` 约 1,293 → 1,436 ms。没有证据支持改写 Claude 解析算法。

当前版在记录落地后约 **73 ms** 收到旧执行器 `idleClose`，随后新执行器约 **217 ms** 才收到同步；旧版同一执行器约 **148 ms** 收到同步。源码显示：来源通知先等待 75 ms 合并，服务器直到 `onHint` 进入来源检查时才持有执行器。这段等待里已知有待处理提示，却可能被 200 ms 空闲定时器提前关闭。

小型真实执行器用例验证了该竞争：先送入来源提示，尚未触发通知合并回调时执行已有的空闲回调；**修复前执行器被退休，断言失败，修复后同一执行器和采集凭据保留，处理结束后仍正常空闲退出。** 该用例证明生命周期缺口，不证明 Claude 多出的每一毫秒或 OpenCode 的全部旧症状同源。

## 最小生产改造与正确性

只改 `src/usage-source-watch.js` 与 `src/server.js`：第一条提示进入合并等待时取得已有的 `retainWorker` 持有；合并提示共享一次持有，通知触发后持有至实际检查完成；取消等待、处理完成或失败时释放。重叠提示各有自己的持有，停止监听释放尚未执行的提示，正在处理的检查结束后释放。

保留原通知回调的同步调用时机、75 ms 合并窗口和 200 ms 空闲退出；持有不会启动不存在的执行器，也不阻止显式关闭。**没有加长空闲超时、增加堆或常驻进程。** 初版实现曾把通知回调移至微任务，完整回归有 3 条既有时序用例失败；已恢复原调用时机，最终全套和相关回归均通过，不修改那些断言掩盖回归。

`799d83e` 的同步价格目录传递、AsyncLocalStorage 作用域和价格版本比较保持原样。ZCode 两次候选追加分别核对 7,674／7,675 条，均只插入 1 条；旧历史修订仍完整回退。候选 12 次变更各只有一次来源同步、无空同步。无新增持久表、schema、依赖、原生助手或 UI 改造，四来源仍完整读取对应原始文件／数据库。
