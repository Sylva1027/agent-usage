## 实现与一致性

`src/usage-all-summary-store.js` 保存基础总计、费用、渠道/模型统计及时间线的计算状态；会话去重成员留在索引化 SQLite 表中。普通追加从最后一个检查点继续，不重读完整事件载体，也不建立逐事件 `HistoryQuoteInputs` 缓冲。只保存一个当前时区/粒度上下文，没有预生成所有筛选组合。

- 按现有 legacy 查询的 **event id/插入顺序**累计，保持浮点加法顺序。已用“先插入大额、再插入较早时间戳的小额”的反例验证精确尾数；没有通过改变旧算法排序或放宽金额容差获得对拍。
- 新 id 即使带较早时间戳仍可追加到累计状态。旧 id 的更新、删除或 REPLACE 从受影响位置前的可用检查点重放；上下文或来源语义变化则重建。
- 每 1,024 条事件一个检查点区间，每区间只留最新快照；保留最近 32 个区间及空起点，最多 33 份。超过保留区间的旧修订可从起点重放，事实和成员精度不丢失。这约束的是派生快照副本，不是历史保留量。
- 事实修订、dirty 位置、成员与检查点通过同一数据库的短事务协调；只有完整且版本一致的结果可读。构建中断后继续；缺失或损坏检查点在事实未变化时也能主动恢复。
- 定价、汇率、证据、时区、来源身份和派生格式参与失效判断。保留来源待修复阻断、原响应缓存的发布核验和 `data_version` 防护，没有把旧值冒充新数据完成。

接入在真实同步之后、汇总读快照之前；没有把长时间构建包在同步的旧读事务内。当前只加速 **热事实、全部来源、all、无明细、天/周/月粒度**。来源筛选、明细、其他范围及冷历史沿用原路径；查询计划或来源语义不满足原顺序契约也回退。

收尾还修复两处实测发现：无排除范围的日期边界改为同一 SQL 语句中的两个索引端点查询，保留空库、epoch 和冷/筛选语义；持久结果接管时释放旧逐事件报价载体，同时保留此前的聚合结果。回到原明细范围仍可复用，不用再次扫描事件来交换内存释放。

## 性能方法

沿用冻结的六来源增长数据：1,968 文件、1,729 会话、90 天；1× 初始 146,412 事件，10× 为 1,464,120。原页面、真实发现/校验/同步/解析与 SSE 路径均保留。每格独立镜像，空库准备与普通追加分开；每种来源连续追加三次，再切换 today/week/all，最后重启完整隔离服务和浏览器检查复用。

旧实现来自本轮开始前冻结的 97 个 src/public 文件，加载时逐文件核对摘要；当前实现使用本轮源码。四格顺序执行，不与完整回归重叠。gateway old-space 512 MiB、executor old-space 224 MiB / semi-space 4 MiB 不变，没有加依赖或加堆。

本轮集中于 E: 的 SHA 回退环境；不把上轮活动 journal 的结果混入本轮对照。每格三次追加是诊断样本，不计算或宣称 p95。Windows 每 500 ms 采样，包含服务子进程和辅助进程；浏览器、runner、observer 分开。I/O 为 OS 逻辑传输，不是物理盘读写。重启后的第二个服务根进程不在首个根的资源树内，重开延迟可报告，但不据该段声明资源验收。

**d 四格**验证主体改造和首次构建，24 次普通追加全部通过；初始/六次追加后的四组结果，对基础总计、费用、事件/会话/home 数、时间线及错误、渠道/模型九类字段精确对拍。随后两处收尾修复以 **e 两格续测**验证：复用各自 d 的实验镜像，再各做六次追加；起始事件已多六条，九类字段先与 d 的末态逐值核对，再检查新数据与绘制。e 不是同初态的第二次严格 A/B，不能跨轮拼加速百分比。
