## 已确认的阶段与下一次定位重点

**9/9 事实完整，9/9 SQLite `quick_check=ok`。** 每次都独立核对了六来源事件数、五项 token 总和、额度观察、文件/home数量；会话数始终1,729，文件数1,968，home数6，冷分片0。5×/10× 的全部事实已提交，之后才发生 OOM；事实已写入不等于端到端首屏完成。

因此后续优先收敛**导入后的处理工作集**。源码中可确认的候选是 `src/usage-store.js` 的 `quotaObservationsFromDatabase`：以 `Array.from` 把全部额度观测变成 JS 对象；`quotaObservations` 再按全局修订缓存整份载体，供窗口选择和范围纪录消费。本轮额度历史也随规模增长，不能把内存失败只归因于用量事件数。

这条读取路径的内存随额度历史增长是代码事实；**尚未通过函数级探针证明它就是本批 OOM 的首个触发点**，故障报告没有可用 JS 栈。下一次先做定向定位，再决定阶段 B1 中首先消除哪份全历史载体；本轮不追加正式改造，也不直接据此选择语言或存储迁移。

## 本轮范围

只补齐完整重建的历史量轴：合成 1×、5×、10×，每档三次，从全新空索引启动正式服务，执行真实来源发现、文件状态检查、指纹、读取、解压、解析、同步和业务计算。成功要求原页面显示本轮精确结果后两帧；失败原样保留。另有一份冻结真实输入的物理目录校准。

使用当前索引和 DSH 单遍导入版本。没有修改正式源码、数据库耐久设置、网关或执行器默认堆预算，没有增加产品工作进程；没有替换活动数据库或重启用户服务。每轮独立状态、独立浏览器，固定输入只生成一次并复用。

三个规模固定六种 harness / 六个 home 实例、1,968 个用量文件、1,729 个有事件的会话和 90 天时间窗。增加事件密度、原始行数、解码字节和压缩输入，因而对应约 14.6 / 73.2 / 146.4 万条事件；不是文件数增长或年份跨度增长试验，冷分片为零。

源文件长度合计为 4,173,636,380 / 20,867,701,211 / 41,736,256,911 bytes；日志解码量为 6,410,418,406 / 32,052,089,440 / 64,104,178,880 bytes，另有每档固定约 93.19 MB 辅助配置/证据输入。源文件长度指实际压缩文件/SQLite 的逻辑长度，不是磁盘分配簇或物理读写计数。

## 物理目录校准

真实样本：146,412 条事件，71,153 条额度观察，1,968 个用量文件，1,729 个会话。重新定位捕获文件到 E 盘私有目录，不使用 readdir/stat 回放；这不是对原 C 盘来源位置的延迟校准。轻量口径的完整重建到首屏单次 **53.660 秒**，服务进程 CPU 合计 **55.514 核秒**，执行器 OS 生命周期峰值 RSS **183.418 MiB**，服务树采样峰值 RSS **224.125 MiB**。

合成 1×：同样的事件、文件、会话、额度观察数量通过正式六来源解析与独立持久事实核对；解码字节与真实画像相差约 0.000008%，源文件长度约多 4.845%。早期单次预检只用于工具自检，不混入正式矩阵。

合成内容与真实内容不同：固定少量模型和请求用量，减少累积用量/重试等复杂变化；日志目录统一为 fixture，cwd/项目按文件生成，业务分组及首屏载荷与真实输入不同。Codex 合成为每文件单个 zstd 流；DSH 帧数随规模增加，保持平均帧粒度。SQLite 保留 reader 所需表/字段与索引，未消费的表以独立 padding 表代替，OpenCode 保留每个消息 8 KiB 合成 JSON。合成曲线用于比较相同规则下的增长趋势，不能把它的绝对秒数等同于真实历史。

本批 today 用量为 0；计时器要求非空、已初始化的精确 title，且首屏 metadata 和重建事实库都必须具有该规模全部事件，随后经过两帧，避免把页面初始空值/0 当作完成。

## 环境与资源口径

Windows 11 build 26300，Node 24.19.0，i7-14700KF（20 核 / 28 逻辑处理器），约 31.76 GiB 物理内存。网关 old-space 参数 512 MiB，执行器 224 MiB、semi-space 4 MiB；这些是既有默认值，不等于 RSS 上限。机器环境及源码哈希保存在私有 output 中。

Chromium 启动放在计时前；浏览器资源单列。没有清空 OS 文件缓存或独占整机，属于进程冷启动。初次发现、同步及内容解析仍真实执行；关闭自动发现/价格刷新调度仅用于固定后台条件，各数据集配置一致，未设置 skipCheck 或注入规范化事件。

外部 PowerShell 7 观察器约每秒记录服务树 Working Set / Private Bytes / 进程峰值 / CPU / Windows 逻辑读写计数及 SQLite/WAL 体积，父子关系约三秒刷新，短命 Node 进程另以启动/退出遥测补齐。服务树包含其控制台辅助进程，浏览器与观察器分开；CPU 合计也包含短命启动器。

- CPU 核秒是进程 user+system 累积时间；正常退出用全生命周期数据，异常退出缺失的尾部必须标注为下界。
- 单进程 OS 峰值 RSS 是生命周期峰值；服务树 RSS、Private Bytes 和 WAL 是采样峰值，可能漏过短峰。
- 各进程峰值之和不代表同时发生的树峰值。
- 读写是进程逻辑 I/O，包含缓存和 IPC，最后一次采样可能漏过退出尾部；不能解释为物理磁盘流量或 SSD 实际写入。
- 采集成本另列，不并入产品服务资源。没有测量空闲 60 秒稳态或整机资源受限配置。

## 正确性与复现

生成器的小夹具通过正式解析器检查 1×/5×/10×、逐事件 token、额度观察、固定会话、时间边界及二元 `(source_path, parser_event_id)` 身份；跨文件共享 Codex 会话保留。每次成功重建独立核对六来源事件数及五项 token 总和、额度、文件/home/会话、首屏 metadata、页面精确值及 SQLite quick_check。输入在生成后与整批运行后分别全文件 SHA256，哈希工作不计入重建，也不与重建并行。

私有目录：`output/architecture-20261103/growth-baseline/`，包含 profile、真实校准、三个不可变数据集、空状态种子、环境、源码哈希、逐轮 manifest / analysis。正式矩阵为 `standard-light/manifest.json` 与 `standard-light/analysis.json`，同口径真实校准为 `real-light/`。单轮完整结果沿用 `output/architecture-20261102/full-startup/growth-*`，含 API、事实库、进程遥测、资源样本和失败诊断；不发布原始来源或配置内容。

运行后再次核对三档各1,973个输入文件 SHA256，5,919项均无变化；真实校准1,973项也无变化。正式 `src/`、`public/` 的87个文件哈希未变，本轮实验网关和采样器均已退出。没有因本轮重跑完整业务测试；本轮验证针对工具、真实格式、事实完整性和实际崩溃状态。

本轮保留的输入、旧诊断批次及正式多轮状态文件长度合计约 **87.16 GB**，位于 ignored `output/`，供后续复现；这不是产品运行时额外常驻资源要求。未在用户反馈前清理这些证据副本。

工具：`growth-profile.mjs`、`growth-dataset.mjs`、`growth-run.mjs`、`growth-analyze.mjs`、两类生成器及其测试、`growth-resource-sampler.ps1`。使用既有 `full-startup-run.mjs`，只增加物理 home、固定实验选项、资源采样和致命错误报告接点，原有实验模式保留。worker 分工与模型请求见 `growth-worker-audit.json`。

正式计时使用 `startup-options.mjs`，只在已核验的服务工厂入口合并实验配置，不载入 TypeScript 或启用逐函数追踪。八项 Node 工具/生成器/原挂钩回归及 PowerShell 自检通过，后者包含保持写句柄打开时读取遥测、读取期间重新打开追加句柄的共享语义回归。

旧批次 `standard-a` 单独保留：一轮 5× 有明确的遥测 `EBUSY`，原因是 Windows 读取共享标志阻止了记录器写入，已修复；一轮 10× 在采样前消失，因未捕获 stderr，原因不能确认。其余旧 OOM 也不作为正式容量边界，因为旧配置挂钩额外载入了 TypeScript：单独导入测得额外约 8.21 MiB JS 堆，不能排除它影响临界点。整个矩阵以统一轻量挂钩重跑，旧结果和 `VALIDATION-STATUS.json` 均保留，不用成功重跑覆盖原始失败记录。

10× 准备时，生成器的 SQLite padding 校准因最终 B 树分裂比目标多两页而中止。已修正为有界页分配容差并补回归，保留失败文件与日志；1966 个已生成日志经逐帧/流式解码核对全部行数和字节后恢复构造，未重新生成或删减日志。该准备错误发生在服务基准之前，单独保留，不计作标准服务测量样本。恢复工具为 `growth-recover-lines.mjs`。

空索引重建只包含当前捕获原始文件覆盖的历史；已有库中原始文件消失的保留事实不在重建输入中。本轮没有把重建副本用于迁移或替换活动库。
