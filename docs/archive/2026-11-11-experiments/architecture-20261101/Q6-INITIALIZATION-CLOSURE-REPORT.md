## 本轮验证对象

使用隔离小文件和独立实验 SQLite，将来源清单、逐文件字节快照、原生证明与确认游标组合成可运行的验证载体。原始字节以 base64 保留，读取快照时核对字节摘要、大小、文件身份、证明 offset 和 seal USN 的绑定。源码只在 `experiments/` 中，正式程序及用户数据不变。

这是小规模能力验证：每次实验快照的源字节总量限制在 1 MiB，单文件捕获是完整读取。它没有实现生产 JSONL/DSH 解析、用量事实、计价或业务视图；实验中的小事务和全文快照不能直接搬作长期历史的正式实现，也不能据此宣称已验证资源或刷新性能。

## 固定的检查和发布顺序

初始化：

1. 在盘点之前取得起始游标 A，递归枚举受管目录、文件及对象身份；不明类型、重解析点或不支持的别名明确拒绝快速认证。
2. 对每个文件建立原生边界、读取字节、验证最终边界，得到与该字节快照绑定的文件证明。
3. 读取 A 之后的完整日志区间，固定结束截点 B。目录/别名疑义要求重新盘点；已知文件在其证明之后、B 之前又有内容变化时，仅补捕获这些文件。
4. 补捕获后仍确认 B，不追赶最新日志位置。B 之后的新增、改写和目录变化保留给下一轮，不等待所有 writer 安静。
5. 在同一个实验数据库事务中提交清单、内容/证明和 B。失败保持旧发布版本，首次失败不留下完成状态。

后续检查：

1. 从已确认游标读到新的固定截点，按对象身份映射到来源。
2. 只对有精确已提交内容证明覆盖的内容记录去重。目录变化不能因为文件内容已认证而被略过；不能笼统删除带 CLOSE 的变更记录。
3. 对变动文件重新捕获，随后在同一事务里提交快照与原固定截点。期间再来的变化留待下一轮。
4. 对外读取快照时使用同一个读事务，避免把不同提交的清单和游标混合；同一写连接在提交前不能把自己的未提交行当作已发布快照返回。

这里的“完成”针对明确的检查截点。截点之后的新写入必须能在下一轮找回；读到旧版本本身不算该条新记录已完成刷新。

## 实测结果

| 检查 | 实际结果 |
| --- | --- |
| 完整目录与字节清单 | 多层目录、两个来源子目录、空目录逐路径及逐字节对拍一致；样本名称代表来源组织，不代表已运行真实 Codex/DSH 解析器 |
| 初始化中新对象 | 枚举后新增文件或嵌套目录，不发布部分清单；原目录、原数据库明确重试后包含新增项 |
| 持续写入与有限初始化 | 每次文件 seal 后仍写入，初始化只定向补捕获一次；下一轮捕获截点之后的剩余字节，不反复全目录初始化来等待静默 |
| 初始化前就已打开的 writer | 句柄始终不关闭；首次累计 FILE_CREATE/CLOSE 触发一次保守拒绝，第二次同库初始化成功；随后连续 20 轮追加逐轮与源字节一致 |
| 目录与文件改名 | 父目录、父目录大小写及叶文件大小写改名均要求重盘点；即使旧路径仍能打开，内容 seal 也不能认证旧目录清单 |
| 失败与已有发布版本 | 首次失败后同库重开仍无完成标记；已有版本存在时失败不覆盖旧内容或游标；重解析点/别名保守拒绝 |
| 不同写入时刻 | 读取后、seal 后、提交前分别追加或原地等大小改写；陈旧捕获拒绝，或明确保留在未确认区间并在下一轮精确恢复 |
| 精确恢复 mtime | 初轮 JavaScript utimes 有数百纳秒误差，保留为非最终证据；最终使用隔离实验助手的 SetFileTime 恢复到原 Windows tick，三案大小及 mtimeNs 完全相同，闭环仍通过 |
| 已提交证书去重 | 已认证的内容记录按身份、字节、offset、seal 绑定去重；连续静默轮不重新读取或 seal 全部来源；未笼统忽略 CLOSE 标志 |
| 错误确认最新截点的负控 | 独立夹具里，处理期间新建文件被错误 late-ack 丢掉；正确 captured-cut 路线保留其记录，并通过明确重新盘点恢复该文件 |
| CLOSE 负控的边界 | 正常算法精确恢复字节；本机该样本还有独立 DATA 记录，故“丢 CLOSE”变体没有复现遗漏，照实记为未观察到，不把它包装成真实反例 |
| 提交前 SIGKILL | 实验库保留旧快照及旧游标；重开后仅恢复一次变化，随后静默轮不重复捕获 |
| 提交后 SIGKILL | 新快照及新游标都保留；重开后无需重新捕获该变化。Windows 实际退出为 code=1/signal=null，记录了真实 kill 操作；两案助手均随父进程退出 |
| 读取期间另一进程提交 | 在读取游标与文件行之间，由真实子进程提交；本次读仍完整看到旧版，下一次读完整看到新版，没有混合 |
| 二进制字节 | 不能按 UTF-8 往返的六个源字节，通过 base64、摘要和证明精确对照；不以文本显示内容代替原始字节 |

## 验收方法与证据边界

初始化测试由独立文件系统遍历/读取作对照；并发测试在读取后、seal 后和提交前等确定位置注入变化；恢复测试使用真实子进程强制终止，重新打开实验数据库检查快照与游标是否同版本。正常方案和错误确认最新截点的对照分开记录，不以人工篡改证书构造的无效状态冒充真实失败。

测试脚本首版中的语法、重试换库、过时断言、私有字段获取 PID 和 Windows 退出码等问题由主代理修正后实际运行；删除了一处会吞掉失败的分支及仅复制实现逻辑的合成检查。没有把 worker 自报结果、工具启动或错误算法的观测当作正确性通过。

本轮没有发布可用于正式长期历史的实现。数据库里保存的是**实验来源字节快照**，不是用量事实；不能据此宣称已验证历史保留、跨文件业务累计、计价、真实 harness 写入方式或全量业务发布。这些仍须在第二卡复用现有实现后对拍。没有进行整页、10×、文件数增长、完整重建或长期资源验收，1.5 秒目标尚未测试。

不明归属、目录/别名变化、证书不完整、journal 缺口或不支持卷的快速认证仍必须拒绝，交回完整检查。只读到新版本、或能进入快路径，并不自动等于所有新记录都已完成刷新。
