# DSH 单遍导入实施与完整重建复测

> 历史材料，2026-11-11 归档。本文命令与状态属于原记录日期；源码及恢复方法见[归档入口](../README.md)。

日期：2026-11-03，Windows / Node 24.19.0。结论：**保留单遍导入候选。最终三组配对的完整重建均更快，事实一致，CPU和执行器峰值RSS均下降。** 本次完成阶段 A 的一个导入优化子项，按用户要求在此停下；容量增长基线及 B/C 尚未完成。

## 正式改动

修改 `src/dsh-usage.js`，使用既有逐帧解析器一次读取和解析源文件：

1. 保留第一条 session header，暂存模型、provider、标题和用量等必要投影；usage 只保留实际参与计算的五项数值，不携带无关扩展字段。
2. 暂存使用 V8 二进制序列化，保留负零等既有数值行为。序列化 Buffer 合计不超过1 MiB时留在内存；超过则将已有及后续投影写入 SQLite 匿名临时数据库，按 rowid 顺序重放。
3. 仍完整扫描来源，先交付既有坏帧/坏行告警，再校验 header/version、解析仓库，最后按原顺序调用事件消费者。晚到或重复 header、模型切换和标题处理继续沿用原语义。
4. `finally` 关闭临时连接，正常返回、缺失/不支持的 header、告警/仓库/事件回调异常及临时插入准备失败均有清理回归。公开完整行流和数组读取 API 保留。

匿名临时数据库使用空文件名，SQLite 负责临时文件生命周期；本机编译为 `TEMP_STORE=1`，可向磁盘溢出。`cache_size=-1024` 是约1 MiB的页缓存建议值，不是进程内存硬上限。缓冲预算也不包含 JS 容器、当前合法大记录、原有压缩输入 Buffer 和解压帧；这些开销通过进程峰值实际观察。没有增大网关/执行器堆、增加常驻进程、修改正式索引耐久设置或主库 schema。

## 完整重建对照

使用先前捕获的同一份六来源真实输入、同一私有空索引种子、原页面及正式默认堆设置。基线包含上一阶段已加入的复合索引，仅将 DSH 模块替换为本轮修改前的冻结源码；候选使用当前源码。每轮创建新数据库状态与浏览器 context，按旧/新、新/旧、旧/新的顺序交错运行，共6次。

这些是进程冷启动；Chromium 启动在计时外，网页读取和绘制在计时内。目录/stat仍采用冻结回放，内容、指纹和SQLite读取捕获文件，必要同步及完整解析照常执行。没有清空OS文件缓存，也没有独占整机，因此不把绝对秒数外推为所有机器或真实目录访问的保证。

| 最终配对 | 两遍基线 | 单遍候选 | 缩短 |
| --- | ---: | ---: | ---: |
| 第1组 | 59.206 s | 51.203 s | 8.003 s |
| 第2组 | 58.506 s | 52.325 s | 6.182 s |
| 第3组 | 49.721 s | 44.591 s | 5.130 s |
| 中位数 | **58.506 s** | **51.203 s** | **约12.5%** |

每个实现只有3个样本，不报告p95或统计显著性。跨轮整机耗时有明显波动，所以采用本批配对；不能直接把昨天带重探针的53.629秒与本轮标准计时比较。计时结束条件为原页面显示该轮API精确值并经过两帧；由于捕获数据在本轮日期的 today 为0，新增了 title 必须非空的检查，避免把初始空值误判为已显示0。

## 单独诊断：实际工作量

另跑一对启用阶段、SQL、JSON及DSH计数探针的完整重建，不混入上述标准样本。两边持久事实再次一致：

| 项目 | 两遍基线 | 单遍候选 |
| --- | ---: | ---: |
| DSH整文件读取 | 322次 / 318,114,398 bytes | **161次 / 159,057,199 bytes** |
| DSH帧解压调用 | 155,934次 | **77,967次** |
| 累计解压输出 | 1,252,547,520 bytes | **626,273,760 bytes** |
| 全执行器JSON.parse | 1,432,383次 / 10.077 s | **1,278,834次 / 8.641 s** |
| 临时数据库 / 暂存磁盘payload | 0 / 0 | **0 / 0** |
| 此诊断完整重建首屏 | 50.946 s | **47.333 s** |

实际161个DSH文件的薄投影均在内存阈值内，没有新增临时库写入；超预算溢出与清理是合成夹具验证，不能冒充大规模真实溢出负载已经验收。JSON时间包含在解析等外层阶段中，不能与其他span直接相加。标准样本约7.3秒的中位差也不能全归因于旧首遍约3.9秒：重复读取、对象驻留/GC及整机波动都会影响差值；这组单次诊断的差值为3.613秒。

诊断含重探针，执行器峰值RSS为基线251.000 / 候选213.160 MiB，CPU合计58.888 / 54.574核秒，同样下降；其绝对值不与无重探针样本混报。
