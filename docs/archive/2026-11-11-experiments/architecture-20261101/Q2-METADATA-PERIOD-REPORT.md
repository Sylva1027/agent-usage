## 改动

- 元数据的事件数、精确全局/每来源会话关系、模型集合和最近活动时间持久化。按事件 id 分批构建，普通追加只读新增行；未来时刻查询对每个实际分组做索引定位。更改/删除旧事实走可恢复重建，时间、来源映射与警告仍按现有规则产生。
- 复用现有 UTC/local 日、模型、仓库及会话 rollup，保存经过认证的追加游标和日边界。新 id 即使时间较早，也只加入其增量；修订、删除和显式 id 的 REPLACE 退回受影响日修复，UTC/local 全部证明通过后才共同更新。
- 周期查询优先读取完整的 UTC 或本地日；范围首尾若已证明没有其他所选来源事实，扩展到完整日边界，避免反复扫描首日/末日。合并同一日历下所有完整缓存段，仅向原始事实查询段间空隙和未覆盖边界。16 项用量及已知性字段保持原样，价格/汇率变动不触发原始周期事实重算。
- 缺表、缺失/同名错误触发器和部分 schema 可以原子恢复；完整 schema 重开保持只读。元数据还会对事实表唯一索引和 schema 变化保守回退。热数据专用查询不会消费包含冷历史的完整 rollup；冷权威、校验失败与已有回退保持生效。
- 同步完成后先更新元数据视图，再 checkpoint，避免发布状态时又写出 WAL。准备派生视图后重新对齐修订，防止并发提交藏在旧的进程内缓存后面。

事实表、原始来源、历史保留及现有发布保护继续沿用。持久成员关系随历史存于磁盘；新增元数据批次最多 1024 行，不把完整历史转成 JS 数组或常驻集合。

## 对照口径

改造前为本轮开始时冻结的 98 个 `src/public` 文件，即 Q1 完成后的版本；加载时校验摘要。空库容量/首次构建账本使用 `q2-20261103-a` 的两个改造前基线和 `q2-20261103-b` 的两个候选。每轮全部镜像均在该轮认证前准备完毕，避免后建硬链接改变正在计时来源的 NTFS 元数据；a 的基线全部退出后才准备 b，原始数据构造和摘要相同。

a 的 1× 初稿候选已通过业务结果校验，但账本发现真实 sync 仍先重建日汇总、随后周期认证回扫旧事实，不能算作目标完成。Main 补齐实际同步入口，新增真实 Codex/DSH 追加计数断言并重跑回归；该候选退出最终表格，a 的 10× 候选在启动前明确延期，没有运行。最终 b 只运行两个候选，不把诊断轮与修正后结果拼接成一次成绩。

b 的四格业务对拍通过，但 10× 周期仍约 3.9 秒。定位发现原模型查询选中一个可用缓存段，却把整个请求范围都要求为完整缓存；新追加日期与旧历史之间的空日使它抛出缺日错误，再让整个周期退回原始 SQL。Main 改为合并所有完整段、只查询间隙，仓库查询同步复用相同范围分解。

**最终刷新成绩取 c 的四格续测**：各自复用 a/b 已发布镜像，双方起点都是原始事件数 +6；先核对与自己上一轮末态九类基础业务字段精确一致，再各追加六次，末态为原始事件数 +12。两种实现的起止结果也彼此逐字段对拍通过，包含周期对比与元数据；只规范镜像路径/来源 id 及不同实际追加时刻产生的活动时间字段，不放宽数值精度。独立测试另行覆盖活动与未来时刻语义。c 没有重建原始输入，首次构建成本继续采用 a/b 的实际账本，不能把 c 的启动时间当作空库重建。a 的来源硬链接元数据曾在准备 b 时改变，c 基线首次开页重新认证；该首次开页不用于冷启动加速结论，后续追加及服务重开在认证完成后测量。

1× 为 146,412 条事件，10× 为 1,464,120 条；六类来源、1,968 个用量文件、90 天与会话轴固定。10× 是密度验证，不等同于一到两年的独立容量验收。

每格含空库首次开原页面、三次 Codex 和三次 DSH 追加、多范围切换及完整服务/浏览器重开。保留来源检查、同步、解析、SSE、查询及正确新值绘制；没有清 OS 页缓存，不把它称为物理磁盘冷启动。gateway old-space 512 MiB，executor old-space 224 MiB / semi-space 4 MiB；没有加堆。每来源三次仅为诊断，不能计算正式 p95。
