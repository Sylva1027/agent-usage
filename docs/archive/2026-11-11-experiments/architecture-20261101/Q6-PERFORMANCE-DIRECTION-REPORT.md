本轮先跑 1× 原生 Q5/候选对照，实际完成 **7 次追加、3 次专门计时切换、1 次服务重开**。Q5 组完成 4 次追加及收尾；候选组完成 3 次正确新值观测后中断，三次全部依赖完整检查，已超过事先记录的 50% 回退停止线。剩余 10×、SHA、独立文件数、候选收尾与重开均未执行。没有为获取更好成绩补样或反复重跑。

首次打开及重开中的默认页面→all 准备动作独立于上述切换数量，不计入普通切换指标。复用 Q5 既有事实种子，通过 SQLite 备份和两个独立来源的复原/认证准备对照，没有重新导入整份真实历史。

主指标为写入完成到原页面正确新值的帧回调；同时保存等待 spinner 清除后的探针确认时间，二者不混用。以下都是本轮小样本，不是长期中位数或 p95：

- DSH：Q5 两次 **1.851 / 1.856 秒**；候选仅一次 **8.406 秒**，其中发生完整文件重解析，不能把它当作稳定增量性能。
- 已有索引首次打开到 all 视图：Q5 **7.246 秒**，候选 **14.873 秒**。包含浏览器打开、默认页面和 all 视图准备，不是空库完整重建，也没有清空操作系统文件缓存。
- 候选三次检查均执行了全量来源发现和目录枚举，每轮约 **1,969 次首尾文件指纹计算**；没有发布可复用的认证清单。前两次 Codex 的实际尾部解析只有 **568 / 569 字节**，却继续承担全局检查及初始化重试。

冻结对照为 Q5 `04aadc2` 的第二卡前留存版本，候选为第二卡结束时的版本。基线 109 个运行文件、候选 111 个运行文件逐文件核对；本轮未修改生产实现。页面使用各自冻结的原始资源，价格在各进程启动时固定为同一份留存目录。

原生组沿用 C 盘来源，将小型价格/导入配置也放到 C 盘，数据库仍放 E 盘；新旧版本布局一致。这样避免把 E 盘 journal 不可用造成的预期混合卷回退误当成候选算法失败。安装中的正式助手没有替换。

## 回退原因已定位

候选初始化报 `source checkpoint cannot be sealed`，在第一个没有可复用进度的 DSH 文件处停止发布。这个文件约 **946,567 字节**，不是新出现的坏数据：既有完整解析能读取 **69 条用量事件**。

唯一一组定向诊断复用了该文件，分别运行增量/完整读取，并检查第一个压缩帧：

- 该帧压缩后为 **243,620 字节**，头部未声明完整解压长度。
- 现有增量读取器的单帧解压上限为 **1,048,576 字节**；实际收到 `ERR_BUFFER_TOO_LARGE: Cannot create a Buffer larger than 1048576 bytes`。
- 增量模式因此返回 `SOURCE_PROGRESS_UNSUPPORTED`，没有生成检查点；完整模式正常产出 69 条事件。
- 正式采集清单目前按来源种类将 DSH 都归为必须有增量检查点的文件。一个合法但只能完整解析的文件，就阻止整个清单进入 ready 状态。下一次刷新又重复清单初始化，而不是复用已完成部分。

这暴露的是第二卡的接入缺口：**发现某个文件有没有变化，与能否只解析该文件尾部，被错误地绑定在一起。** 真实索引中有两个 DSH 来源没有进度；其余来源缺少进度不一定是异常，例如非增量表示或其他 harness 本来就使用完整读取。本轮只诊断第一个确定阻止发布的 DSH 文件，没有继续扩展成全面来源调查。

## 工具中断与正确性边界

第三次候选追加已经完成正确新值、事件数和 SSE 检查，随后实验工具断言“原生组必须存在一次成功的增量 verify”失败。该次实际保留原生证明，但走了完整文件重解析；工具把合法回退误判为实验失败。

已修正工具，将“原生增量追加”与“有原生证明的完整重解析”分别记录，并新增两个自检，覆盖该区别和提前停止规则。**没有改写原始失败结果，也没有把该组标为通过或重跑补齐。** 3/3 完整回退本身已满足停止条件，与这条工具断言无关。

初始 all 视图的九项核心业务字段、records、metadata、period comparison 已与 Q5 精确对拍。7 次追加的正确总量、事件数和通知均有观测；候选整组未完成，不能宣称完成了最终业务对拍、重开或全矩阵正确性验收。第二卡的既有单元/恢复通过结论仍仅适用于其已列场景。

## 资源记录

堆预算保持 gateway 512 MiB、executor 224 MiB / semi-space 4 MiB。首次打开及已执行动作期间的服务树采样峰值：Q5 **256.67 MiB**，候选 **240.28 MiB**；浏览器分别约 **961.05 / 802.73 MiB**，单列。两组动作数及持续时间不同，不能据此判定候选内存更好，或资源验收通过。

同一采样段中的服务逻辑 I/O 增量：Q5 读 **722.43 MiB**、写 **27.21 MiB**；候选读 **5,222.12 MiB**、写 **1,115.31 MiB**。CPU 观测增量分别约 **3.63 / 10.89 秒**。它们包含首次初始化、已执行追加及该段其他动作，不是单次追加成本或物理磁盘 I/O；短生命周期进程的采样也可能不完整。

候选留下约 **1.65 MiB** 的未完成目录清单/索引，ready=0。临时目录可见字节为零不代表匿名 SQLite 临时存储为零。已有资源脚本的 allocatedBytes 字段仍是 GetCompressedFileSize 口径，不当作磁盘簇分配量。
