# 两年混合布局：归档验证复用实施与验收计划

状态：实施及限定验收完成，随本卡本地提交后停止等待反馈。2026-11-08。基线为 `186b30b`；最终结果见[统一对照报告](../archive/2026-11-11-experiments/architecture-20261101/ARCHIVE-VERIFICATION-REUSE-REPORT.md)。最终 85/85 延迟门、精确结果、工作量及内存门通过；首轮一年 11 项失败保留，按既定复核规则对两个受影响布局各补一对，共 10 组计划运行＋4 组复核，另有 1 次诊断。两年 Codex 62.813→43.829 秒，ZCode 109.977→54.987 秒，重开 100.958→64.784 秒，首开 469.688→305.047 秒，候选服务树上界最高 469.96 MiB。原始资源采样中的 PID 复用误归属有单独原始／派生证据，未改计时工具、生产冻结版本或门槛。不自动进入归档压实或来源解析重构。

**目标：消除同一次刷新重复验证归档，以及执行器退出后丢失已完成的语义证明。保住当前和一年数据的收益，给两年刷新、重开设置明确时间门。**

## 2. 只实现这两项改造

### A. 同一刷新共享一轮完整归档验证

沿用现有 server 刷新协调、executor 请求持有、已发布读者及 HistoryProjectionStore。将同一刷新内的准备、投影维护和最终响应接到一个显式操作范围，记录操作 ID、归档集合、输入版本和使用者。

1. 每个包仍按当前规则做锁前和 SQLite 固定读事务内的两次完整 SHA；本卡不删除这两次检查。
2. 只有**同一仍有效的归档读事务／文件身份约束**覆盖后续消费者，才共享该次字节验证。单纯“摘要相同”“刚刚验过”“mtime 未变”不足以跨已释放的锁复用。
3. 主库事实、授权、来源绑定和修订是独立版本依赖；同步前后的结果不能因共用冷文件证明而混为一个版本。冷文件内容可共用，当前绑定／修订仍重新核对。
4. 新的独立刷新、新归档集合、文件替换、锁释放、取消、超时或执行器异常均结束该范围。后续操作重新核对完整字节。
5. 只持有本次活动操作需要的冷归档读者；不把主库 WAL 读事务贯穿同步，也不延长 200 ms 空闲退出、不增加常驻执行器。
6. 单次服务重开中的默认页和首次 all 若是两个独立操作，分别验证字节；不能为了降低计数把所有后续请求都归为同一个无限操作。

**阶段门：** 小夹具证明正常刷新每包一轮两次 SHA，消费者没有脱离有效保护范围；并发写入／更换归档能中止复用。主库同步继续进行，冷读者在结束和故障时释放。

实施核查补充：本机 Windows 的 Node 文件 `ctime` 与创建时间相同，同大小原地写入并恢复 mtime 后不能依赖这些字段证明内容未变。SQLite 读事务也不阻止绕过 SQLite 的原始文件写入。因此在**现有** Windows 助手中用短期 `FILE_SHARE_READ` 句柄锁住数据库、清单，并逐级固定非 reparse 父目录；仅锁末级文件无法防止父目录联接切换，使 SQLite 打开另一个文件。父目录允许共享读写但禁止删除共享，保留不可移走的子对象，利用 NTFS 非空目录不能转换为 reparse point 的约束；不合并大小写不同的目录身份。目录检查不依赖 mtime，必须实测兄弟文件写入／替换、主库 WAL 提交与清理正常。不依赖 USN、不替代 SHA、不安装或常驻新服务。助手不可用／旧版不支持／已有冲突写句柄时保持原有独立操作校验；助手死亡或租约丢失必须拒绝复用结果。候选构建记录及性能资源包括此助手变化，旧版助手保持冻结。

### B. 持久保存与归档内容绑定的语义校验完成记录

目前同一进程已经在完整 SHA 相同后复用表证据；将这一有限能力扩展到执行器退出和服务重开，复用现有派生状态存储，不建立另一套事实库。

完成记录至少绑定：实际归档 SHA 和长度、完整 manifest 摘要、schema/备份/候选格式、校验算法版本。它只能由完整成功的校验流程产生，在所有表证据、范围、事件指纹和来源指纹验证成功后原子发布；未完成记录不可读。

| 校验内容 | 每次仍做什么 | 可以复用什么 |
| --- | --- | --- |
| 归档当前字节、清单和读取期间身份 | 完整 SHA、清单合法性、固定读事务及身份约束 | 仅 A 的同一有效操作内可共用字节检查 |
| 由固定文件内容决定的语义 | 比较完整内容及算法身份；不匹配则完整校验 | 成功的 quick_check、外键、表计数／指纹、候选范围及来源指纹证明 |
| 当前主库授权、绑定和修订 | 用当前快照／版本验证；不能直接复用旧主库结论 | 有完整依赖证据时才复用现有局部派生结果 |
| 价格、证据、时区及业务结果 | 沿用既有依赖失效和精确累加顺序 | 原有业务投影，不由校验完成记录代替 |

边界：

- 先检查当前完整字节，后复用语义结果；完成记录不证明“文件没有变”。
- 仅在现有可复用条件成立的 DELETE journal 归档使用；WAL／旁路写入状态不能用主文件 SHA 证明所有行，保持完整回退。
- 持久完成记录还要求新版完整路径租约；没有租约时仅保留旧有进程内能力。可信路径与旧进程缓存使用不同版本键，旧内存命中不能直接升级为持久证明；旧助手及旧记录不能进入新版复用。
- 完成记录只来自本应用校验过程，不导入归档提供的 `verified:true`，不允许调用者自行声明校验成功。损坏、缺失、半写、旧格式或身份不一致均完整回退。
- 不把全部来源成员放进内存 JSON；来源关系继续使用磁盘索引。普通热事实更新不得清空与未变冷包绑定的证明。
- 首次升级或完成记录缺失，需要一次完整语义校验。成本计入首开，不能预热后声称升级免费。
- 必须先通过“已验包被修改”“新 manifest 搭配旧记录”“缓存恢复自旧版本”“校验中杀进程”等反例，才接入正式读路径。

**阶段门：** 已完成且字节未变的包，在全新 executor 和全新服务中完整 SHA 仍执行，重复的全表语义扫描为 0；修改任一实际输入能触发重新校验或原有错误。

## 3. 定位范围和实现范围

先从既有日志还原 Codex、ZCode、重开三条时间线。补 **1 次两年混合定向诊断**，只包含这三个操作，区分：来源发现／解析、锁前 SHA、锁内 SHA、表证据、候选范围／来源核验、当前授权／修订、业务查询、通知／绘制、执行器出生与退出。诊断使用现有数据，不再完整导入或生成归档。

这次诊断用来确定两个重复调用各自的入口、读锁寿命和新执行器原因。若两条路径无法在现有一致性要求下安全共享，先明确该障碍，不直接删检查或扩大改造范围。

预期触及的生产范围：

| 模块 | 职责 |
| --- | --- |
| `src/history-backup.js` | 内容绑定的基础校验记录与受控读者生命周期 |
| `src/history-archive.js` | 候选语义证明复用，继续执行当前绑定／修订约束 |
| `src/usage-history-projection-store.js` | 复用现有派生存储，原子发布少量完成记录及恢复 |
| `src/usage-store.js` | 让准备、已发布读取与更新共享合法的本次操作上下文 |
| `src/usage-executor.js`、`src/server.js` | 只有重复入口确实跨请求时调整协调／释放，保留版本与新值完成语义 |
| `src/usage-source-native.js`、现有 Windows 助手 | 操作期间的文件只读锁及失效检查；无 journal 要求，旧助手保守回退 |

现有备份／归档 CLI、导入、恢复、冻结快照、单归档快速路径均为受影响调用者，纳入回归；纯备份校验没有可信完成记录时仍完整验证。测试优先扩展现有 hash、candidate proof、projection recovery、executor 与通知用例。

本卡不改来源解析器、费用算法、归档格式／ID，不压实现有包，不使用原生 journal 来替代 SHA，不增加依赖或堆预算。

## 6. 收口与下一张卡的边界

交付一份集中报告，逐行列“V14／本轮基线／候选／标准／是否达标”，同时列首开成本、真实新值绘制、核验字节／扫描行数、服务树／浏览器、磁盘和恢复结果。实现与验收完成后本地提交，停下来等反馈。

归档压实留待单独决定：现有 segment ID 绑定数据库 SHA；VACUUM 会改变字节身份，需要新候选、语义对拍、授权／修订映射的原子迁移及旧包回滚保护，不能原地覆盖。下一卡的收益必须在这些未压实包上成立。

仍然存在的边界：SHA 回退下每次独立操作需要读取完整归档字节，本卡最多减少重复次数；大来源完整解析、早期修订的精确费用回放也仍可能昂贵。45／90 秒是这张有限范围卡的目标，不代表最终流畅度目标已经实现。
