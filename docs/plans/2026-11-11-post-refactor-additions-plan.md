# 重构后追加需求与并行实施计划

日期：2026-11-11。状态：**计划已整理，待实施；当前不启动实施。** 用户最新要求为“先做成一个计划吧。然后先不实施”。本文保存需求、优先级、人员分工与验收标准；后续收到开始实施的指令再派工。

本批以用户最后一份需求清单为范围，分成七个工作包，建议采用 **1 个主智能体 + 3 个执行智能体**。当前重构和性能收尾沿用[既有记录](2026-11-11-windows-closeout-short-acceptance.md)，本批不恢复性能优化或 TPS 功能。Linux/macOS 可用性检查未列入最后一份清单，不纳入本计划。

## 1. 需求与优先级

P1 优先确定数据行为和发行边界；P2 处理界面可用性与交互；P3 处理独立视觉细节及离线维护。优先级表示业务影响，独立任务可以并行。

| 编号 | 优先级 | 类型 | 目标与完成标准 |
|---|---|---|---|
| R1 | P1 | 模型与计价 | `opencode-go/gemini-4-argon-contributor` 统一登记为 `gemini-4-argon-contributor`；`hy4free` 按免费模型处理。模型汇总、时间分布、计价覆盖和已有历史结果一致。 |
| R2 | P1 | 发行结构 | 同一源码、同一版本号生成普通版和 waifu 版。普通版没有皮肤入口，跳过皮肤加载及旧偏好恢复；waifu 版保留现有皮肤功能。 |
| R3 | P2 | 布局 | 时间分布右侧详情随内容增长，最大高度为默认的两倍；超过上限后在框体内部滚动。以当前 384px 默认高度规划 768px 上限。 |
| R4 | P2 | 滚动条 | 时间详情、按模型、按仓库、数据来源弹窗和更新计价标准弹窗内的滚动区域，复用旧 TPS 左侧框体的滚动条外观；包括弹窗内嵌列表与计价子弹窗。 |
| R5 | P2 | 主题交互 | 深浅色切换在 1 秒内完成亮度和颜色渐变；转换期间忽略重复切换，转换完成后恢复。图表、皮肤和弹窗同步过渡。 |
| R6 | P3 | 控件外观 | 5h/7d 开关从中间斜着分成两半，明确区分选中状态，沿用现有额度窗口选择与禁用行为。 |
| R7 | P3 | TPS 离线维护 | 右侧数据框体单位由 `tok/s` 改为 `token/s`；左侧表头改为“平均速度”，同步英文文案及对应测试。只修改离线维护代码，不接入当前产品。 |

实现遵守现有视觉结构。机制、估算口径和边界解释默认放在用户主动展开的详情，不增加常驻提示、警告或额外框体。

## 2. 已核查的实现边界

### 模型与计价

共享入口是 [public/pricing-models.js](../../public/pricing-models.js) 和 [src/pricing.js](../../src/pricing.js)。现有 provider 前缀归一化依赖价目表能否解析目标模型，因此 R1 的指定 Gemini 映射需要在价目表缺项时也生效，不能扩大成对所有未知前缀的无条件删除。

本计划将 `hy4free` 按精确模型 ID 处理，其明确免费规则优先于残留付费条目。现有最低费率逻辑会过滤全零费率，仅添加零价目录项可能仍得到“未计价”，因此要复用明确免费政策的计价路径，并排除残留价格对其他未知模型最低估算的影响。Gemini 本项只统一身份，未指定新费率。

原始事件与归档保留原始模型名。现有读侧共享分组和计价版本失效机制可用于重新生成派生结果，预计无需修改 OpenCode reader、升级数据库 schema 或重写归档。实施时用旧缓存重开及冷热历史一致性测试验证这一边界；冻结和导入实例继续遵守各自既有目录语义。

### 双版本发行

当前没有正式的双版本打包入口。复用现有运行文件与助手配套规则，参见[正式交付与升级](../15-delivery-upgrade.md)，新增小型打包脚本，从同一源码生成两个独立暂存目录。

建议产物名为 `agent-usage-vX.Y.Z.zip` 和 `agent-usage-vX.Y.Z-waifu.zip`，同属一个版本。版本号在实施集成时统一确定。两包共享统计、计价、服务与主界面代码，普通包裁剪皮肤入口、弹窗、角色层及专属模块和资源。无需新增生产依赖或维护两套长期源码。

前端先固定发行标识与可裁剪区块，皮肤模块按发行版本加载。普通版启动跳过皮肤偏好恢复，并处理按钮绑定、Tab/Escape 等代码对皮肤节点必然存在的假设。保留用户旧偏好值，使切回 waifu 版后可以继续恢复。

### 布局、滚动条与主题

[public/styles.css](../../public/styles.css) 当前以 `--main-panel-stable-height: 384px` 定义主区域默认高度，桌面布局已有固定高度约束。R3 要协调这个约束与内容增长、768px 上限，保持左侧图表和右侧详情对齐；不能只在某个子元素追加 `max-height` 后忽略外层布局。

旧 TPS 列表采用有限高度视口内的原生滚动，没有页码按钮。R3 按这一交互实现“滚动分页显示”。旧滚动条为 8px 宽、圆角轨道和滑块，颜色随主题变化，可提取少量共享 CSS 复用。变窄后需检查模型/仓库表头、正文和底部合计的列对齐，避免嵌套滚动条。

[public/app.js](../../public/app.js) 的主题切换会更新皮肤并重绘 Canvas。R5 需要选择能覆盖这些视觉变化的渐变实现，验证转换中间帧和 1 秒结束点；按钮锁定与实际转换生命周期一致，不把连续点击排队到转换之后。保持现有可访问性支持，不引入额外动画框架。

## 3. 智能体分工与文件归属

峰值为 1 主 + 3 执行。三个执行者沿用当前模型，不另外指定模型覆盖；按文件边界派工，避免同一文件同时写入。

| 角色 | 负责工作 | 独占写入范围 |
|---|---|---|
| A：模型与计价 | R1，模型规则、免费规则、计价版本、旧缓存与历史一致性 | `public/pricing-models.js`、`src/pricing.js`；对应计价、覆盖和历史失效测试及必要数据夹具。 |
| B：前端与交互 | R3–R6，以及 R2 的皮肤加载和页面接线 | `public/app.js`、`public/app-state.js`、`public/index.html`、`public/styles.css`、`public/i18n.js`、必要皮肤模块/样式及 bootstrap 生成源；相关 UI 测试与夹具。`public/pricing-models.js` 属于 A。 |
| C：打包与发行 | R2 的打包、包内容检查、解压运行和发行文档 | 新打包脚本及测试、`package.json`、必要的 `package-lock.json`、CI、两份 README 与交付文档。只修改打包暂存副本，不并写 B 的前端源文件。 |
| 主智能体 | 共同约定、R7、逐卡审查与最终集成 | 本计划与任务入口、TPS 独立维护补丁及验收记录；协调其余文件归属，不并写执行者正在修改的文件。 |

归属清单不是必改清单。实际只修改任务需要的文件；新增共享接点先由主智能体指定唯一写入者。沿用当前合适的工作区并保留已有改动，不按功能批量复制整个项目。

## 5. 验收标准

| 范围 | 必须验证的行为 |
|---|---|
| 模型身份 | Gemini 带前缀与裸名在目录缺项、有项和残留旧键时均合并；汇总与时间分布使用同一身份；其他未知模型规则保留。 |
| 免费计价 | hy4free 缺 token 明细、Fast、未知上下文和存在旧非零价格时仍为零费用，不进入缺价/最低估算统计；其他模型的最低估算不被其残留价格影响。 |
| 缓存与历史 | 先用旧规则预热并持久化，再用新版本重开；热、冷及混合历史结果与全新计算一致，原始模型键、归档哈希、token 总量保留。 |
| 详情高度 | 空、少量、刚好达到上限及大量条目；渠道/模型/花销三种模式；默认布局正常，最多增长到两倍，超过后内容可滚动访问，图表和详情保持对齐。 |
| 滚动条 | 覆盖所有指定框体及弹窗内实际滚动节点；深浅色、中英文、窄窗口检查；表头/合计列对齐，滚轮、拖动与键盘滚动正常。 |
| 5h/7d | 中央斜分和选中状态可辨；现有切换、无 Codex 来源禁用、额度窗口缺席行为正常。 |
| 主题渐变 | 起点、中间帧、结束帧体现连续变化，约 1 秒结束；转换期间连点仅触发一次，结束后能再次切换；Canvas、角色图层、表格及打开的弹窗无突然换色或布局跳动。 |
| 普通版 | 已有 waifu 偏好时，首屏、刷新和主题切换均无皮肤入口、角色或皮肤配色，无皮肤资源请求；Tab/Escape 及正常看板功能无异常。 |
| waifu 版 | 皮肤入口、选择器、旧偏好恢复和深浅色角色资源正常，继续通过相关皮肤检查。 |
| 两包交付 | 从同一集成源码生成，共同核心文件一致；实际解压后分别启动，同一夹具核心统计一致；助手及回执按交付要求配套。 |
| TPS 离线维护 | 左表头“平均速度”/“Average Speed”，右侧单位 `token/s`；空值与有值、中英文输出正确；封存 UI 测试更新后通过，正式两包仍无 TPS。 |

先跑每卡受影响的局部验证，集成后执行一次适用的完整测试与 `typecheck`、`lint`、`format:check`，并完成两包验收。仅在新修改、失败或未解决问题需要时扩大或重复测试；不重新开展性能负载实验。
