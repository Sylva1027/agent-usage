## 2. 已核查的实现边界

### 模型与计价

共享入口是 [public/pricing-models.js](../../public/pricing-models.js) 和 [src/pricing.js](../../src/pricing.js)。现有 provider 前缀归一化依赖价目表能否解析目标模型，因此 R1 的指定 Gemini 映射需要在价目表缺项时也生效，不能扩大成对所有未知前缀的无条件删除。

本计划将 `hy4free` 按精确模型 ID 处理，其明确免费规则优先于残留付费条目。现有最低费率逻辑会过滤全零费率，仅添加零价目录项可能仍得到“未计价”，因此要复用明确免费政策的计价路径，并排除残留价格对其他未知模型最低估算的影响。Gemini 本项只统一身份，未指定新费率。

原始事件与归档保留原始模型名。现有读侧共享分组和计价版本失效机制可用于重新生成派生结果，预计无需修改 OpenCode reader、升级数据库 schema 或重写归档。实施时用旧缓存重开及冷热历史一致性测试验证这一边界；冻结和导入实例继续遵守各自既有目录语义。

精简已删除 `API_TOKEN_PRICES`、`isPeakPricingTimeExact` 等无消费者入口；R1 继续使用现行 `canonicalModelName`、`resolvePricingModel`、`estimateEventCostForModel` 和 `API_PRICING_VERSION`。`knownToken` 已合并到 `public/usage-fields.js`，本需求不涉及其解析规则。

缓存按职责验证：费用 memo、持久摘要沿用计价版本失效；周期事实缓存仍只因模型映射/事实等相关输入变化而重聚合。现有 [history-period-price-invalidation 测试](../../test/history-period-price-invalidation.test.js)要求仅费率或汇率变化复用周期事实，不能为本批统一清缓存或将所有缓存改成价目版本键。代码更新后的连接内状态通过新进程重开验证。

旧统计参考现位于 [test-support/summary-reference.js](../../test-support/summary-reference.js)，它仅供对照测试使用。A 复用现行内存/SQLite/HTTP 路径及字面量断言，保留独立对照；由于参考也调用共享模型规则，必须直接断言 Gemini 的规范名、分组数和 hy4free 的零费用，不能只让两条共用同一函数的路径彼此相等。B 直接验证 `loadUsage → state.summary → render`，不把参考计算重新引入浏览器。

`test/pricing-models.test.js` 当前明确断言指定 Gemini 在缺目录项时保留前缀，实施时只更新这一预期并保留其他未知模型反例。`test-support/pricing-official-fixture.mjs` 还保留该原始 ID；规范身份不等于已有价格，原始输入与缺价场景可以继续保留。新增夹具优先复用已有 `codex-log-fixture.mjs`、`pricing-official-fixture.mjs` 和当前报告构造器。

### 布局、滚动条与主题

[public/styles.css](../../public/styles.css) 当前以 `--main-panel-stable-height: 384px` 定义主区域默认高度，桌面布局已有固定高度约束。R3 要协调这个约束与内容增长、768px 上限，保持左侧图表和右侧详情对齐；不能只在某个子元素追加 `max-height` 后忽略外层布局。

旧 TPS 列表采用有限高度视口内的原生滚动，没有页码按钮。R3 按这一交互实现“滚动分页显示”。旧滚动条为 8px 宽、圆角轨道和滑块，颜色随主题变化，可提取少量共享 CSS 复用。变窄后需检查模型/仓库表头、正文和底部合计的列对齐，避免嵌套滚动条。

[public/app.js](../../public/app.js) 的主题切换会更新皮肤并重绘 Canvas。R5 需要选择能覆盖这些视觉变化的渐变实现，验证转换中间帧和 1 秒结束点；按钮锁定与实际转换生命周期一致，不把连续点击排队到转换之后。保持现有可访问性支持，不引入额外动画框架。

R5 的现行调用方必须一起处理：`public/skin-palette-studio.js` 的 `syncTheme()` 目前每次点击后等待 80ms，最多重试三次；`scripts/skin-palette/capture.mjs` 的 `applyThemeViaToggle()` 目前只读 `data-theme`，最多点击两次；`test/skin-palette-quality.test.js` 也存在只等属性变化就开始采样的场景。改为等待目标主题和实际过渡完成后再注入配色、截图或继续操作，沿用现有等待入口与超时，不靠反复点击或统一加固定长延时。

CSS 修改按精简后的规则位置落地，不在文件尾追加一整套重复覆盖。保留 `[hidden]`、窄屏媒体覆盖及现有 `prefers-reduced-motion` 行为；按钮已有的零过渡和无按压位移断言继续通过。普通模式新增的 1 秒主题渐变单独验收。图表尺寸继续由现有布局和 ResizeObserver 驱动，不为高度上限新增持续轮询。

现有 `test/ui-geometry.test.js` 断言默认面板为 384px、顶部包含皮肤入口，需分别扩展“默认/超长内容”与“普通/waifu”场景；默认高度断言保留，普通版单独断言没有皮肤按钮及其占位。焦点测量复用现行 adjacent 算法，不恢复已删旧算法；涉及源码变更的新证据单独生成，旧皮肤评审哈希不改写。

长期规则以[皮肤与配色维护](../13-skins.md)和[桌面验收基准](../03-development.md#界面设计与验收基准)为准：保留十款皮肤及简洁模式，优先桌面与并排场景。`skin-bootstrap.js`、`skin-assets.json` 沿用现有生成入口；只在相关输入确实改变时重生成，旧色源和历史哈希不手工改写。B1 可直接从保留 ZIP 读取旧 `styles.css`，不依赖 M1 完成文案补丁或恢复整棵解压目录。
