# 四来源：保留相同前缀的增量发布

基线 `db5e951`。本卡覆盖 Claude Code、WorkBuddy、ZCode、OpenCode 共用的事实提交入口，完成本地提交后停止等待反馈。

**已完成实施与限定验证。** [统一结果、标准与边界](../../experiments/architecture-20261101/SOURCE-PREFIX-PUBLICATION-REPORT.md)：ZCode 第二追加 6.231 → 3.362 秒（快 46.1%，超过 20% 目标），WorkBuddy／OpenCode 快 24.7%／30.7%；Claude 因共享会话子文件替换持续回退，无收益。固定 8 组、16 追加、8 修订、8 重开及 32 对响应／211,267 个数值对拍完成，所有逐项防退化线通过。服务树生命周期补充估计最高 363.34 MiB，堆不增加；最终 67 项相关回归通过。全套两项旧失败已在冻结基线复现，三项随机端口失败隔离通过。原始输入仍完整核对，ZCode／OpenCode 仍观察到每次两次读取，不宣称真正增量续读或长期容量通过。本地提交后停止等待反馈。

## 做什么

完整解析来源后，逐条比较已有的标准化事实；在能证明与原完整替换结果完全相同时，保留相同的旧记录，只插入新增部分，减少删除重插和派生结果重算。既有适配器、来源检查、计价和通知继续使用。

先限制为**当前索引末尾的一段连续来源记录**。验证所有持久字段、事件顺序和 ID 分配，不以 token 总量相同代替记录相同。这个限制用于保住按插入顺序累计金额的现有精度：非末尾来源直接走原完整替换；旧行修订、删减、重排在核对失败后回滚，再完整替换。跨来源交错更新可能因此回退，必须如实统计。

本卡不是原始输入的增量续读：SQLite 仍读取完整用量快照，JSONL 仍完整解析去重；不能用 MAX(id)、文件大小或通知替代旧记录检查。无新增永久表、schema 迁移、依赖或堆额度。冷历史／修订覆盖继续走原路径。

## 固定验证

| 项目 | 范围和标准 |
| --- | --- |
| 语义与金额 | 四来源追加、无用量变化、旧记录更新／删除、迟到重排、交错来源与 ID 缺口，和禁用新路径的完整替换严格对拍，包含行 ID、金额与已知性 |
| 事务与恢复 | 新增事实失败、警告回调失败、重开和外部索引写入，不出现半份提交；原有历史保留测试继续通过 |
| 写入增长 | 1,000 / 10,000 条历史的定向夹具：符合条件的一条追加只引发 1 次事件插入，0 次事件更新／删除；读取仍按完整来源记录数报告 |
| 原页面 | 复用上一卡原始记录与共同索引，4 来源 × 旧／新共 8 组；16 次追加、8 次旧修订、8 次重开，正常发现／解析／提交／通知／绘制全包含 |
| 页面效果 | ZCode 第二次普通追加目标较旧版至少快 20%；其余追加、修订、切换和重开沿用“慢 >10% 且增加 >100 ms”回退门；未达标明确报告 |
| 资源 | 默认 gateway 512 / executor 224 MiB + semi-space 4 MiB 不变；服务树沿用 512 MiB 线，浏览器和 I/O 另报，不将采样下界说成完整 I/O |
| 回归与结束 | 完成相关回归、一次完整 npm test、typecheck/lint，保留旧失败证据；本地提交后停止，不自动扩大到持久候选／四来源原始续读 |
