## 固定执行范围

1. 主代理核查 `reuseSourcePrefix` 各回退条件、原始解析顺序、首个查询／同步事务交叠，最多两组低扰动原页面定位，不先扩展大矩阵。必须明确命中的条件，并以确定性测试复现；若回退是保证事实顺序／业务正确所必需，应保留并说明，不强行删除保护。
2. 一个 pinned worker 独立负责暖执行器／重开场景的回归夹具与对拍；主代理负责共享生产代码、集成和计时工具。文件单写、不生成后代。用户已确认恢复 DeepSeek；本次及后续 pinned worker 显式指定 `model:"group/deepseek"`、`reasoning_effort:"max"`、`fork_context:false`。Raman 创建 ID 为 `01a1b091-5165-77d0-8384-22a6b0084230`；创建回执证明请求参数和启动结果，不证明路由后的物理模型。
3. 有可修复根因时作最小改造，验证追加、修订、删除、迟到、失败回滚及精确金额／事件 ID。保持原始来源检查、真实新值完成语义、默认堆和 200 ms 空闲退出，不改存储架构、价格算法、原生助手或 UI。
4. 代码稳定后只运行一次既有四来源原页面对照：4 来源 × 旧／新共 8 组，16 追加、8 修订、8 重开及 today／week／all 切换。另记录首次服务进程创建至默认页和首次 all 完成的总时间，用同一防退化门检查是否转移刷新耗时。逐值业务对拍、同步与事实写入计数、服务树／浏览器分列。没有可安全修复的根因则停止在诊断结论，不为追分数修改业务契约或空跑候选矩阵。

## 验收标准

| 项目 | 标准 |
| --- | --- |
| 根因 | 明确回退分支与可复现触发条件，不能只凭计时推测 |
| 事实复用 | 适用的普通末尾追加保留旧事实 ID／顺序，只插入新增事件；必须回退的修订继续回退 |
| 正确性 | 与原算法事件及业务逐值一致，金额无容差，删除来源历史保留 |
| 防退化 | 首次服务打开、首／次追加、修订、重开、切换均不同时慢 >10% 且多 >100 ms；每格一次，不声称 p95 |
| 资源 | 服务树 ≤512 MiB；gateway 512／executor 224 MiB + semi-space 4 MiB 不变，浏览器另计 |
| 验证与交付 | 有关回归、必要完整检查、typecheck／lint；保留旧失败；私有输入和证据只留 output；本地提交后汇报停止 |

不部署、推送、切换在用来源／数据库／服务或安装助手；完整重建、多年容量、真正来源增量续读、冷历史及跨平台不在本卡范围。基线生产文件已冻结在 `output/zcode-first-prefix-20261106/baseline/`。
