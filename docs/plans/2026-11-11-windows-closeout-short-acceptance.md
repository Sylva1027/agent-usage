## 固定执行量与顺序

### 1. 校正资源统计：离线回算＋6项短测试＋1次30秒校准

已有代码及当前候选原始样本显示：首帧CPU／I/O累计值存在，但没有前一帧，所以增量是null；最终零服务进程样本的增量也是null。`pollResources`目前一律把它们计入永久缺采。这证明汇总存在误判，不证明其他位置一定没有漏采。

按PID和精确创建时间核对进程与累计计数，区分首帧、不适用和真实缺失。每个统计窗口标出开始／结束及覆盖范围，禁止跨进程复用计数；不能把Node的I/O操作次数转换成字节数。首先回算已有15份资源记录，保留原报告和原判定，输出单独更正记录。

只补6项工具短测试：首帧累计值、正常增量、退出后的零进程树、部分进程缺计数、短进程退出缺尾值、PID复用。预期可解释的样本不得误报；真正未知仍必须失败或未完成，不能补0。再用一次30秒的小进程夹具核对实际Windows采样、退出及观察者开销。

若发现真实计数缺口，限于现有采样器／汇总器的一处最小修正和对应校准；不能用旧记录推导不存在的尾值。关键覆盖仍无法确认则停在此步，报告具体缺口，不开启大组，也不另建庞大跟踪系统。

### 2. 仅一个两年原页面组：四轮短循环

使用已保留的两年混合布局、原页面、真实来源检查、默认堆。网关四轮间始终不重启；不清缓存、不替换数据库、不重置来源。执行器维持原200ms空闲退出，正常退出／重启属于被测行为。

| 每轮步骤 | 固定工作量 | 核对 |
|---|---|---|
| 三标签准备 | 原主标签＋两个附加标签 | 不计入写入90秒，准备耗时单列 |
| 连续写入 | 90秒、5秒一条、18条Codex／DSH交替 | 每轮独立记录完成版本，轮次／输入ID唯一 |
| 自动排空 | 首个完整新值≤60秒；所有标签安全收尾≤300秒 | 不增加提示、手工刷新或重启帮助排空；两个时间分开记录 |
| 精确核对 | 每轮1次独立数量、金额、会话核对 | 三标签结束后关闭附加标签，执行器正常退休后才进入oracle |
| 空闲观察 | 每轮120秒 | 取无工作满60秒后的同长度窗口比较内存、句柄、WAL、临时文件 |

总计 **1组、4轮、72条追加、1次最终服务重开**。独立oracle共6次：起点1次、每轮末1次、最终重开后1次。不添加其他来源、旧历史修订、价格变化、杀进程或升级场景；这些已有针对性证据，本次缺的是重复使用后的释放。

四轮负载和空闲固定时间合计14分钟，另加三标签准备、排空、oracle、重开及恢复，整卡预计约30–45分钟。等待只用于真实处理和资源释放，不延长为两小时／八小时浸泡。短循环验证反复使用时的收敛，不宣称证明所有按小时计时的慢泄漏。

若发现必须修改生产代码的新可靠性缺陷，先报告具体阻塞和最小修复范围；本卡不自行扩成下一轮重构或性能调优。
