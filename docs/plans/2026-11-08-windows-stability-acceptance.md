## 6. 判定标准

以下为本卡拟冻结标准，不是已经取得的成绩。原有性能目标不因长测而自动放宽。

| 项目 | 标准 | 失败处理 |
| --- | --- | --- |
| 数据与版本 | 丢失、重复、混版、错误金额或将旧值标为刷新完成均为0 | 停止，保存输入与可恢复状态 |
| 升级与复用 | 已有投影升级冷复制0、完整重建0；普通追加未变冷复制0，ZCode投影净增行为保留 | 停止进入大组 |
| 服务树内存 | 活动与必要维护峰值≤512MiB；空闲连续60秒窗口≤256MiB；浏览器另列 | 排除可证明的PID误归属后仍超限则停止 |
| 常驻增长 | 可比较的空闲窗口，末小时中位值≤首小时中位值＋32MiB；句柄和临时文件无持续累积 | 记录对象／句柄／文件变化，作为稳定性失败 |
| 普通处理与追赶 | 单条普通输入可见等待不超过120秒；异常／重算后未完成队列须在300秒内排空，停止输入后同样≤300秒 | 不用旧值结束等待；持续超限则停止 |
| 当前／一年收益 | 短保护检查保持原R判定，记录任何新未达项；长测可比较普通窗口末段p50相对首段也用R | 不用跨来源平均掩盖退化；普通速度持续恶化不得称稳定性通过 |
| 两年性能 | 普通刷新35／45／42秒、重开45秒和旧修订78秒原门继续列出 | 每次结果保留；已有80.520秒是欠项，新的孤立越线可继续观察分布，但不算通过 |
| WAL、候选与临时文件 | 停止输入并完成正常checkpoint后回到可解释的空闲基线；正常关服后无孤儿候选、遗留的大WAL或持续累积的临时快照 | 保留文件来源与恢复证据，不能靠人工删文件制造通过 |
| 资源成本 | CPU核秒、逻辑读写、最长写锁、磁盘峰值及排空时间完整计入 | 缺失关键证据标为未验收；不通过增大堆或降低验证过门 |

120／300秒是稳定性与追赶的外层期限，不替代普通刷新35／45／42秒标准。p50／p95／max逐来源、逐场景报告；普通每来源40次，另有并发和持续写入样本，属于本卡观测分位数，不能称为原总计划“每类100次、多个服务实例”的完整性能验收。

已知旧修订欠项或单次速度异常本身不启动自动优化循环；新增数据错误、OOM、无法恢复、持续积压或持续资源增长是停止硬门。1小时阶段存在这些问题，不进入8小时。

## 7. 实现与证据边界

复用`c1-run`的启动／关闭／浏览器、六来源mutation、原资源采样、已完成的故障工具和业务核对设施。只增加长期调度、逐批期望账本、跨版本关联和收尾分析；保持每个来源真实格式，不新建一套模拟后端。测试辅助注入和故障点仅存在于实验工具。

逐条记录原始输入落地、源边界、已提交版本及首个包含它的正确页面；一次合并发布可以确认多条输入，事实不能省略。以已知新增／修订账本核对每轮变化，开始、依赖变化、恢复和最终时点再做有界完整核对；费用按逐条顺序、成员去重和原业务契约核对，不用token总和乘单价替代。

复用保留的权威事实、来源和13份包，不重新生成多年原始数据。新主库身份需要的首次派生准备允许执行一次，单列其耗时和磁盘；不能拷贝一份身份不匹配的现成投影来伪装快速启动。此前测量的工作副本和结果不覆盖，测试只操作隔离副本，不能使用在用用户状态。

延用250ms资源采样和进程退出高水位，按精确PID＋创建时间归属；采样开销另报。用户服务、系统journal、源检查和堆上限均不改变。测试副本与瞬时WAL沿用至少64GiB空闲预检，实际新增空间与峰值公开，不当作产品新增硬件要求。

不循环拍图：仅开始、结束及失败保留必要截图。测试产物统一登记在新的独立输出目录；完成核对后清理可再生工作副本／临时快照，保留输入指针、汇总、指标流和失败证据，避免再次积累大量旧截图。
