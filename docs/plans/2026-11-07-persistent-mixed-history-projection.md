## 这张卡解决什么

把“每次把冷热历史重新拼成临时数据库，再重新计算业务结果”，改成“首次建立可恢复的磁盘投影，之后维护变化来源与受影响业务结果”。投影可跨请求、执行器退出和服务重开复用；原始事实、归档包仍是权威来源。

| 已知问题 | C1 证据 | 本卡处理 |
| --- | --- | --- |
| 重复拼全历史 | 一年最终活动运行 35 次载体构建，每份约 2,904 MiB | 持久保存载体；正常追加不搬运未变冷事实 |
| 重复算业务结果 | 多归档路径不能直接复用全热 all 汇总；其他持久结果也随临时库消失 | 接入 all、元数据、周期和历史纪录的持久结果；范围查询只补选中范围与必要边界 |
| 修订阶段内存超额 | 534.04 MiB 出现在 ZCode 旧值修订后的同步收尾，开始构建载体时 | 修订前缀分批溢写；控制构建并发与中间状态；独立复测峰值 |
| 重开可能重复初始化 | 一年混合重开至 all 210.692 s | 核验版本后直接复用已完成投影；初始化成本单列且纳入首开总时间 |

峰值时执行器约 359.95 MiB、网关 144.31 MiB，另有助手等约 29.77 MiB。现有日志能确定阶段，不能进一步证明 JS 对象／SQLite／原生内存各占多少。第一里程碑最多补一次这个修订阶段的定向内存诊断，不再重跑六来源整组定位。

## 里程碑一：可复用、可恢复、版本正确

1. 扩展现有 `UsageHistoryQuery` 为一份持久派生 SQLite 文件，位于应用状态目录，备份／归档不把它当权威事实。首次只构建一次；可删除重建，不替换用户主库或保留历史。构建从现有主库和归档取事实，不以重扫原始日志替代已保留的缺失来源历史；迁移前后对拍权威事实计数与摘要。
2. 主库在事实事务内提交小型来源变更批次及唯一版本标识。记录事实修订号、相关辅助输入修订号、来源／分片、操作类型和受影响范围；不另存整份事件日志。只在存在冷历史并启用投影时维护，避免全热路径和完整导入增加逐事件负担。
3. 每份已完成投影记录消费位置、权威归档列表／摘要、修订状态、来源身份、格式和算法版本。事实与待处理标记同事务；派生库允许落后，读取必须匹配发布版本。主库和派生库不假设跨库原子提交。
4. 现有事实修订触发器继续有效；补齐辅助输入的持久变更检测。外部或旧版写入没有完整批次、数据库被替换、触发器／格式不匹配时，拒绝增量证书，走一次可恢复重建。不能只凭 MAX(id)、mtime 或连接内 data_version 跨重开复用。
5. 持久文件使用正常的事务与落盘策略，不能继承临时库的 `journal_mode=OFF`／`synchronous=OFF`。首次或无法证实的状态建立候选文件，完成后发布；缓存损坏可以丢弃，权威事实不受影响。

**阶段门：** 小夹具结果与旧路径逐值一致；首次建成后，无变化的请求、执行器重启和服务重开，完整载体重建次数均为零。此时不宣称普通刷新已优化完成。

## 里程碑二：增量事实、增量业务和工作集约束

### 变化怎样进入投影

- 已证明的安全尾部追加，只取新增事实及辅助变化。
- 来源必须完整重解析时，在磁盘上对该来源做精确多重集差分；相同 payload 的重复次数保留。主库重写数千行不应导致投影重写全部其他来源。未知变化的保守回退仍保留。
- 冷修订按分片／来源的精确移除与增加更新，来源缺失保留历史，归档授权转移校验热冷冲突。分片完全未变时不重新导入其事件。
- 变更批次重放必须幂等；投影落后时可合并连续批次，但不能漏掉中间删除、回退或辅助输入变化。

### 保持排序和费用语义

当前多归档通路先按时间、再按规范化 payload 的 JS UTF-16 顺序重排并生成行号。持久表后插入的物理 id 不能代表这个顺序，否则迟到事件、金额累加和同值纪录会改变。

投影保留稳定来源身份和显式逻辑顺序。单一时间戳内的变更复用现有 `UsageSourceRows` 有界排序；只整理该时间戳组，不给整份历史重新编号，该组变化从组前检查点恢复。排序需要的原始字段和日历派生字段分开处理。所有依赖顺序的混合消费者——费用、timeline、历史纪录、成员首次出现和仓库会话顺序——使用同一逻辑顺序。

复用 Q1 的累计器、精确成员关系和检查点机制，为混合路径适配逻辑游标，不直接取消现有保护条件。普通末尾追加接续累计器；迟到／修订从变化之前的检查点回放必要后缀。早期修订或真实重新定价可能需要较长回放，如实计入，不能把每日金额重新相加或用总额相减替代。

全热的既有插入顺序、单归档未修订 all 的旧 SQL 顺序分别保留。无归档时不创建／打开新投影、不安装冷历史变更记录、不增加来源扫描。单归档 all 原快速通路继续可用，不强制换成多归档排序或先等待新缓存初始化。不同布局之间不能借浮点容差掩盖语义变化。

### 哪些业务结果必须复用

| 结果 | 普通追加时的工作 | 必须保留的边界 |
| --- | --- | --- |
| all 摘要／费用／时间线 | 新逻辑位置及受影响后缀 | 请求级计价、未知值、币种、非线性规则和原累加次序 |
| 元数据 | 受影响来源、模型、精确会话成员 | 跨来源去重、未来记录的 asOf、来源告警 |
| 周期／日汇总 | 明确脏日及对应 UTC／local 分区 | 去掉“最早到最晚脏日”的无关包络；跨日会话不能直接求和 |
| 历史纪录 | 受影响日／周／月贡献与全局候选 | 修订可以降低旧冠军；组合来源重新比较，不能只取各来源冠军 |

价格／汇率、证据和时区使用独立依赖键。它们变化时重算真正依赖它的结果，不重新复制原始冷事实；不预生成所有筛选组合。首次特殊筛选可以按实际选择范围计算，不能再为它复制一遍完整历史。

### 内存和发布

- 同一主库只允许一个有效构建任务；并发请求共享进度，发布时检查目标版本。正常追加以短事务提交事件差分、关联业务结果和发布标记，不为每次更新复制整份投影。
- 原始来源、归档前缀、修订对拍及排序使用按字节分批和现有磁盘溢写；移除覆盖整个来源／所有分片的 JS 数组与成员 Map。超大合法记录保留，不靠丢记录、加堆、强制 GC 或频繁重启达标。
- 普通读取使用已提交投影；原始主库快照在所需变化捕获后释放，不贯穿归档核验和业务重建，防止主库 WAL 被长读拖住。
- 新数据刷新只有在事实、投影和响应对应同一已完成版本时才结束和通知。切换可用既有“已发布版本”读机制；后续写入进入下一轮，不把旧缓存标成新刷新。
- 缓存进度写入不应被误认为原始来源变化；保留现有外部提交、响应缓存和 acquisition 保护。未知外部写入仍需检查，不能一概忽略 data_version。
- 200 ms 空闲退出及现有 worker 持有机制不变；依靠磁盘复用而非延长常驻进程。最多保留一份已发布投影和一份构建候选，废弃文件在失败／重开时回收，WAL 必须收敛。

**阶段门：** 六来源各一笔普通追加不重建全载体、不复制未变冷分片；范围切换和重开不重建全载体；语义、恢复和内存门全部通过后进入正式计时。

## 完整校验还需要多少工作

归档仍调用现有完整校验，保留字节、清单、来源绑定、事件数量、移除次数和读取期间一致性检查。持久投影不能替代这些检查，不引入跨请求的“mtime 相同所以可信”。

在现有证明边界允许的同一次操作内合并重复工作；跨操作不随意复用证明。将来源检查／解析、归档校验、投影维护、业务读取、通知／绘制分别计时并记录核验字节。SHA 模式下，工作量仍有随包字节增长的部分；去掉反复复制和计算后，再报告这部分实际下界。

本卡不压实归档、不新装助手、不切换原生证明机制；不能把这些未实施的收益写进预期成绩。

## 正确性边界与交付

小型语义回归覆盖：同时间多条与 Unicode 顺序、跨来源／日期会话去重、迟到事件、冷修订下降与重复 payload、来源消失、归档授权转移、价格／汇率／证据／时区变化、外部和旧版写入、缓存／包缺失与损坏、并发请求和持续追加。新增四个发布故障点复用已有真实强杀和恢复设施；不再为同一已证实故障反复跑完整页面组。

改动预计到达 `usage-history-query`、`usage-store`、`usage-executor`、既有汇总／元数据／rollup／纪录模块和必要发布边界；最多新增一个投影存储模块，不另建消息队列、后台常驻服务或依赖。顺序／变更游标／恢复各有调用方回归。复用 C1 测量工具，仅增加投影构建次数、复制／净变更行数、后缀回放、版本及存储计数，不另建性能框架。实现稳定后相关测试、类型、lint 和一次完整回归收口，已知失败保留。

最终交付代码、测试、本地提交及统一 Markdown 对照报告，逐项列标准、旧值、新值、是否达标、首次初始化和资源成本，然后停止等待反馈。未通过门槛不改写为通过，也不临时扩大到新语言、数据库、桌面客户端或另一套来源采集架构。
