# 0.8.5 本机切换与发行验收

2026-11-01，按用户指定版本号交付 0.8.5。前后端移除范围、研究盒子与完整回归见[拆除验收](../2026-11-01-tps-extraction/README.md)；0.9.0 是此前未发布的本地候选，正式版本统一为 0.8.5。

## 数据与看板

已停稳旧服务，完整备份原数据目录并核对原库 SHA-256、SQLite quick_check、源文件与外部归档登记。恢复点留在本机私有操作目录，不随源码或 release 上传。没有删除或清空原索引，也没有 VACUUM。

新旧程序分别打开独立可写备份副本，全部范围、历史日期、5h 与 7d 的统计、费用及窗口一致。当前数据库只从 schema 23 升至 24，仍沿用原数据目录。正常刷新补入较新的会话记录；逐条按来源、时间、身份及全部用量字段做多重集对照，旧事件均保留。正常重新索引会重分配 SQLite 行号，因此行号不作为业务保留条件。

0.8.5 运行在原 `127.0.0.1:3765`，保留 128 MiB old-space 设置与 7 GiB 服务树 Job 限制。原 5h 窗口不可用状态保持一致；7d、普通历史和全部范围接口通过。真实 Chromium 页面无 TPS 区域、无新增占位或说明、无脚本错误，RANGE 控件保留。README 的示例截图使用隔离合成数据重新生成。

## 客户端清理

DSH 已通过离线包管理卸载 `dsh-agent-usage-tps`，并移除其 profile bundle；其他依赖与 bundle 清单逐项保持一致，原配置和安装包已备份。此次未启动或重启 DSH，没有发送模型请求。

旧 Codex TPS 并排引擎与专用快捷方式已先备份、逐文件校验，再从安装位置移除；实际运行的官方原版引擎保持不变。OpenCode 配置没有本项目采集条目；WorkBuddy 保留普通启动入口，用户和机器级均没有本项目全局 Node hook。

Codex 持久 TRACE/debug 与 analytics/OTLP 的恢复使用封存的原恢复器，先比较本项目写入值，再恢复对应原值，保留用户之后的修改。官方隔离配置接口只读预检和精确进程范围自检通过；实际恢复需要先退出当前 Desktop，再协调重启。该最后步骤的本机结果由私有恢复回执记录。原始会话、companion、ledger 与历史日志保留，不再由新看板消费。
