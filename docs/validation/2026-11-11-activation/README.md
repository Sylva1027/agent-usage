## 实际启用时补齐的兼容修复

1. **旧 Codex 会话移入归档目录。** 旧索引仍指向 `sessions`，实际文件已移至 `archived_sessions`，部分同时压缩。原逻辑会重复导入新路径，并等待不存在的旧路径重解析。现在只在同一 home、唯一 rollout 文件身份、旧路径确实缺失且无冷归档时执行原子迁移；核对旧事件及额度记录的完整多重集合，允许新增，拒绝截断或变更。原记录完整进入既有替换历史。`price_version` 是本地价目表生成字段，迁移连续性不因这个字段单独变化而拒绝，原值仍保留。
2. **中断后的待修复状态。** 普通实时执行器允许先打开数据库再修复依赖队列；修复前仍不发布不完整元数据。冻结及导入实例的保护不变。累计依赖匹配同时要求来源、home 和 session，不能因另一个 session 有检查点而漏修。
3. **无关诊断日志阻塞发布。** Codex 经常写入 `logs_2.sqlite` 的 WAL。现在按服务等级与额度来源解析器实际筛选的记录计算输入签名；普通诊断写入不再使采集失效。同 ID 修改、删除、相关新增和数据库身份变化仍被检查，并清除对应解析缓存；不认识或读不了的 schema 保留原物理文件检查。真实日志的三次只读短测为 66.9–68.2 ms，仅说明此次检查成本。

保护仍然保守：若归档移动同时伴随跨文件累计基线修订，无法证明旧记录完整覆盖时会拒绝迁移，不猜测或丢弃旧事实。本轮没有扩展这种复杂迁移策略。
