# Rust 接入与全部范围内存实验

本实验仅运行 `.codex-usage/rust-integration-20261030/` 下的隔离源码、SQLite 和随机回环端口。正式 `src/`、`public/`、服务配置和端口 3765 均不参与修改。

## 比较方法

- 固定输入：前轮冻结的 6 个来源、1,753 个文件，约 3.52 GB；固定统计时刻为 `2026-10-29T06:14:07.825Z`。本轮不查询上游或读取 Magpie。
- 三个对照：原 Node；仅精简性能样本保留字段的 Node；精简字段后交 Rust 聚合，同时接入 Rust DSH 解析的候选。预热库未改变时不触发 DSH 解析，因此预热对照主要验证统计聚合。
- 三轮轮换顺序，每次独立库和缓存，串行运行。父服务 old-space 128 MiB，计算器 old-space 224 MiB、semi-space 4 MiB，未提高预算。
- 内存取同一采样时刻服务、计算器及已观察到的 Rust 子进程之和，同时记录 WorkingSet 与 Private Bytes。采样目标间隔 100 ms，实际间隔保存在各结果中；这是采样峰值，不能保证捕获短于采样间隔的瞬时尖峰。
- 比较完整 `summary / metadata / periodComparison / pricingCatalog / quota`，不删除业务字段、不用数值容差。范围含今日、本月、全部和 7d，并检查无新增命中、冻结快照及重启命中。

## 已确认的峰值来源

原实现的全部范围共有 70,521 个已定位样本和 527 个未定位样本。SQLite 虽然逐行解码，统计选择器仍把完整对象保存在数组中。诊断性强制 GC 后，选择前后 heapUsed 仍从约 34.7 MiB 增至 200.8 MiB，因此主要是被引用的对象，不只是暂未回收的垃圾。

这些完整对象序列化约 65.4 MiB，包含路径、身份、诊断链等统计聚合无需长期保留的字段。后面的分组排序及最终 JSON 输出不是主要增量。强制 GC 只用于归因，未用于正常性能对照。

精简 Node 对照仍逐行执行原有全字段校验；Rust 对照也由原 JS 计算来源、时间范围、标记和采样资格，再逐行写紧凑 NDJSON。Rust 保留精确分位数所需的数值向量及分组累计，不保留完整样本。临时文件读写和子进程开销都计入请求耗时。

## 三轮预热库结果

三轮所有五块业务数据完全深等，无新增 15 次命中均未启动计算器，冻结快照和重启命中也一致。以下内存均为服务进程树合计，MiB；耗时包含 HTTP 返回和 JSON 解析。

- 原 Node：全流程峰值中位数 419.98（范围 416.72–420.27）；全部范围阶段峰值中位数 419.98；全部查询耗时中位数 3.043 秒。
- Node 精简对象：全流程峰值中位数 352.20（319.23–359.12）；全部范围阶段峰值中位数 304.96；全部查询耗时中位数 2.793 秒（2.742–3.899 秒）。
- Rust 候选：全流程峰值中位数 358.29（356.74–358.36）；全部范围阶段峰值中位数 283.05；全部查询耗时中位数 3.058 秒（3.040–3.199 秒）。

Private Bytes 全流程峰值中位数依次为 407.02、334.61、339.79 MiB。无新增命中耗时中位数依次约 122、167、123 ms；这组结果不支持“Rust 能降低空闲常驻 Node 的占用”或“Rust 聚合能显著加速查询”。

原实现到 Rust 的全部范围阶段约节省 137 MiB；其中约 115 MiB 已由精简 Node 对象获得，Rust 进一步节省约 22 MiB。全流程的最高点随后转移到索引检查等阶段，Rust 的全流程峰值没有优于精简 Node。这说明数据保留方式是此处的第一收益，语言切换不是等比例的全服务收益。

## 冷建库与计量边界

历史增量库含 71,048 个样本；当前源码从头重建会产生 130,807 个样本。差异全部来自 Codex 旧方法表示与当前 tps-v4 重建，其他五个来源数量一致。因此只在相同初始库状态间比较实现，不能把两种工作负载的耗时或峰值混为一组。详细来源聚合见 `cold-warm-and-sampling-audit.json`，本轮没有修改历史索引的迁移策略。

原实现针对冷重建库查询全部范围时返回 500，计算器退出 134；stderr 明确为 `Reached heap limit ... JavaScript heap out of memory`。故障时总工作集约 387.78 MiB，并非超出总 RAM 512 MiB 后才失败。Node 精简版在相同预算下冷建库和全部范围都成功，总峰值 355.09 MiB，全部范围阶段 339.84 MiB；今日五块业务数据与原实现完全一致。

早期预热组的 100 ms 采样确实没有覆盖部分短命统计进程的内存样本，原始结果据此保留为采样峰值，不当作硬上限证明。DSH 子进程通过异步 spawn 从启动即进入采样集合；另增加原生 PID 文件以补齐 owner 退出后的结束跟踪，PID 集合去重，不重复计算。同一程序今后再产生原生子进程时，仍需继续扩展进程跟踪。

`dsh-cold` 使用原 helper：27276 从启动即由 runtime hook 记录并计入采样；本次运行在它退出前，将该已捕获 PID 写入实验预留的 PID 文件，补齐结束跟踪。最终 helper 自行写入该文件，`rust-cold` 使用这一版本。修改仅为进程计量，不改变解析、批次或统计。两版二进制哈希分别保存在各结果中。

仅替换 DSH 的冷建库今日查询成功，五块数据与 Node 精简版完全一致，阶段总峰值 340.57 MiB；随后全部范围仍因原 JS 样本保留而 OOM，故整个试验记为失败，总峰值 407.20 MiB。这直接说明单独替换解析器无法解决全部范围峰值。

最终 Rust 组合版冷建库及全部查询均成功：总工作集峰值 373.55 MiB、Private Bytes 峰值 357.64 MiB，全部范围阶段分别为 260.96 / 241.96 MiB。今日、命中及全部范围的五块业务数据与精简 Node 完全深等。原生 DSH PID 从启动到退出自动记录，无遗留 open PID。

这次冷建库单轮中，精简 Node / Rust 组合首次今日响应分别为 214.71 / 198.95 秒，全部范围分别为 4.61 / 4.90 秒。它不是三轮冷建库速度基准，也不支持普遍提速结论；原实现首轮冷建库今日响应曾为 162.32 秒。所有成功候选的本轮采样均低于 512 MiB。

结论：先优化 Node 对象保留方式更划算。Rust 聚合能再减少查询峰值，但当前桥接方式需要临时 NDJSON、进程通信和额外 native 构建；整个服务最高点并未优于 Node 精简对照。本轮证据不足以支持整体换栈或直接切换正式服务。

## 证据与复现

原始证据保存在项目的 `output/rust-integration-20261030/`，配置为 `experiment.json`。其中包含本机私有冻结输入路径，不是可分发数据集。

- `profile-1-stages.jsonl`、`profile-gc-stages.jsonl`：阶段归因及 GC 诊断。
- `sample-shape.json`：样本字段大小。
- `perf-parity.json`：真实全量、范围、排除来源、空集及溢出/Unicode 等对拍。
- `*-warm-*-result.json`、`warm-matrix.json`、`comparison-summary.json`：三轮全服务对照及逐字段校验。
- `*-cold*-result.json`、`cold-matrix.json`：真实重建路径；失败结果也保留。
- `cold-original-today-parity.json`：原 Node 冷建库今日响应与精简 Node 的完整业务对拍。
- `local-tests.log`、`native-perf-*.txt`：局部测试、离线编译和静态检查。

并行按 pinned-workers 使用三个指定 `group/deepseek`、`reasoning_effort=max` worker，分别负责 DSH 接入、服务测量框架、Rust 统计内核；测量由主代理串行排程，worker 已逐卡验收并关闭。测量结束后清理本轮重复的 trial 数据库，保留原冻结输入/seed、源码快照、配置、二进制及 JSON 结果。

在已保存的隔离副本中重新生成接入：`node experiments/rust-integration-20261030/dsh-build.mjs`、`node experiments/rust-integration-20261030/perf-build.mjs`、`node experiments/rust-integration-20261030/compact-build.mjs`。DSH 构建细节见 `native-dsh/README.md`，统计内核见 `native-perf/README.md`。

运行 `matrix.mjs` 完成三轮预热库对照；运行 `cold-matrix.mjs` 完成重建对照；运行 `report.mjs` 汇总已有结果。运行前应确保没有另一个资源基准同时执行，并使用新的 trial 名称或明确清理自己上次创建的私有 trial。

本轮不做正式接入、跨平台打包或小时级耐久验证。观察到低于 512 MiB 的峰值不等于任意未来数据规模下的内存上限保证。
