# Node 索引检查与 DSH 内存实验

本轮只修改隔离源码与实验脚本，正式 `src/`、`public/`、配置和服务端口 3765 未改动。基线是上一轮 Node 精简对象版，不包含 Rust 接入。

## 口径

- 沿用冻结的六个本机来源、1,753 个文件、3,520,947,065 bytes，固定统计时刻 `2026-10-29T06:14:07.825Z`。只读冻结副本，不查询上游或读取 Magpie。
- 每个试验使用独立 SQLite 和汇总缓存副本。三轮预热库轮换顺序为 baseline/combined、combined/baseline、baseline/combined；资源试验串行。
- 父服务 old-space 128 MiB，计算器 old-space 224 MiB、semi-space 4 MiB。未扩大堆预算；prefix Worker 被移除，不改统计和归属规则。
- 取同一时刻父服务与全部计算子进程的 WorkingSet、Private Bytes 之和。线程内存已包含在所在进程内，不重复累加。采样目标 20 ms，实际间隔与 PID 覆盖保存在结果中；不包含浏览器、测量客户端、采样器和操作系统文件缓存。
- 比较完整 `summary / metadata / periodComparison / pricingCatalog / quota`，无字段删减或数值容差。预热路径含今日、本月、全部、7d、冻结快照、五次无新增命中和重启命中。
- 预热与空库重建具有不同的历史样本集合，只在相同起始库状态间对拍。首次响应指启动后汇总缓存未命中的今日查询，不指重启后已有持久化结果的命中。

## 已固定的原因

索引检查不是简单目录扫描。基线阶段剖析显示，目录发现只需约 7 ms；Codex 检查还会读取完整前缀、验证归属、检查读取后的稳定性，并水合部分历史性能候选。已更新的 seed 再次启动时，`updatedFileCount=0`，仍有 6 个线程构建、1,499 个线程保留；本轮没有为了省时放松这些历史兼容判据。

基线另外存在可直接删除的临时分配：

1. `changedSessions` 为空仍逐文件查询旧 session，后面的 `.some()` 必为 false。
2. 旧 sample keys 先 `.all()` 再建 Map；历史候选比较同时保留旧对象和新 `.all()` 数组。
3. 67,290 条额度观测先 `.all()` 再 `.map()`，一轮剖析的 SQL 物化带来约 46 MiB heapUsed 增量。它是该时点的净增量，受 GC 影响，不是对象精确大小。
4. 大 home 前缀检查启动两个 Worker，分别加载完整模块图。候选改为同一计算器内两个异步 reader，各复用 1 MiB Buffer；完整内容哈希、失败状态和前后稳定窗口保持。

候选采用迭代读取、直接映射、及时清除已用的旧候选 Map。阶段插桩只用于归因，有额外开销，不用于速度结论。

一次候选剖析的索引同步为 9.84 秒，其中完整前缀约 2.03 秒、归属证明约 1.47 秒、读取后检查约 0.70 秒；后续 dashboard 汇总另需 4.03 秒（其中 summary 3.42 秒、periodComparison 0.60 秒）。这解释了为何减少索引临时对象后，HTTP 首次响应仍约 15 秒：减少分配没有移除这些读取与汇总工作。上述区间有嵌套关系，不能再次相加计为总耗时。

## DSH 原型

去除逐帧 `split` 数组，用 `indexOf/slice` 扫描；usage/perf 热路径在异步 yield 前提取统计字段，TPS map 不保留正文、stream 或工具载荷。完整 rows API 保持兼容。坏帧、坏 JSON、晚头、跨帧 UTF-8 replacement 语义、模型归属、usage 和 TPS 均保留。

它仍会持有整个压缩文件、单个解压帧和未完成行，`JSON.parse` 仍完整创建单条记录。它降低保留重载荷的机会，不能保证单条巨大 JSON 不会耗尽 JS 堆。没有引入自定义 JSON parser、第三方依赖或 Rust 桥接。

## 三轮预热库结果

以下均为本轮同一冻结输入、相同起始库的结果，不与上轮不同采样时段的数值混算。

- 全流程总工作集峰值中位数：334.78 → 284.28 MiB，约降低 15.1%；范围分别为 334.77–338.49 / 283.57–286.81 MiB。
- 全流程 Private Bytes 峰值中位数：343.91 → 296.88 MiB。
- 首次请求阶段总工作集峰值中位数：约 335 → 266 MiB，约降低 20.4%。最高点随后移至全部范围查询。
- 首次响应中位数：14.912 → 15.137 秒；三轮分别为 14.912/14.287/15.527 与 15.918/14.594/15.137 秒。本轮不能证明首次响应提速。
- 全部范围查询中位数：2.865 → 2.866 秒；该阶段工作集峰值中位数：282.28 → 284.28 MiB，未改善。
- 无新增命中各 15 次，均未启动计算器；耗时中位数 134 → 139 ms。重启命中中位数 125 → 121 ms。父服务在这些短请求中的占用没有显示出显著下降；本轮没有把这些请求时点冒充长期待机数据。

三轮的完整五块业务数据、冻结快照、无新增命中和重启命中全部一致。全部已记录启动的服务/计算器 PID 都获得了内存采样，结束后没有未闭合的 PID。

最大三个 DSH 文件为 13,114,066 / 10,806,901 / 8,851,570 压缩 bytes，共输出 3,716 个 usage 事件及 3,716 个 TPS 样本。独立进程一次顺序对照的生命周期 maxRSS 为 125.48 → 123.46 MiB，总耗时 3.397 → 3.132 秒，事件/样本/告警摘要一致。收益较小，且只是单轮局部结果；不支持“DSH 改写显著降低全服务占用”或“已经解决超大 JSON 的 OOM”结论。

## 空库重建结果

两版均从空库重建并成功返回今日、今日命中和全部范围，五块业务数据全部深等。

- 总工作集峰值：399.73 → 370.77 MiB；Private Bytes 峰值：409.20 → 379.96 MiB。
- 首次今日响应：170.179 → 164.572 秒；全部范围查询：3.401 → 3.575 秒。
- 两版 WorkingSet 和 Private Bytes 的所有采样均低于 512 MiB；启动的进程均获得采样且已正常结束。

这是一轮重建对照，不是稳定提速结论。最终矩阵八次服务运行的实际采样间隔中位数为 22–26 ms，单次最大间隔为 52–68 ms；比目标 20 ms 稀疏，不能排除更短尖峰。

本轮主要成果是减少索引阶段临时内存。首次响应、范围切换、短测刷新和父服务常驻占用没有显示出稳定的速度/占用改善。若继续降低首响耗时，已测得的主要剩余工作是完整内容校验、归属证明、部分历史候选复建和 dashboard 汇总；DSH 不是这组真实数据中的首要瓶颈。

## 验证与复现

实验配置与完整证据位于 `output/node-index-20261030/`，包含私有本机路径，不能当可分发数据集。

- `profile-stages.jsonl`、`index-profile-*-result.json`：阶段剖析。每条含 PID；新插桩也含 threadId，heapUsed 属于各 isolate，RSS 属于整个进程。
- `index-first-verify.json`：仅 SQL/数组优化的单轮完整业务对拍。
- `matrix-warm.json`、`matrix-cold.json`、相应 `*-verify.json`、`comparison-summary.json`：最终服务对照。
- `dsh-memory-real.json`：冻结集合中最大三个 DSH 文件的独立解析对照。maxRSS 是该子进程全生命周期峰值，回调 heapUsed 仅为采样点，均不能当成每个文件的瞬时峰值。
- `combined-tests-host.log`：131 项回归通过。`measure-prefix-tests.log`：8 项实验工具/前缀语义测试通过。DSH 另有完整行、事件、TPS、告警深等脚本。
- 一次 prefix 试验因采样状态文件重写间隙被误读为空而把 PID 0 纳入采样，记为失败并保留原证据；采样器已修复，并以空状态回归测试验证。最终矩阵没有沿用该次结果。一次测试的 SQLite 硬链接被沙箱拒绝，宿主重跑全部通过。
