# Node 首次响应：重复工作隔离实验

本轮以此前已验证的 Node 精简版和索引/DSH 优化组合为基线，只修改 `.codex-usage/node-startup-20261030/` 中的源码副本及本目录实验脚本。正式 `src/`、`public/`、配置、端口 3765 和 Git HEAD 均未改动。

## 测量口径

- 冻结的六个本机来源、1,753 个文件、3,520,947,065 bytes；固定统计时刻 `2026-10-29T06:14:07.825Z`。不联网、不读取 Magpie、不改原始日志。
- 每次使用独立 SQLite 和汇总缓存。预热库的首次响应指：已有索引、尚无本次汇总缓存时的今日查询；与已有持久化汇总的重启命中分开记录。
- 三轮预热对照串行执行，顺序为 baseline/candidate、candidate/baseline、baseline/candidate。完整流程含今日、本月、全部、7d、冻结、读取冻结快照、五次无新增命中和重启命中。
- 取同一时刻父服务与全部计算进程的 WorkingSet、Private Bytes 之和；不把浏览器、测量客户端、采样器和操作系统文件缓存算入服务。目标采样间隔 20 ms，实际间隔和进程覆盖记录在 JSON 中。
- 父服务 old-space 128 MiB，计算器 old-space 224 MiB、semi-space 4 MiB，未提高堆预算。512 MiB 是整个服务的测量目标，不是单进程堆上限。
- 比较完整 `summary / metadata / periodComparison / pricingCatalog / quota`，没有删业务字段或引入数值容差。

## 确认的重复工作与最小修改

### 内容校验

基线先读取头尾探针，再顺序读取完整前缀计算 SHA256。候选在完整前缀读取期间同时计算前置探针，不再独立读取一次。完整前缀、后置稳定性探针、归属证明和 append 校验仍保留，没有跨轮复用完整内容校验结果。

真实插桩中，prefix 阶段的同步探针读取由 2,613 次、159,240,655 bytes 降为零；完整异步读取仍为 3,823 次、2,790,483,764 bytes。减少的是重复探针读取，不能宣称不再读取完整历史。

完整 prefix 读取失败仍返回不完整证据；如果短探针仍可读取则保留其结果。空文件也必须成功打开，不能把不可读空文件当成成功。`content-test.mjs` 的五项检查覆盖正常读、append、中部改写并增长、读取中途失败和不可读空文件。

### 历史候选复建

6 个线程的旧归属各有两条路径，当前各只有一条。基线因路径数量不同触发复建，发布后又保留缺失的旧归属，所以下次启动继续复建。

候选复用已存在的 `perf_missing_sources`：只有上一轮成功发布、方法版本相同、policy 无需升级、同 home 的 Codex 路径仍缺失且没有替代路径时，才在路径数量比较中忽略这条已确认缺失的额外旧依赖。不删除旧样本或归属，不跳过整个 home 的内容检查。

真实插桩的 staged/retained 由 6/1,499 变为 0/1,505。新缺失仍构建一次；路径返回、同 size/mtime 的内容变化、dirty timing、旧方法、损坏元数据仍要求重建。`history.test.mjs` 对 events、samples、归属、依赖、告警和 indexVersion 做完整对拍。

### 汇总

历史冠军扫描原先逐条重复规范化模型并构造 event memo 键。候选使用现有 `createEventPricing()`，在一次调用内复用模型字典，仍按原顺序累加并使用相同价格公式、tier 证据及未知值语义；冠军汇总缓存保留。

同一读事务中的 quota observations 只读取一次。额度范围原先三次调用降为一次；今日范围本来就只调用一次，因此这项不作为今日首响提速的原因。

`summary-parity.mjs` 七个案例比较完整对象，涵盖不同范围、时区、未知模型/tier/context 和非整数费率。

## 实测结果

三轮相邻预热对照的中位数：

- 首次响应：21.394 → 15.062 秒，减少 6.332 秒，约 29.6%。基线三轮为 22.282/21.394/21.357 秒，候选为 15.163/15.062/14.899 秒。
- 首次请求阶段总工作集峰值：254.71 → 239.84 MiB，约降低 5.8%。
- 全流程总工作集峰值：276.30 → 280.14 MiB；Private Bytes 峰值：288.52 → 292.76 MiB。整个流程的内存没有明显改善，不能把首响阶段的下降说成全流程下降。
- 全部范围查询：3.394 → 3.542 秒，未提速；这一阶段仍产生全流程最高工作集。候选三轮全流程工作集最高 282.55 MiB、Private Bytes 最高 294.68 MiB。
- 无新增命中各 15 次，中位数 185.80 → 185.59 ms，均未启动计算器；重启命中为 175.83 → 169.36 ms。没有新增一次完整耐久试验，不能据此判断长期待机变化。

本轮候选从空库重建成功：首次今日响应 239.987 秒，全部范围查询 4.879 秒，总工作集峰值 368.21 MiB、Private Bytes 峰值 378.66 MiB，完整业务结果与已验证的冷库基线相等。基线引用的是上轮同源码、同输入结果，不与本次耗时相减作速度结论。

三轮预热与一次候选空库重建中，服务/计算器所有已记录启动的 PID 均获得采样，运行结束无未闭合 PID；WorkingSet 与 Private Bytes 的采样均低于 512 MiB。预热实际采样间隔中位数 31 ms、最大 46–74 ms，候选冷库中位数 31 ms、最大 46 ms；不能排除更短尖峰。

最终数值、进程覆盖和阶段 IO 在 `output/node-startup-20261030/comparison-summary.json`，完整对拍在 `matrix-warm-{1..3}-verify.json`、`matrix-cold-1-verify.json`。

## 首次响应剩余耗时

一次候选插桩的首响为 15.062 秒，其中索引同步约 10.200 秒，dashboard 汇总约 2.601 秒。同步内部包含完整前缀读取约 1.787 秒、归属证明约 2.973 秒、后置探针约 1.087 秒；发现来源仅约 5 ms，前置文件与指纹检查约 121 ms。汇总内部 summary 约 1.938 秒，历史冠军扫描约 854 ms，额度观测约 447 ms，趋势比较约 469 ms。

这些阶段有嵌套关系，不能再次相加算作总耗时。未覆盖区间还包含进程启动、传输和其他工作，未为它们单独标定。profile 的机器时段与插桩开销不同于速度矩阵，只用来定位剩余工作，不能把两次 profile 相减当作各优化的独立收益。

结论是：本轮消除了明确的重复读取、重复复建和逐条重复计价，改善了已有索引但汇总未命中时的首响。完整历史内容读取、归属证明和后置稳定性检查仍占主要时间；没有用跳过这些检查换取速度，也没有证明首次建库或全部范围查询提速。

## 验证、协作与复现

按 pinned-workers 分别派出内容校验、汇总两张独立任务卡；主代理处理历史候选与整合。两名 worker 的创建参数均为 `model: "group/deepseek"`、`reasoning_effort: "max"`、`fork_context: false`，返回 ID 为 `01a18a32-53db-77d3-9b02-833a796d48d6`、`01a18a32-54a3-7891-b142-c29cb9491e5f`。这是工具请求参数记录，不是对物理后台模型的证明。交付已验收，worker 已关闭。

候选相关回归测试 130/130 通过、无 skip。冻结基线使用相同适配方式的相关测试 86/86 通过。`validation-hook.mjs` 仅在加载时适配原型已删除的 Worker 和无效 SELECT 注入点，保留业务断言；没有修改正式测试或跳过失败。原注入点在冻结基线上也会失败，相关日志保留。

空库测试复用上一轮真实基线的冷库业务输出作为 oracle，只在本轮重新构建候选。`cold.mjs` 先检查相同输入 manifest、固定时间、全部基线源码哈希，再对拍完整业务结果。两次冷库运行不相邻，不能据此宣称冷库提速。

脚本顺序：`prepare.mjs` → 三个 `*-build.mjs` → `combine.mjs` → 局部及适配后的回归测试 → `matrix.mjs warm` → `cold.mjs` → `report.mjs`。prepare 不覆盖已存在的隔离源码。配置和完整原始证据在 `output/node-startup-20261030/`，含私有本机路径，不作为可分发数据集。

收口时已核对无残留实验 Node 进程，并删除本轮 `trials/` 的运行数据库（约 14.6 GB）。脚本、源码副本、JSON/JSONL、完整响应以及原冻结输入和 seed 均保留；结果 JSON 中的 trial 数据库路径仅作为运行记录。

阶段插桩仅用于解释工作量，带有额外开销，不能把不同时段的 profile 耗时相减当作稳定提速。最初一次基线请求在计算器启动前遇到 `fetch failed`；未产生业务响应，退出后无进程残留。失败记录保留，最终速度矩阵使用重新命名后六次成功的相邻对照，没有将该失败纳入性能数据。

本轮不追加小时级耐久，不重做 Rust 接入，不引入新的持久化认证层或放松校验。采样结果不能排除短于采样间隔的尖峰，也不能证明任意规模或单条巨大记录均低于 512 MiB。
