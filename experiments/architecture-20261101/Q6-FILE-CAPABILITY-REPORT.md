## 2. 哪些数据值得直接比较

| 比较方式 | 可以回答什么 | 不能由此推导什么 |
| --- | --- | --- |
| 同一行 Q5 与本轮 | 同数据、同通路、同布局下，新旧版本的差异 | 不能拿早期另一轮 Q5 成绩替换本轮对照 |
| 原生 1× 与原生 10× | 固定文件分布下，事件密度增长的影响 | 10× 不等于一年或两年历史 |
| 2 千与 2 万文件 | 固定事件数、会话数的文件分布对照 | 两档实际解析路径不同，差额不能全算作文件数成本 |
| 同一行首次打开的新旧版本；同一行重开的新旧版本 | 两类启动流程各自是否退化 | 首次与重开的计时起点不同，不能跨列计算速度比 |
| 同一行资源总成本 | 同组动作全程的 CPU、逻辑 I/O 与内存代价 | 不能当作单次追加成本，也不能把逻辑 I/O 当物理磁盘 I/O |
| 原生与 SHA | 了解两种运行条件的表现 | 来源所在卷、检查工作不同，不能作纯算法速度排名 |

**原生**指系统变更日志能够提供完整变化依据；**SHA**指继续使用完整前缀内容校验的回退路径。本轮原生来源及辅助输入在 C 盘，数据库在 E 盘；只在同一通路内评价新旧版本。

固定 **20,001 条事实、2 个会话**。每个版本、每档文件数、每种来源各 **1 次**；这些是单次观测，不是稳定中位数。

2 千文件候选两次为尾部增量；2 万文件候选两次为**有原生证明的单文件重解析**，Codex / DSH 分别读取 1,505 / 433 字节。四次都没有全局回退；重解析不能记为成功尾部增量。

### 增长标准：耗时比 ≤1.300

耗时比 = 大规模耗时 ÷ 小规模耗时；1.300 代表数据规模增大后，刷新最多慢 30%。

| 文件数 2 千 → 2 万 | DSH | 5.938 | 2.679 | ≤1.300 | 未通过 |

事件密度组初始事实为 146,412 / 1,464,120 条，均为 1,968 个用量文件，同一日期/文件/会话分布。文件数组的事件数和会话数固定，但解析路径不同；不能据四次追加拟合长期增长曲线。
