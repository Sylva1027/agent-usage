# Q5：刷新提速与通知闭环

日期：2026-11-04。状态：实现、正式矩阵、业务对拍及额外诊断完成。**正确性与资源门通过，2 秒刷新和 400 秒重建门未通过。** 接续 [实施卡](../../docs/plans/2026-11-04-q5-refresh-delivery-plan.md)与 [Q4 报告](Q4-BULK-BUILD-REPORT.md)。本地阶段提交后停止等待反馈。

## 实现范围

一条候选、两项改造，继续使用 Node、SQLite 和浏览器。

1. **刷新交付。** 跳过来源检查的读取仍等待已经开始的同步；同步承诺在异步准备前登记。响应保持业务结果与来源指纹一致，未命中读取最多补读一次，持续提交不会无限拖住请求。每轮完成的变化及时通知页面，不再等待连续提示结束；相同版本去重。页面合并当前请求期间的通知，切换范围遗留的请求和价格详情请求不阻塞新数据；断线重连、订阅就绪及监听错误均能触发核查，替换掉的订阅不能干扰当前页面。
2. **来源校验。** SHA 回退的读取块由 64 KiB 改为 1 MiB，保持同样的完整字节读取、前后快照检查、v2 证明与实际解析字节绑定。沿用 Q4 已有的 Windows 原生证明；只有 journal 证明完整成立才避免旧前缀读取，不启用或配置系统 journal。原生程序没有改写。

没有新持久结构、迁移、依赖或进程架构；原生组使用原来已有的 helper，计入服务树。gateway 512 MiB、executor 224 MiB / semi-space 4 MiB 保持不变。用户服务和活跃数据库未改动。

## 复测口径

Q4 对照冻结自 `5fcad38e958fc1eceba08c847f163f4b29128193`，逐文件核验 101 个源码/页面文件及 7 个原生相关文件。候选在运行中和跨轮继续核对源码摘要。价目从进程启动起使用同一份捕获输入；在线价格更新正确性另由普通回归验证。

两规模均为六类来源、1,968 个用量文件，原始输入约 4.27 / 41.83 GB，初始事实 146,412 / 1,464,120 条。全部来源副本在首次认证前准备。每种规模和证明方式持有一个固定来源目录，两版本顺序运行、使用独立 SQLite 副本，保留事件 ID；每轮恢复两个独立追加文件并校验原始字节、事实摘要和证明，准备时间另记。数据库均在 E 盘，SHA 来源在 E 盘，原生来源在 C 盘；只比较同一证明方式与来源目录内的 Q4/Q5，不能把 C/E 差异解释成代码收益。

正式计划为 **8 组页面、160 次追加**，每组各 10 次 Codex 和 DSH，包含真实来源检查、同步、解析、SSE、请求和正确新值绘制，并验证范围切换及完整服务重开。失败尝试先落盘保留，不用旧值或停止转圈作为完成。**2 次候选完整重建回归**使用 E/SHA 空库；另有 **2 次 C/原生对照初始化**用来生成独立种子，实际规范导入共 4 次，二者分别计数。不是物理冷盘、正式 p95 或长期容量验收。

普通用户权限预检中，C 盘原生 begin、seal、append verify、advance 成功，同大小中间改写且恢复 mtime 被拒绝；E 盘返回 journal 不可用（Win32 1179），故使用 SHA。进程不是提升权限的系统管理员；工具执行权限与 Windows 管理员权限不同。

## 结果

**8 组、160 次追加全部完成**，没有中断组、被排除的追加或原生回退冒充快路径。四格起止的九类主业务字段、元数据和周期结果逐值对拍通过，八次完整服务重开通过；正式重建和原生初始化也通过事实检查。这里的“通过”表示正确性，速度目标另判。

以下为每源 10 次的“落地后显示新值、关闭忙状态、两帧并由探针确认”中位数，单位秒，Q4→Q5：

- **1× SHA：** Codex **3.131→2.954**；DSH **2.672→2.654**。
- **10× SHA：** Codex **8.055→6.164**，减少 **23.5%**；DSH **3.135→2.915**。
- **1× 原生：** Codex **2.864→2.859**；DSH **2.773→2.757**，基本持平。
- **10× 原生：** Codex **2.670→3.293**；DSH **2.258→2.365**。本组候选更慢，**不能声称原生路径提速**；该组的时序差异保留在证据中。

探针在写入诊断后再确认页面，会比浏览器自己的绘制记录晚。浏览器观察到的 10× Codex 新值绘制中位数为：SHA **7.840→5.945 秒**；原生 **2.458→2.935 秒**。两种终点分别保留，**按实际绘制也没有达到原生 ≤2 秒目标**，没有用更早的请求完成或缓存旧值替代。

10× SHA 每次 Codex 实际解析中位数仅 **570 字节**，证明仍读约 **4.04 GB** 旧前缀；两版本读取量相同。1 MiB 读取块减少调用开销，未改变增长阶。独立同文件、交替三次的小测中，两次前缀校验合计 4,044,842,700 字节，耗时约 **3.023→2.128 秒**；这是证明函数的小测，不是页面成绩。

80 次原生追加均证明 verify、capture 和最终进度实际走原生快路径，旧前缀读取为 **0 字节**，仍有 journal、来源目录和数据库访问。原生能力在 Q4 已存在；不能把“原生相对 SHA 的差异”全部记为 Q5 的贡献。

## 完整重建与剩余时间

正式两次候选空库重建到原页面默认页及首次 all：**1× 55.766 秒、10× 429.745 秒**；初始事实分别为 146,412 / 1,464,120 条。10× 超过 400 秒，门未过。额外两次 C/原生 Q4 种子初始化为 **53.114 / 468.881 秒**，属于夹具准备，不能与 E/SHA 直接作因果比较。

Q4 旧报告的 10× 中位数为 372.071 秒，但本轮插桩、目录布局和运行状态不同。为核实本次改动是否造成重建回退，在原定矩阵后另做 **1 次 Q4/E/SHA/10× 空库诊断**，使用相同来源目录、价目、Q5 插桩和资源观察器；与正式回归分开列，不混成重复样本。诊断耗时 **701.159 秒**，原始事实及事件 ID 摘要与种子完全相同，完整页面和数据库完整性检查通过；服务树峰值 **218.67 MiB**。当前同口径诊断没有测到候选重建更慢，但这仅是一轮顺序对照，**不把它当作稳定中位数或将跨报告的差异全部归因于代码**。连同正式回归和种子初始化，本轮实际空库导入共 **5 次**。

另对同一不可变 2 GB 前缀做有／无 Q5 包装的交替小测，每种三次：Q4 证明类 **3.055 / 3.130 秒**，Q5 **2.101 / 2.103 秒**。此处插桩差异约 2.5% / 0.1%，没有解释整个启动链路的差距；**没有完成整页和完整导入的无插桩校准**。本轮绝对成绩与验收状态均按这套诊断口径报告，不替代用户设备上的性能保证。

剩余刷新时间已能定位到较粗的环节。10× 原生候选的来源同步中位数约 **1.763 秒**；一个 3.412 秒确认样本中，来源同步 **1.961 秒**，实际新记录追加 **69 ms**，SSE 后请求约 **323 ms** 才收到响应，浏览器随后处理和绘制。每次追加窗口新启动执行器的中位数为 1，落地到同步开始约 318 ms。这些包围计时含子调用，不能相加两遍。

这支持下一轮先细分来源同步中的全来源检查、同步后发布检查以及执行器启动成本。**尚未单独量化每项，不能把全部余量都归为目录扫描，也没有证明只延长执行器寿命即可解决。** 本轮不继续更改这些机制。

## 资源与磁盘

- 候选四格活动服务树最大采样峰值 **340.31 MiB**，候选 10× 冷构建峰值 **203.69 MiB**，均低于 512 MiB。两种堆参数和进程结构未增加；没有常驻完整事件数组。
- 浏览器单独计量，候选四格峰值约 **1.16 GiB**，不计入服务树预算；本轮没有优化浏览器内存。
- 10× SHA 完整页面组（含初次加载、20 次追加、切换和服务重开）的采样 CPU 合计 **90.38→76.30 秒**，逻辑读取 **46.35→45.21 GiB**，逻辑写入 **0.347→0.393 GiB**。读取量未因读块增大而根本减少；没有把逻辑写入增加隐藏为“零额外开销”。
- 10× 正式冷构建采样 CPU **436.80 秒**、逻辑读 **104.95 GiB**、逻辑写 **23.64 GiB**；WAL 最大采样长度约 **230.18 MiB**。最终页面库两版本均约 **2,252.69 MiB**，无新增持久结构。
- Windows 逻辑 I/O 不等于物理磁盘流量；500 ms 采样不是瞬时上界，短进程和追加窗口的边界会影响归属。精确前缀字节数使用证明返回值，未用采样值冒充。目录可见 TEMP 也不能代表匿名 SQLite 临时文件的完整占用。
