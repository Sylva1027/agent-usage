# B2：来源级增量实施与验证

日期：2026-11-03。状态：本轮实施与验证已收口，**新链路对拍、恢复及单源回退容量门通过，整页延迟与服务树资源门未通过**；停止等待反馈，不能称为 B2 全部验收通过。本轮不进入 B3/C，也不重启用户服务。

## 已实现的通路

- Codex 按完整物理行续读，保留模型、累计解释、字段已知性、跨文件基线、额度路由和行号；DSH 按结构化的完整 v4 Zstd 帧续读，一次只保留一帧，超过边界的有效输入仍走完整解析，不丢记录。
- 每个来源的事实、解析状态、校验证据与字节进度在同一事务提交；旧写入器的事实/来源变更会使进度失效。修订的累计依赖进入持久队列，发现顺序相反及进程中断后仍会继续修复。
- 活动 NTFS journal 上使用一个按需启动的 Rust 后台辅助进程核实完整写入区间，保留浏览器界面，不配置系统 journal。二进制需显式构建，缺失、能力不足或不安全时完整校验/解析回退。
- 持久纪录的普通追加只计价新增事件；精确成员落盘，周期排行从小型持久周期行重算。旧行更新/删除仍可撤回重建，并保留并列和下降语义。
- 浏览器共享来源唤醒，75 ms 固定合并窗口，经真实同步提交后 SSE 通知当前范围重读；保留 60 秒完整检查、重连恢复、冻结/手动/只读导入隔离，慢 SSE 连接断开后重连恢复。

## 主审修正与当前验证

独立 [V1 审查](./B2-NATIVE-REVIEW.md)发现了两处可复现的错误接受路径：同 size/mtime 的同路径替换可绕过不变判断；SHA 校验与提交之间旧前缀可变。主线已加入物理身份/ctime 的来源签名与进度核验，SHA 回退在解析后重读并核对完整旧前缀；原生路径结束后再核对当前路径身份。相同完整字节的来源恢复可以重新认证进度并保留已有事实/归属；新文件中段不同则完整重解析。V2 六项反例回归及复审通过，两项发现已闭环；不能只凭原生组件自身测试宣称整条路径可靠。

现有索引中尚无进度的旧来源，首次实际变化仍需完整解析以建立检查点；未强制把迁移变成全部原始历史重建。预先存在的旧“不变来源”内容抽样契约不在此被声称为全内容完整性证明。新进度一旦建立就受上述身份、前缀及事务约束。

主线最终 77 项来源、存储、追加、反例、精确替换及刷新测试通过；三种实际子进程 SIGKILL（追加提交前、提交后、上游修订提交后且依赖尚未修复）均恢复到正确总量，游标不越过未提交事实，重复重启不重复计算。证据：`output/architecture-20261103/b2/crash-bounded-final/result.json`。

第一次沙箱外完整回归为 2,630 项：2,601 通过、25 跳过、4 失败。两项是 B1 已复现的旧 UI 问题；另两项分别是新 native 集成测试误用无 journal 的 E: TEMP，以及冻结流程主动关闭 SSE 的 `ERR_ABORTED` 被旧捕捉器当作资源失败。已明确使用私有 C: 活动日志夹具，并只对有显式 `EventSource.close()` 证据的 SSE 取消分类；连接重置、普通 fetch 及未主动关闭的流仍报失败，三项定向回归通过。最终完整回归为 **2,648 项：2,621 通过、25 跳过、2 项旧 UI 失败、0 取消**。沙箱备份 EPERM 的无效轮不作为产品结果。类型检查通过；lint 无错误，保留已有 51 warnings / 3 infos，未修改无关 CSS。

真实留存库 160,447 条事件、10 个范围重新与旧算法对拍，**63,752 个数字字段全部逐值相等，其他值也相等**。JSON 字节摘要不同仅来自 448 处对象键顺序，不是数值容差通过。证据：`output/architecture-20261103/b1/b2-final-business/`、`output/architecture-20261103/b2/retained-numeric-diff.json`。

1×/10× 来源垂直与原页面诊断均已完成，并保留失败与续测边界。资源限制维持 gateway 512 MiB / executor 224 MiB old-space，不把小样本当 p95，也不把 E: 回退当成历史无关追加。

## 来源增长与回退容量

[G1 报告](./B2-GROWTH-DIAGNOSTIC.md)覆盖 1×/10×、Codex/DSH、C:/E: 共八组：同源字节在自有副本中追加，校验原始冻结输入 SHA，再逐字段、多重集对拍 events、rate-limit、quota-source 三表；八组均通过。每组只包含选定的最长一个来源，不冒充完整六来源页面。

- 10× Codex 长日志约 2.02 GB。活动 C: journal 下三个追加的 `sync()` 为 **33/34/41 ms**，解析 **357/357/359 字节**后缀、旧前缀校验读取为零；all dashboard 另需约 **401–432 ms**。这些不能相互替代，也不是端到端页面时间。
- E: journal 不活动，三个追加的 `sync()` 为 **3.15–3.16 秒**；每轮约 **4.04 GB** 证明读取（旧前缀两次加后缀）。保持完整性，但不满足历史无关刷新或一秒目标。
- 旧 full replacement 在同一进程连续三次追加后，于 224 MiB 堆下复现 OOM。定位到旧/新事实数组和 canonical payload 计数 Map 后，改为临时磁盘 SQLite、逐行精确多重集比较；原序列复测通过，2.02 GB 完整替换 **16.36 秒**。修复没有依靠隔离重启、增加堆或清空业务缓存。
- 八组服务树的采样 RSS 峰值约 **137–191 MiB**，包含辅助进程；helper 约 **8.9–9.1 MiB**。采样不是严格瞬时上界。临时差分空间及额外 I/O 随被替换来源的不同事实增长，正常追加不建立这份暂存。

[S1 独立复核](./B2-REPLACEMENT-REVIEW.md)及五项新回归确认 canonical JSON、排除 event auto ID、重复次数差、来源归属、历史 method/reason 以及失败回滚保留旧语义。冷修订 effectiveRows 的旧数组/Map 路径仍属 B3，未把这项修复称为全路径有界。

G1 主矩阵完成后又补了“首次解析尚无 checkpoint 时也检查 discovery ctime/最终物理身份”的时序保护；不新增读取和计算结构，77 项定向及最终完整回归覆盖此差异。矩阵原始源码 hash 与闭环源码 hash分开保存，不能说八组均在最终字节完全相同的源码上执行。

随后补齐“上游修订已提交、下游原始来源不可用”的发布门：事实和待修复队列持久保留，拒绝把新上游与旧下游的混合统计作为已完成结果。来源返回后会继续修复；存储层及真实 HTTP 的缺失→失败读→返回→正确读回归均通过。这个错误分支保护未改变正常追加的计算结构，但增加了公开查询前对 pending 队列的空表检查；最终源码与此前矩阵差异在闭环审计中保留。此处没有把来源永久丢失时仍能重解释旧累计关系当成已解决。

## 必须先解决的判定

字节游标、解析器状态和事务提交能够避免重复处理，但它们不能单独证明旧字节未改。当前 `syncRound` 在发现来源变化后整文件重解析，因此“修改旧行并追加”能被重新计入；把它改成“长度变大且首尾指纹一致就只读后缀”，会减少既有的变化处理保证。

`b2-append-evidence-proof.mjs` 使用当前正式的 Codex 与 DSH 解析器、完全隔离的合成日志验证了两种输入：只有追加，以及旧中段同时修订。物理文件身份、递增且相同的 mtime、大小、头部/旧前缀尾部/新尾部抽样和新增后缀均一致，完整解析的结果却分别为 2,401,200 与 2,409,200 token，相差 8,000。两种来源均通过这些断言；DSH 使用 Node 解码自检通过的合法 v4 Zstd 帧。

这不是 SHA256 碰撞，而是未读取的中段可以不同。`ctime` 还能说明发生过变化，但它没有提供写入范围；文件通知和格式中的序号也不能直接成为旧前缀未改的证明。副本中的 mtime 受控，用于比较同一观测契约，正式日志未被更改。有效证据为 `output/architecture-20261103/b2/preflight-v2/result.json`；v1 未要求 mtime 递增，保留但不作为此项通过证据。

解析器状态同样不可简化为 offset：Codex 还需要 session/turn 上下文、累计计数及其已知字段、cache-write、首次请求判断和额度路由状态；DSH 需要已验证帧边界、首个会话头、当前模型/供应商及跨帧行状态。旧文件修订还会影响其他文件的累计基线，不能只更新变动文件后忽略依赖链。

## Windows 能力核对

通过 [pinned-workers](C:/Users/Silver/.codex/skills/pinned-workers/SKILL.md) 独立核对普通权限下的变更日志接口，W1 已审阅：C: 的目录句柄可查询活动 journal，较新非特权读取成功；E: 的目录句柄返回 journal 不活动、单文件 USN 为零。沙箱内外均为非管理员且结论一致，不能泛化为所有 Windows 不支持。结果见 [Windows 实验](./B2-WINDOWS-PROBE.md)与 [派卡记录](./b2-worker-audit.json)。未启用/创建/删除系统变更日志，未安装服务或进行 UAC 提权。

不能仅用旧文档的管理员要求下结论：Microsoft 的较新绑定确实定义了 [`FSCTL_READ_UNPRIVILEGED_USN_JOURNAL`](https://microsoft.github.io/windows-docs-rs/doc/windows/Win32/System/Ioctl/constant.FSCTL_READ_UNPRIVILEGED_USN_JOURNAL.html)。同时，单文件 [`FSCTL_READ_FILE_USN_DATA`](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_file_usn_data) 返回的 Reason 不有效；[变更日志记录](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journal-records)还会在未关闭的写入句柄期间合并相同原因，不能直接把一个递增 USN 当作覆盖所有改写的证明。

原计划已允许能力不足时完整校验回退，因此不因 E: 缺少能力而自动要求用户确认或改变系统设置。W2 在当前 C: 活动 journal 的私有临时夹具上通过 272 项断言，随后 W3 完成另进程长期打开 writer 的追加/覆写、精确 seal 区间、缺失/畸形协议和超时验证；见[原生组件证据](./B2-NATIVE-PROOF.md)。只操作自有合成文件，未改变任何卷日志配置。若后续确实必须改变系统前提或验收要求，按用户指示先停止说明。
