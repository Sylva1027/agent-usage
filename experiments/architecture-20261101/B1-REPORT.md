## 改造范围

- 额度通过数据库查询生成小型窗口结果，完整观测仍保留；历史窗口供消费者逐个归约。
- 历史纪录的周期数值、精确成员及构建进度持久保存；事实版本与计价/证据/范围依赖分别失效。
- 仓库多周期统计沿用 dirty-day rollup，保留精确 cwd 去重与原始明细字段语义。
- 时间线会话去重共享小型内存预算，超过后用匿名 SQLite 暂存，不减少精度。
- 额度来源分类不再全表读入 JS：按线程/账号索引查询有效状态，身份查找为 Map，线程和账号共享 1 MiB LRU；每个读帧及写入/回滚边界清缓存，连接更换时重新绑定。
- 冻结读快照不能升级为源库写事务；必要时使用独立匿名派生暂存，继续从原快照读取。

具体接点为 `usage-quota-store.js`、`usage-quota-source-store.js`、`usage-record-store.js`、`usage-session-members.js`，以及现有 `usage-store.js`、`usage-rollups.js` 与时间线消费者。没有新增依赖或改变执行器堆限制。来源级增量、多个冷分片改造及阶段 C 长测属于后续阶段。

纪录首次构建经历两次工程修正：先去掉反复 `LIMIT` 排序，再改为一次按事件 ID 遍历、每事件计价一次并同时累加日/周/月；每批最多 1,024 事件及三倍周期状态，提交数值和进度，精确成员由 SQL 去重。数字相加仍按事件顺序，不能先按批次求和再合并而改变浮点结果。价格/证据/时区/范围变化重建对应结果，事实修订只重建脏周期。所有工程尝试独立保留，不代替正式矩阵。

新派生格式是可重建的内部表：纪录 FORMAT7、rollup FORMAT8。既有事实及原始来源已消失的历史不被替换；升级从现存事实构建。旧版可继续读权威事实，回退后首次切回新版会重建不匹配的派生格式。

独立补充的三事件夹具发现 FORMAT6 的本地周期成员查询默认使用当前时区边界，会漏掉按另一时区导入、但保有原日期键的历史行。修复前能稳定复现会话纪录缺失；FORMAT7 在周期和脏标记内保存事实的实际最早/最晚时间，以索引范围加原日期键查询，修订同步扩展边界，避免漏算或为此退化为逐周期全表扫描。修复后与原算法及手算成员数一致。`b1-capacity-v1` 在七轮完成、一轮运行时主动停止，全部保留为工程证据；不能拼接为最终九轮矩阵。

### 首次构建成本的归因

轻量分段诊断 `growth-b1-final-phase-before-1-1x` / `growth-b1-final-phase-after-1-1x`，属于补来源分类前的同一 B1 核心，不能混入最终中位数：旧/新首屏 38.346 / 41.498 秒；同步 35.510 / 36.352 秒、34.360 / 37.875 CPU 核秒；新版同步内的仓库 rollup 插入约 1.148 秒、0.845 核秒。新版同步后额度预热 1.141 秒/核秒，纪录预热 2.335 秒、2.484 核秒；随后 core 1.341→0.111 秒、1.640→0.109 核秒。

新增成本主要来自同步记账、仓库视图与首次持久额度/纪录构建。该改造把反复执行的业务工作提前保存，同时增加第一次重建的 CPU、读写和磁盘成本；它不是零成本提速。同步包含其内部 rollup 时间，不重复求和；单次分段也不能精确隔离每个 SQLite 触发器。计划中 1× 超过 10% 的回退需归因并保留未通过状态，不能用容量成功抵销。

### 额外路径和未覆盖范围

最终代码的 `b1-restart-complete` 使用已完成 10× 的状态、同一来源及原页面，连续两次均为进程冷启动。第一次 16.075 秒、summary miss：同步 9.115 秒、metadata 1.849 秒，额度和纪录预热仅 0.620 / 1.106 ms，持久视图确已复用；core 仍约 1.051 秒。第二次 0.891 秒、summary hit，没有执行器业务阶段。这是两个诊断样本，不是 p95，也不是 OS 缓存清空后的成绩。

首次派生写入触发既有 `data_version` 安全核验，因此完整重建当次响应未直接发布旧摘要缓存，后一次才发布。没有放宽版本校验来制造命中；来源检查、metadata 的全历史 SQL 工作和首次摘要 miss 仍是实际成本，不能只报第二次并宣称冷启动目标已实现。

10× all/hour 诊断触发原有时间线粒度上限，进入 cost/grouped 回退，不是普通 all/day 的成绩。查询及升级约 77.125 秒，OS 峰值 284.73 MiB；TEMP 逻辑分配 9.91 MiB，未建立会话匿名库。该数字不覆盖瞬时 sorter/journal 物理文件峰值，不能作为全部临时磁盘的上界。

`metadata-size-audit.json` 核对了官方额度元数据：真实留存种子及本轮 1×/10× 中均只有一条、289 字节，密度增长未放大该轴。`official_quota_observations` 的整块 JSON 以及来源 `codex-quota.json` 的整体解析仍存在；来源证据 JSON 也未进行独立增长压力测试。因此本轮不能宣称所有元数据/输入都已实现有界处理。来源级采集属于 B2/B3，但这些剩余整块读取须继续列在接入前容量清单，不能只用当前样本小而宣布普遍安全。

## 校验与边界

冷视图修复后的最终完整回归：2,575 项，2,548 通过、25 跳过、2 项失败，取消为零。两项是既有 UI 用例：`M4.3 S3/S5` 的 dense-data 等待，以及 `M5.2.C-D2b3` 的 light/x 搜索结果断言，均在保存的 B1 前 store/rollup/timeline 代码上复现。没有放宽这两个断言，也没有修改产品 UI 来绕过它们。相关证据是 `full-tests-closed.log`、`test-gate-closed.json`、`skin-baseline-control.log`、`edge-baseline-control.log`；之前 2,574 项的完整回归另有保留。

两项旧 rollup 测试改为显式删除可选模型表，继续验证缺表旧库和空库重建；新格式会在打开时准备模型表，不能再把“打开后不存在表”当成夹具前提。重建后所有空汇总表均核对为零行。最终完整回归已包含这一修正。
